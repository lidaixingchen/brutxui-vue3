# 跨包令牌编译器下沉与构建拓扑解耦方案

---

## 一、 背景与第一性原理

### 1. 现状痛点分析

在 BrutxUI Vue 3 当前的代码库组织与构建链路中，设计令牌（Design Tokens）的编译与跨包分发存在**拓扑倒置（Topology Inversion）**、**越界写泄漏（Write Leakage）**与**门禁横向耦合（Horizontal Verification Coupling）**：

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│                          当前设计令牌编译与构建拓扑现状                     │
├─────────────────────────────────────────────────────────────────────────────┤
│ 1. packages/shared/src/design-tokens.ts (单一事实源)                        │
│    └─ 仅存放静态令牌常量（BASE_THEME、SHADOW_DEFINITIONS 等数据定义）        │
│                                                                             │
│ 2. packages/ui/scripts/compiler/token-style-compiler.ts (编译器寄生于 UI)   │
│    ├─ 承载 596 行核心编译算法，但模块物理落位于 packages/ui                │
│    ├─ 倒灌 CLI 专属的 TypeScript 模板生成（UTILS_TEMPLATE、cn() 代码）     │
│    ├─ 跨包越界直接写入 packages/cli/src/styles/brutalist.css                │
│    └─ 跨包越界直接写入 packages/cli/src/lib/constants.ts                    │
│                                                                             │
│ 3. packages/cli/package.json (构建时反向调用与环形耦合)                     │
│    ├─ "prebuild": "pnpm --filter brutx-ui-vue prebuild:tokens"              │
│    └─ CLI 构建强耦合 UI 子包执行环境，违背 Monorepo 单向依赖原则            │
│                                                                             │
│ 4. packages/cli/scripts/check-brutalist-tokens.ts (门禁横向依赖 UI 产物)     │
│    └─ 读取 ../ui/src/styles.css 做正则比对，CLI 无法完全脱离 UI 独立校验    │
└─────────────────────────────────────────────────────────────────────────────┘
```

1. **依赖拓扑倒置与环形构建耦合（Circular Build-time Coupling）**：
   - Monorepo 的基础拓扑契约为：`packages/shared` 作为最底层基础设施，由上层包 `packages/ui` 与 `packages/cli` 单向依赖。
   - 现状却是：CLI 在其 `package.json` 的 `prebuild` 钩子中，必须反向调用 `pnpm --filter brutx-ui-vue prebuild:tokens`。在 Turborepo 并行构建或独立子包构建时，触发隐式子进程调用，破坏 Turbo 任务图（DAG）调度与缓存追踪，存在并发写竞态隐患。
2. **编译器实现位置错配与跨包越界写（Cross-Package Write Leakage）**：
   - 令牌编译引擎 `TokenStyleCompiler`（596 行）承载纯数据转换与 CSS 格式化逻辑，其输入源为 `packages/shared/src/design-tokens.ts`。
   - 该模块被安放在 `packages/ui/scripts/compiler/` 下，并通过脚本跨包直接修改 `packages/cli` 源码区的文件，破坏了子包自治与物理隔离边界。
3. **消费者模板逻辑向底层倒灌（Leaky Abstraction）**：
   - 原编译器混入了 CLI 脚手架特有的 `UTILS_TEMPLATE`（包含 `clsx`、`tailwind-merge` 导入及 `cn()` 函数实现）代码生成，使底层共享层承担了上层脚手架的业务细节，违背单一职责原则（SRP）。
4. **门禁横向耦合未绝（Horizontal Verification Coupling）**：
   - CLI 的令牌防漂移脚本 `check-brutalist-tokens.ts` 直接读取 `packages/ui/src/styles.css` 进行交叉比对。UI 与 CLI 均为 shared 令牌的下游派生产物，以派生物校验派生物违背单一信源原则，导致 CLI 检查依然无法脱离 UI 源码独立闭环。

### 2. 移除性测试（Deletion Test）

- **假设删除 `packages/cli` 对 `packages/ui` 的 `prebuild` 跨包调用**：
  CLI 子包获得完全独立的预构建与构建能力（可脱离 UI 包独立打包与测试），Monorepo 的 Turborepo 任务图恢复为严格树状单向流（`shared -> ui`，`shared -> cli`），彻底消除 CI 构建时缓存穿透与时序争用隐患。
- **假设删除 `packages/ui` 中的跨包写入逻辑**：
  UI 包的生成脚本仅收敛至自身文件（`styles.css`、`preflight.css`、`utils.ts`），消除越界修改隐患。
- **假设删除 `packages/cli` 对 UI `styles.css` 的跨包比对读取**：
  CLI 门禁改为自身脚本的新鲜度自校验（`--check`），实现全流程自包含与真正的物理隔离。

## 二、 目标与非目标

### 1. 目标
- **编译器下沉至 `packages/shared`**：将 `TokenStyleCompiler`（设计令牌纯计算编译器）重构下沉至 `packages/shared/src/tokens/`，紧邻单一数据源 `design-tokens.ts`。
- **构建高内聚的纯计算深模块**：
  - 编译器仅输出纯字符串 CSS/规则块，剥离文件系统 IO；
  - 剥离通用标记替换为独立纯函数 `replaceBetweenMarkers`；
  - 剥离 CLI 专有脚手架模板，交由 CLI 本地组装。
- **消除 Monorepo 构建时环形依赖与越界写入**：
  - CLI `prebuild` 改为调用本地生成脚本；
  - UI 脚本彻底移除对 CLI 目录的引用与写入。
- **门禁解耦与自闭环**：
  - 各包生成器统一支持 `--check` 幂等与新鲜度校验，直接以 shared 为基准自检，切断跨包读取源码；
  - 修复 `scripts/check-contracts-all.mjs` 中的自动修复指令，使其正确指向对应子包。
- **对齐全局命令与治理契约**：
  - 根目录新增统一全仓令牌同步命令；
  - 同步更新 `AGENTS.md` 等常青文档契约。

### 2. 非目标
- 不变更任何既有的 CSS 类名、设计令牌取值、Tailwind `@theme` 变量名与 fallback 机制。
- 不变更生成产物（`styles.css`、`brutalist.css`、`constants.ts`）的最终字节输出内容。

### 1. 纯计算编译器深模块契约（Token Style Compiler）

落位于 `packages/shared/src/tokens/`，并通过 `brutx-shared-vue/tokens` 对外导出：

```typescript
// packages/shared/src/tokens/token-style-compiler.ts
export interface CompilerOptions {
    indentSpaces?: number;
}

export class TokenStyleCompiler {
    constructor(private readonly tokens: ThemeTokens = BASE_THEME.light) {}

    /** 编译 :root 与 .dark CSS 变量声明块 */
    public compileRootBlock(options?: CompilerOptions): string;

    /** 编译 Tailwind v4 @theme 变量声明块 */
    public compileThemeBlock(options?: CompilerOptions): string;

    /** 编译预设主题声明块（.theme-pastel, .theme-mono, .theme-warm 等） */
    public compileThemePresetsBlock(options?: CompilerOptions): string;

    /** 编译 preflight 字体栈 CSS 声明 */
    public compileFontStackBlock(): string;

    /** 编译 UI 侧 @utility 纹理声明块 */
    public compilePatternUtilityBlock(indentSpaces?: number): string;

    /** 编译 CLI 消费方直挂阴影与纹理工具类规则 */
    public compileCliUtilityRules(): string;

    /** 编译 UI lib/utils.ts 颜色名称常量代码段 */
    public compileColorNamesBlock(): string;

    /** 编译 UI lib/utils.ts z-index 名称常量代码段 */
    public compileZIndexNamesBlock(): string;
}
```

通用标记注入函数独立剥离（无 IO 纯函数）：

```typescript
// packages/shared/src/tokens/markers.ts
export function replaceBetweenMarkers(
    content: string,
    startMarker: string,
    endMarker: string,
    replacement: string,
    sourceLabel?: string,
): string;
```

### 2. 自治式代码生成适配器（Autonomous Generation Adapters）

1. **`packages/ui` 本地适配器**（`scripts/generate-styles-tokens.ts`）：
   - 依赖：从 `brutx-shared-vue/tokens` 导入 `TokenStyleCompiler` 与 `replaceBetweenMarkers`；
   - 作用域：严格限定在 `src/styles.css`、`src/preflight.css` 与 `src/lib/utils.ts`；
   - 门禁模式：保留并强化 `--check` 模式，纯内存比对磁盘文件新鲜度；
   - 移除所有对 CLI 路径的引用与越界写入。

2. **`packages/cli` 本地适配器**（`scripts/generate-tokens.ts`）：
   - 依赖：从 `brutx-shared-vue/tokens` 导入 `TokenStyleCompiler`、`replaceBetweenMarkers` 及 `BRUTAL_COLOR_NAMES`、`BRUTAL_Z_INDEX_NAMES`；
   - 作用域：严格限定在 `src/styles/brutalist.css` 与 `src/lib/constants.ts`；
   - 本地模板组装：在本地脚本内完成 `constants.ts` 中 `UTILS_TEMPLATE` 的插值生成，不向 shared 倒灌脚手架代码；
   - 门禁模式：实现完整 `--check` 模式，校验磁盘文件是否与 shared 单一信源编译一致；
   - `package.json` 指令更新：`"prebuild": "tsx scripts/generate-tokens.ts"`。

3. **门禁解耦与去横向依赖化**：
   - 改造 `packages/cli/scripts/check-brutalist-tokens.ts`，将其重构为对 CLI 自包生成物的新鲜度校验（直接调用 `generate-tokens.ts --check` 或以 shared 单一事实源为基准校验），**彻底移除对 `packages/ui/src/styles.css` 的物理读取**。

## 四、 涉及模块重构与接口收敛

### 1. `packages/shared/`
- **新建模块目录**：`packages/shared/src/tokens/`：
  - `pattern-tokens.ts`：承接原编译器内的 `PATTERN_UTILITIES` 结构化定义；
  - `token-style-compiler.ts`：纯计算编译器实现；
  - `markers.ts`：纯文本标记区间替换函数；
  - `index.ts`：统一导出入口。
- **导出配置**：在 `packages/shared/package.json` 的 `exports` 中暴露 `"./tokens": "./src/tokens/index.ts"`，并补充类型声明。

### 2. `packages/ui/`
- **修改脚本**：`packages/ui/scripts/generate-styles-tokens.ts`：
  - 改为从 `brutx-shared-vue/tokens` 导入编译器与标记替换函数；
  - 彻底删除所有 CLI 文件路径定义（`CLI_BRUTALIST_PATH`、`CLI_CONSTANTS_PATH`）及覆写逻辑；
- **清理目录**：彻底删除原寄生目录 `packages/ui/scripts/compiler/`。

### 3. `packages/cli/`
- **新建脚本**：`packages/cli/scripts/generate-tokens.ts`：
  - 负责本包 `brutalist.css` 与 `constants.ts` 的生成与 `--check` 新鲜度校验；
  - 本地组装脚手架代码模板。
- **修改脚本**：`packages/cli/scripts/check-brutalist-tokens.ts`：
  - 切断对 `../ui/src/styles.css` 的跨包读取；
  - 对齐自包生成校验逻辑。
- **修改配置**：`packages/cli/package.json`：
  - `"prebuild"` 替换为 `"tsx scripts/generate-tokens.ts"`；
  - 新增 `"prebuild:tokens": "tsx scripts/generate-tokens.ts"`，形成跨包同名规约。

### 4. 根配置与全仓契约
- **根 `package.json`**：
  - 新增全仓令牌一键同步指令：
    `"generate:tokens": "pnpm --filter brutx-ui-vue prebuild:tokens && pnpm --filter brutx-vue prebuild:tokens"`
- **契约门禁调度器** `scripts/check-contracts-all.mjs`：
  - 更新 `tokens-alignment` 检查项的 `action.command` 为 `pnpm --filter brutx-vue prebuild:tokens`（或 `pnpm generate:tokens`），恢复门禁自愈有效性。
- **开发与治理规范** `AGENTS.md`：
  - 更新“自动生成文件”表格中的触发命令与执行上下文说明，明确 UI 与 CLI 各自的生成边界与单一事实源流向。
