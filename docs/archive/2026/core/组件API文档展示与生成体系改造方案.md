# 组件 API 文档展示与生成体系改造方案

## 一、目标与交付边界

将 Button、Alert 已使用的 `ComponentApi` 建设为组件文档的统一 API 展示入口，打通公开成员清单、源码提取、双语语义说明、静态生成、页面呈现与质量检查。推广的首要验收标准是信息准确、完整、可定位；搜索、折叠和类型徽标服务于这些目标。

本方案交付范围包括：

- 改造 API 元数据生成器、数据契约与生成编排。
- 改造共享展示组件及其必要的文档站点基础设施。
- 修改组件文档模板、开发指南相关流程、命令说明和检查脚本。
- 分批迁移 `apps/docs/components/` 与 `apps/docs/en/components/` 中的适用组件页面。
- 建立自动提取无法独立表达的类型、透传能力、条件行为及运行时默认值的维护机制。

实施时不改变业务组件行为；源码变更以 API 注释和必要的类型声明完善为限。发现公开导出与文档不一致时，先核对现行契约，不以文档迁移顺带决定业务 API 的增删。区块页面、独立组合式函数页面和完整 TypeDoc 站点不纳入本次批量迁移。

## 三、总体设计

采用“结构提取、语义编写、生成汇合、统一展示”的分工。

| 层次 | 负责内容 | 权威输入 |
| --- | --- | --- |
| 文档成员目录 | 页面对应的公开组件、子组件、公开名称与来源 | 现有 API 契约、组件元信息及文档映射 |
| 结构提取 | 属性、必填性、类型、声明默认值、事件、插槽和实例成员 | Vue SFC、TypeScript 类型与依赖声明 |
| 语义说明 | 中文与英文描述、条件行为、默认值解释、透传事件、类型说明 | 源码注释及组件级双语说明数据 |
| 文档生成 | 合并、引用解析、排序、静态 API 内容、页面数据与诊断 | 成员目录、提取结果和语义说明 |
| 页面展示 | 列表、搜索、定位、折叠、复制及响应式布局 | 当前页面、当前语言的生成数据 |

Markdown 正文负责用法、组合关系、数据类型、组合式函数、程序化控制示例和可访问性说明。`ComponentApi` 负责可查阅的成员清单。正文通过稳定锚点引用成员，避免重复维护同一份属性表。

## 四、文档数据契约

### 4.1 公开成员清单

1. 以现行 `packages/ui/api-contract.ts` 与组件元信息作为公开范围起点，不再把目录内所有 `.vue` 自动当作文档成员。
2. 文档映射只补充页面分组、成员顺序、主组件、公开别名和语义资源位置，不复制完整导出契约。
3. 测试夹具应有明确分类。若夹具已进入公开契约，生成检查报告该冲突；核定所属契约后再处理，不能仅凭文件名隐藏冲突。
4. 对依赖重导出、继承和别名逐一解析实际来源。仅当现行公开契约确实包含该成员时，才生成其文档；不依据旧文档中的名称推断现行导出。
5. 建立全部组件页面的迁移清单，记录页面、组、成员、语言、当前展示方式与待补内容。清单中的适用范围决定最终验收分母。

### 4.2 结构与语义字段

新契约至少包含下列信息，类型定义集中维护，生成器和展示组件共享：

| 对象 | 必需信息 |
| --- | --- |
| 组件组 | 稳定组 ID、主成员 ID、公开成员有序列表、页面标识 |
| 成员 | 稳定 ID、公开名称、成员种类、归属、源码位置 |
| 类型 | 原始类型文本、可读展示、字面量选项、引用类型 ID |
| 属性 | 名称、必填性、可空性、声明默认值、解析结果及运行时回退 |
| 事件 | 事件名称、带参数名的参数列表、声明或透传来源 |
| 插槽 | 名称或名称模式、作用域类型、使用条件 |
| 暴露成员 | 方法签名或状态类型、只读性、适用条件 |
| 语义 | 中英文描述、备注、相关类型与正文引用 |
| 诊断 | 规则 ID、严重性、页面、组件、成员及来源位置 |

属性可选与值可为 `null` 分别表达。禁止通过字符串清理统一去掉 `null`；`undefined` 的展示也必须与可选标记和实际类型保持一致。

默认值按三个独立维度建模，生成器和展示层共用判别联合类型：

| 维度 | 状态与内容 | 契约 |
| --- | --- | --- |
| 声明默认值 | 未声明、值、表达式、工厂函数 | 保留声明来源与原文；显式 `undefined` 与未声明分别记录 |
| 解析结果 | 已解析、保留表达式 | 声明存在时记录；已解析值保留值类型，保留表达式时提供说明 |
| 运行时回退 | 条件、资源键或行为说明、源码来源 | 独立可选字段，可与任何声明状态共存，支持有序条件分支 |

安全解析字面量和可静态求值的常量引用；不执行任意业务表达式或调用工厂函数。对工厂函数仅在静态分析能够证明返回内容时提供解析结果，其余保留原表达式。无法静态求值时要求补充说明，不伪装成确定值。

例如，声明默认值为 `undefined`、运行时通过国际化获得文本的属性，同时展示声明值与语言回退条件；DataTable 的常量默认值保留常量来源并展示静态解析值。未声明默认值且没有回退的属性明确标记“未声明”，不推断实际运行值。

### 4.3 类型可读性

- 字面量联合类型通过类型系统或结构化元数据解析，可显示为徽标；禁止按竖线正则拆解嵌套函数和泛型类型。
- 别名保留名称，同时提供可选值或跳转至类型定义。Button 的 glitch 三项必须能够直接查到合法值。
- 泛型、递归类型和复杂对象提供有界摘要与关联定义。解析深度和展示长度使用具名配置，循环引用保留类型引用。
- DataTableColumn 等数据类型继续在正文提供业务说明，并与生成的类型引用关联。

### 4.4 双语说明与补充信息

组件级语义资源放在文档站内，按组分文件，采用类型约束的成员键；实施时建立统一目录 `apps/docs/.vitepress/api-content/`。该目录为手写语义输入。

- 自有声明成员的基础中文描述在源码注释中维护；组件级语义资源维护英文翻译、文档专用的条件说明、示例和引用。依赖重导出成员的中文说明及人工补充成员的双语说明在语义资源中维护，并记录来源。
- 基础描述与文档补充分字段合并。基础描述按明确登记的文档覆盖、对应语言源码注释、适用的通用描述解析；覆盖仅用于依赖成员在本库中的语义适配或文档上下文表达，并记录适用范围和来源成员。中文不得作为英文页面发布时的自动回退。
- 类型、必填性和可静态提取的默认值来自源码；语义资源不得覆盖这些结构字段。
- 提取器无法表达的透传事件、动态插槽等使用明确的补充条目，记录来源与适用条件。对常规声明成员的补充键必须能解析到现有成员，失效键直接报错。
- 原生事件与自定义事件分组标注。例如 Button 的原生点击及禁用约束不能因缺少 `defineEmits` 而消失。
- 中英文均要求有效语义内容；空字符串、占位横线、仅重复成员名不算完成。语义准确性由逐组件核对验收，不能只依赖字符串检查。
- API 结构或基础中文语义变化时，同批复核英文翻译、文档覆盖、单位、行为条件和运行时回退。生成差异按成员定位结构与说明变化，评审记录复核结果；成员键仍有效仅证明引用存在，不能证明说明仍准确。

## 五、生成与构建改造

### 5.1 模块职责

将 `generate-api-docs.ts` 内部提取、语义合并、格式化和文件输出分开，CLI 保持为编排入口。复用 `vue-component-meta` 与现有 TypeScript 能力，不引入第二套并行扫描器。

生成结果按组件组和语言拆分，保留轻量组索引；展示页面仅引用本页所需数据。取消 `groups` 与多种名称索引重复存储完整对象的方式，别名索引仅保存稳定 ID。完整数据索引供构建工具使用，主题全局注册只引入展示组件代码。

产物保存在文档站 `.vitepress` 的生成目录中，严禁手写。产物采用确定顺序与固定序列化；生成时间不进入需提交的契约内容。相同输入重复生成必须得到相同字节内容。

### 5.2 编排与检查

- 为文档 API 生成建立独立任务，保留 UI 通用生成入口的现有职责，避免每次生成令牌都执行完整文档类型分析。
- 将 API 生成设置为 docs 构建的前置依赖；开发服务器启动前也执行生成。开发期间监听源码、共享类型、公开契约、语义资源及提取配置，采用具名防抖配置合并事件后执行全量生成，仅写入内容有差异的产物并触发页面刷新。生成任务串行执行，运行期间的新事件安排下一次生成；生成失败须向开发者显示定位诊断。
- 记录首次生成、源码修改、翻译修改和共享类型修改的耗时，再决定是否实施细粒度增量提取。增量优化以实测瓶颈为前提；若实施，必须覆盖跨组共享类型、契约、依赖声明及配置变化的失效传播，依赖范围不明时全量失效，并验证增量结果与全量结果一致。
- 将源码、公开契约、语义资源、生成器、相关类型配置和依赖版本纳入任务输入。文档数据变化必须使 docs 构建缓存失效。
- 根级生成一致性入口纳入文档 API 的只读检查，暂存区快照流程使用同一生成逻辑验证暂存输入与产物。
- 检查模式只比较并报告内容差异，不改文件，不增加哈希校验。
- 解析失败、缺成员、重复 ID、失效补充键、迁移页面缺双语说明均输出定位诊断并使检查失败。分批迁移期间，仅清单中已迁移页面执行完整语义门禁；结构解析错误始终阻断。
- 保留现有 `docs:manifest` 入口作为生成命令；新增检查入口在实施时同步登记命令手册和任务图。

### 5.3 静态内容与索引

`ComponentApi` 的基础成员内容须在构建输出 HTML 中存在。站内搜索实际使用的索引输入也必须包含成员名称、类型和描述，不能假定运行时组件内容会自动被收录。

按 VitePress 1.6.4 的构建与本地搜索接口分别接入页面渲染和索引生成：

1. 页面编译阶段解析真实的 `ComponentApi` 调用，将静态 `name`、`subcomponent` 和页面语言解析为组件组数据导入及成员范围，保留页面现有 `name` 写法。该解析器同时用于文档检查和搜索投影，排除围栏及注释中的伪调用；无法静态解析的成员选择参数输出定位诊断。
2. 页面模块显式导入本组、本语言的生成数据，并将其传给 `ComponentApi`。展示组件直接 SSR 输出成员内容，客户端对同一份 DOM 水合并增强交互。基础 HTML 与首次水合均包含调用范围内的全部成员和 API 分类，静态模式可读取完整类型。
3. 本地搜索通过 `themeConfig.search.options._render(src, env, md)` 接入。先调用 `md.render(src, env)` 获取正文和页面环境，遵循 `search: false`，再从相同页面成员范围及语言数据生成索引专用内容，替换对应组件调用的索引占位。索引投影只参与搜索输入。
4. 页面渲染与搜索投影共用成员 ID、锚点和类型格式化规则，索引覆盖名称、类型和描述。投影为可被本地搜索识别的章节和文本，搜索结果指向页面中实际存在的成员锚点。

锚点由稳定组件 ID、API 分类和成员名称确定，不受翻译和展示顺序影响。旧章节链接通过显式别名锚点保留；同页重复成员范围须指定实例标识，并由文档检查保证最终 HTML 的 ID 唯一。页面正文与生成内容的锚点也纳入同一检查。

验收需检查构建后 HTML、实际搜索索引以及关闭 JavaScript 后的内容，并实际点击中英文搜索结果定位成员。保留现有 `#props`、事件、插槽及子组件链接的有效定位；验证首次水合无内容不匹配，首页及其他组页面不加载无关 API 数据。

接口依据：[VitePress 1.6.4 本地搜索与自定义内容渲染](https://vuejs.github.io/vitepress/v1/reference/default-theme-search#custom-content-renderer)。实施时以仓库锁定版本验证接入行为。

## 六、展示组件设计

### 6.1 信息结构与操作

保留 `ComponentApi` 为页面统一入口，拆分职责清晰的数据解析、查询状态、类型显示和成员列表模块。

- 默认按组件成员分组，显示全部 API 分类；主组件排首位，子组件按声明顺序展示。
- 提供可访问的组件筛选和分类筛选，搜索范围覆盖该页全部成员；命中结果显示所属组件，避免只搜索当前子组件。
- 搜索支持名称、类型和描述，命中数与实际可见范围一致。没有 API、当前筛选为空、名称解析失败分别处理。
- 以“名称、说明、类型、默认值”为桌面属性表列序，必填性与可空性清晰标注。
- 长类型先展示摘要，展开后显示完整类型；复制名称和完整类型均有操作反馈。
- URL 锚点能够定位并展开目标成员。保留现有 `name` 用法；明确 `subcomponent` 为固定成员范围，固定范围时不展示可切换到其他成员的控件。SSR 和首次水合显示全部分类；水合完成后 `defaultTab` 决定初始交互分类，空分类自动返回全部。锚点目标优先于分类和搜索筛选，定位时清除阻挡目标的临时筛选。
- 路由、组或语言变化时重置页面临时筛选状态；锚点定位优先于初始分类。

### 6.2 样式、响应式与可访问性

复用库内 Button、Input 和适用的 Reka 原语。颜色、边框、阴影和间距遵循视觉系统及现有令牌；交互时长与布局阈值使用具名配置。

窄屏采用同一数据源的堆叠成员布局，名称、说明和类型均可阅读；只允许复杂类型局部滚动，避免整页横向溢出。

- 搜索框具有明确标签，清空和复制按钮具有可访问名称。
- 折叠控件包含 `aria-expanded` 与关联目标，分类筛选通过状态语义表达选择结果。
- 复制操作支持键盘焦点和失败反馈，卸载时清理反馈计时器。
- 使用真实标题、表头和稳定 ID，焦点样式在明暗主题可见。
- 中英文界面文案随文档语言同步，完整翻译空态、状态提示、必填标记和默认值类别。
- 说明以文本或受控 Markdown 渲染，保留代码片段、换行和链接；停止直接将任意描述字符串作为 HTML 注入。

## 七、模板与规范改造

同步修改 `COMPONENT_DOC_TEMPLATE.md`、`COMPONENT_GUIDE.md` 的文档工作流、`COMMANDS.md` 和生成架构说明。

开发指南纳入第 4.4 节的语义维护归属与同批双语复核要求；模板分别示范源码基础描述、英文翻译和文档补充，生成差异作为逐成员复核入口。

模板正式规定以下章节职责：

| 章节 | 维护方式 |
| --- | --- |
| 预览、安装、用法、变体、尺寸 | 手写，说明真实使用场景 |
| 子组件 | 手写组合关系，成员清单与生成目录校验一致 |
| 数据类型、导出类型 | 手写业务含义，引用可定位的类型定义 |
| 组合式函数、程序化控制 | 保留独立使用与实例调用示例 |
| API 参考 | 使用 `ComponentApi`，展示属性、事件、插槽和暴露成员 |
| 可访问性、样式定制、常见问题 | 手写行为和约束 |

中英文页面使用同一组件组与成员范围，语言由站点上下文决定。模板给出单体、复合、复杂组件的完整示例；手写属性表仅在迁移清单中的待迁移页面继续使用。

章节检查需解析正文中的真实组件调用，排除代码围栏和注释，并验证名称、成员范围、数据存在性、双语镜像和锚点。仅存在“API 参考”标题不能通过。迁移页保留重复 API 表或出现失效语义引用时报告明确位置。

## 八、实施批次与负责范围

各批完成验收后再推进下一批；迁移页面的中英文、语义输入和生成产物同批交付。

| 批次 | 负责范围 | 交付与退出条件 |
| --- | --- | --- |
| A：契约与清单 | UI API 契约读取、文档组映射、现有页面盘点 | 所有组件页面有归属；公开成员冲突有核定结果；基准信息核对表完成 |
| B：代表性链路试点 | 提取契约、语义合并、生成编排、缓存与快照检查、基础 SSR、页面数据绑定和搜索投影 | Button、Alert 结构与双语语义完整；Input、Select、Dialog、DataTable 的关键能力经实际提取验证；试点页面打通生成、SSR、搜索定位和按页加载；重复生成一致；过期产物和解析错误会失败 |
| C：展示与模板 | 查询、折叠与复制交互、响应式展示、模板、指南及文档检查 | 双语、静态内容、搜索、锚点、键盘和窄屏验收通过；源码语义变化的双语复核流程明确 |
| D：单体迁移 | Button、Alert 基准完善；Badge、Input、Statistic、Countdown 等适用页面 | 新旧信息逐项核对；默认值与事件说明准确；双语同时完成 |
| E：复合与复杂迁移 | Dialog、Select、DataTable 及清单中其余适用组件 | 子组件、类型、作用域插槽与程序化说明完整；每组通过后才替换原表 |
| F：收口 | 迁移清单、长期文档、旧产物引用与方案生命周期 | 全部适用页面迁移；过渡检查退出；产物引用清理；完整验收并归档 |

每批保留可独立评审的变更边界。若采用子代理，按生成链路、展示层、双语内容等互不冲突范围分工，主代理整合契约与验证；遵循仓库规定的派生和等待规则。

批次 B 的技术试点覆盖下列契约，复杂组件的完整页面迁移仍在后续批次完成。试点选定成员须具备完整双语说明，并使用正式生成和检查链路；尚未迁移的成员继续按迁移清单管理。

| 代表组件 | 前置验证能力 |
| --- | --- |
| Button、Alert | 别名与合法值、原生透传行为和条件、声明默认值与语言回退共存、基础复合分组 |
| Input | `v-model` 的属性与更新事件对应关系 |
| Select、Dialog | 子组件、现行契约中的依赖重导出与来源、作用域插槽 |
| DataTable | 泛型与关联类型、带参数名的事件、常量默认值、实例方法和状态 |

上述试点决定数据契约能否承载后续迁移。未通过时继续在批次 B 完善提取和补充契约，通过后再推进展示交互与批量内容迁移。每组试点至少验证代表成员从源码到生成数据、静态页面及搜索目标的完整路径。
