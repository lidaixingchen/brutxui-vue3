# 方案自动归档与知识地图自愈引擎方案

> 本方案针对 BrutxUI 工程中方案落地的收尾闭环流程进行深度重构与全自动化升级。基于第一性原理，将 YAML Frontmatter 的生命周期状态作为单一事实源（SSOT），彻底摒弃脆弱的局部文本修剪与手工记账，通过“只读守卫与变异引擎解耦”、“声明式知识地图投影派生”、“双向链接拓扑自愈”以及“两阶段原子事务”，实现方案完工后的一键物理落位、元数据固化、链接校准、索引重塑与原子暂存，并在 `AGENTS.md` 中建立高可靠自动化收尾闭环标准。

---

## 一、 背景与第一性原理

### 1. 现实痛点分析
在现行规范 [`DOC_GOVERNANCE.md`](../../../guides/DOC_GOVERNANCE.md) 与 [`AGENTS.md`](../../../../AGENTS.md) 中，方案完工后的收尾闭环依赖严格的 5 步人工 SOP。在日常开发与 Agent 自治执行中，暴露出明显的脆性（Fragility）与认知负荷：

1. **机械物理搬迁繁琐易漏**：开发者或 Agent 需手动计算年度 `YYYY` 与领域 `<domain>` 路径，手动调用 `git mv` 迁移文件；
2. **相对路径层级极易算错**：方案从 `docs/plans/<domain>/`（相对根目录深度为 3）移入 `docs/archive/YYYY/<domain>/`（深度为 4），文档内部所有的源码与规范引用必须由 `../../../` 手动修正为 `../../../../`，手工计算极易算错、漏改甚至引入孤儿死链；
3. **知识地图手工维护与排版损坏**：需要手动打开 [`docs/index.md`](../../../index.md)，从活跃区剪切条目并粘贴至归档区，同时手动给标题中的 `（N 篇）` 计数加 1，极易破坏中文顿号、句末标点（如 `等。`）或造成统计数字漂移；
4. **时间语义模糊与跨年风险**：原方案单一的 `日期` 字段在立项后若被覆盖为完工日期，将丢失最初起源时间；若按立项日期推导归档目录，会导致跨年完工的方案被错误塞入过去年份的历史封存库；
5. **多头维护与认知割裂**：开发者在修改代码与单测后，仍需分心处理复杂的文档落位与格式排版，缺乏一键收敛的原子化工具。

### 2. 第一性原理推导
从第一性原理出发：
- **YAML Frontmatter 是方案生命周期的唯一事实源（SSOT）**；
- **文件系统拓扑是工程状态的唯一物理投影**；
- **知识地图 `docs/index.md` 是前两者元数据的纯函数投影（Pure Function Projection）**。

一旦某篇方案确认落地完成，其物理目标路径、Frontmatter 终态流转、内部链接层级重算、全仓反向引用更新以及知识地图的条目与篇数，**均具备 100% 确定性的数学映射规则，绝不应依赖人工记账或脆弱的局部字符串剪贴，必须由高可靠的自动化引擎驱动**。

## 二、 架构决策矩阵（基于最佳实践重塑）

对照业界高成熟度工程工具链与深模块（Deep Module）设计哲学，锁定以下核心架构裁决：

| 决策维度 | 核心裁决 | 设计理由与边界考量（最佳实践） |
| :--- | :--- | :--- |
| **Q1: 架构分层与职责分离** | **守卫（Guard）与引擎（Engine）彻底解耦** | `scan-doc-status.mjs` 保持纯只读守卫，无副作用，专职 CI 拦截；新建 `scripts/docs/lib/archive-engine.mjs` 承载重变异逻辑，暴露独立 CLI `scripts/docs/archive-plan.mjs`（`pnpm doc:archive`）。 |
| **Q2: 门禁拦截策略** | **Fail-Closed 严格守卫** | `pnpm check:docs` 扫描到 `plans/` 下存在 `done` 方案时退出码 1，阻断 CI 并精准提示运行 `pnpm doc:archive`，强制收拢闭环。 |
| **Q3: 归档年份推导模型** | **严格基于完工交付年份（Delivery Year）** | 归档目标目录 `docs/archive/${YYYY}/${domain}/` 中的 `YYYY` **必须取完工落地的自然年份**（当天或显式 `完工日期`），立项 `日期` 保持不可变，彻底杜绝跨年方案归档错乱。 |
| **Q4: 链接自愈策略** | **复用 `DocLinkEngine`，正反向双向自愈** | 严禁重造行级正则轮子。复用已验证的 `DocLinkEngine` 分词与原位切片替换能力，既校准被移动文档自身（深度 3 $\to$ 4），又通过全仓倒排索引将外部所有指向旧路径的链接自动重定向到新归档路径。 |
| **Q5: 知识地图同步机制** | **声明式区块确定性派生（Deterministic Projection）** | 彻底摒弃脆弱的增量正则增删与字符串拼接。在 `docs/index.md` 划定结构化区块标记，基于全仓扫描元数据全量重新投影生成，自动格式化中文顿号、句末标点与篇数统计。 |
| **Q6: Git 状态交互与事务** | **两阶段事务（Preflight & Apply）+ 精准暂存** | 阶段一进行纯内存预检（无写操作），验证无冲突后进入阶段二物理执行；通过 `git add <精准文件列表>` 原子暂存，严禁宽松的全局暂存污染工作区。 |
| **Q7: CLI 调用与交互模式** | **双模驱动：支持单文件直达与全仓收割** | 支持 `pnpm doc:archive <file>`（无需人工先改 `done`，直接由 `active` 归档）与 `pnpm doc:archive`（批量处理已标记为 `done` 的方案），并支持 `--dry-run` 预览。 |

## 四、 详细流水线设计与算法实现

### 阶段 ①：元数据扫描与目标路径推导
1. 接收目标方案参数（单文件路径或扫描模式）：
   - 单文件模式：校验文件必须位于 `docs/plans/<domain>/` 下；
   - 全仓扫描模式：遍历 `docs/plans/`，筛选 `status === 'done'` 的方案；
2. **完工年份（Delivery Year）权威推导**：
   ```javascript
   // 严禁使用立项日期推导归档年份！
   const now = new Date()
   const currentYear = String(now.getFullYear())
   const todayStr = `${currentYear}-${String(now.getMonth() + 1).padStart(2, '0')}-${String(now.getDate()).padStart(2, '0')}`
   
   // 若已有完工日期则以完工日期年份为准，否则以当天年份为准
   const deliveryYear = (fm.completionDate ? fm.completionDate.split('-')[0] : null) || currentYear
   const targetRelPath = `docs/archive/${deliveryYear}/${domain}/${fileName}`
   ```
3. 路径安全检测：若 `targetRelPath` 已存在同名文件，抛出冲突异常，阻断流程。

### 阶段 ②：两阶段原子事务（Preflight & Apply）

#### Phase 1: 只读预检（Preflight Validation）
在碰触磁盘之前，引擎在内存中完成全部模拟计算：
1. 验证目标方案 Frontmatter 完备性（`方案类型`、`状态`、`日期` 必填）；
2. 基于 `DocLinkEngine` 提取文档内全部相对链接，核验绝对目标路径是否存在；
3. 基于全仓倒排索引，扫描全仓所有引用该方案旧路径的文件集合；
4. 解析 [`docs/index.md`](../../../index.md)，验证活跃区与归档区结构标记完好，生成预测的新文本；
5. 若任何一步失败，流水线立即安全中断，不产生任何副作用。

#### Phase 2: 原子落盘（Atomic Apply）
预检通过后，依次执行以下物理变更：
1. **物理文件迁移**：
   - 检查文件是否处于 Git 跟踪下（`git ls-files --error-unmatch <file>`）；
   - 若跟踪：调用 `git mv <source> <target>` 保持 Git 提交历史连续性；
   - 若未跟踪：使用 `fs.renameSync` 移动文件。
2. **Frontmatter 终态固化与完工日期注入**：
   - 将 `状态: done` 或 `状态: active` 重写为终态 `状态: archived`；
   - 注入或更新 `完工日期: YYYY-MM-DD`（当天日期），原 `日期` 字段严格保持不变。
3. **文档自身内部链接坐标重算（正向自愈）**：
   - 目标文件从深度 3（`plans/<domain>/`）变更为深度 4（`archive/<YYYY>/<domain>/`）；
   - 复用 `DocLinkEngine` 的 CommonMark 分词器，识别非代码块、非反引号代码段中的有效 Markdown 链接；
   - 提取链接绝对坐标并重算相对路径：
     ```javascript
     const targetAbs = path.resolve(oldDir, href)
     if (fs.existsSync(targetAbs)) {
       const newHref = toPosix(path.relative(newDir, targetAbs))
       // 采用字符物理偏移从后向前切片替换，保证无损排版
     }
     ```
4. **全仓反向引用原子修正（反向自愈）**：
   - 将全仓其他 Markdown 文档中指向 `plans/${domain}/${fileName}` 的相对链接，原位替换为指向 `archive/${deliveryYear}/${domain}/${fileName}` 的新相对路径。
5. **知识地图声明式派生回写**：
   - 将生成好的全新 `docs/index.md` 一次性写回磁盘。
6. **精准 Git 暂存（Targeted Staging）**：
   - 收集本次实际受影响的文件路径数组 `changedFiles`（包含移动后的方案文件、被更新的引用文档、`docs/index.md`）；
   - 执行 `git add -- ${changedFiles.join(' ')}` 进行精准原子暂存；
   - 严禁调用模糊的 `git add .` 或 `git add -A`，杜绝工作区临时代码被误带入。

### 2. 派生渲染算法规则
- **活跃区生成**：
  - 扫描 `docs/plans/` 下所有非 `done` 方案，按领域（`cli`、`ui`、`styles`、`core`）分组；
  - 提取 Frontmatter 的 `状态`、首段引用块或 `描述` 字段；
  - 若某领域无方案，输出 `*（暂无进行中的活跃方案）*`。
- **归档区生成**：
  - 扫描 `docs/archive/` 下所有按年份、领域划分的方案文件；
  - 自动统计精准篇数 `（${count} 篇）`；
  - 自动提取方案主题名（正则剥离 `(方案|设计)\.md$` 后缀）；
  - 主题名清单以中文顿号 `、` 连接，末尾严格格式化为 `等。`（无方案时输出 `暂无归档。`）；
  - 跨年时自动按年份降序生成 `### ${YYYY} 年度落地方案` 章节。
