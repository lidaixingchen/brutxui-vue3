# 系统演进与存量任务收敛路线图与技术契约

本方案作为全工程系统演进与存量任务收敛的**总控路线图（Epic Roadmap）与集成验收基准**，统一协调并追踪 CLI 令牌引导、复合区块变体、统计展示组件及工程自动化四项关键演进。各任务明确职责边界、独立交付验收，整体状态由 Frontmatter 驱动，任务推进与归档依据本文确立的基准执行。

## 一、 定位与治理原则

维护成本源于重复的事实来源、模糊的公开契约、缺乏隔离的测试环境以及脆弱的手工同步流程。本方案以当前代码为客观基线，消除各模块历史演进中的割裂现象。

实施遵循以下最高治理与工程原则：

- **治理生命周期解耦（破除长周期方案死锁）**：
  - 依据[文档治理规范](../../../guides/DOC_GOVERNANCE.md)的黄金判据（读者还要照着做 = `active`，读完不用做 = `done` 归档），本路线图承担跨领域集成验收的顶层索引；
  - 各子任务具备清晰的职责与代码物理边界。涉及跨领域的独立交付（如 M1 CLI 引导、M3 统计组件开发），可在对应领域目录（`docs/plans/cli/`、`docs/plans/ui/`）独立立项原子 RFC 或直接依照本文契约交付；各领域任务落地完成后即时运行 `pnpm doc:archive` 执行原子归档；
  - 本路线图在全部存量任务完成并通过集成验收门禁后，执行最终归档，确保全仓状态机与知识地图实时保真。
- **单一事实来源（SSOT）**：已存在的能力先确认覆盖范围，再安排增量工作；所有生成产物均绑定唯一配置源或代码源，严禁人工二次誊抄。
- **显式契约驱动**：公开 API、变体类型与导出边界由显式契约决定，自动化机制负责执行与检验；样式整理维持既有交互和公开 API 兼容。
- **零假设防漂移（Drift Detection）**：所有派生产物（主入口、元数据、文档 API）在 CI 中实施只读漂移检测，检测到未同步的源码变更时即刻阻断。
- **最小化领域门禁**：按变动领域执行针对性精准检验，跨包集成与发布按现行流水线严格验证。

## 三、 任务规格与第一性原理契约

### M1：CLI 令牌文件引导

**目标**：让交互和自动化初始化都能得到明确、可重复且环境兼容的 CSS 配置，复用现有初始化服务的文件事务。

配置契约：

- **交互模式问询**：在确定 Tailwind CSS 入口后询问是否拆分设计令牌，默认选择拆分（提示独立文件利于主题维护与版本平滑升级）。
- **物理相对路径强制规范**：
  - 拆分文件默认位于实际 CSS 入口同目录，文件名采用集中定义的默认值 `brutx-tokens.css`；
  - 主 CSS 中注入的 `@import` 语句必须基于物理文件系统路径差计算**显式相对路径**（例如 `@import "./brutx-tokens.css";`），严禁输出 `@/` 别名路径，确保在 Vite、Nuxt、Webpack 等各类构建工具中均可原生解析，零配置负担。
- **配置持久化**：用户选择拆分时写入 `components.json` 中的 `tailwind.tokensFile`；选择内联时省略该字段。两种模式都通过现有初始化事务管线执行。
- **自动化无歧义原则**：新项目的 `--yes` 与 `--defaults` 使用与交互默认选择一致的拆分配置，不触发询问；`--silent` 只控制输出。
- **已有项目非破坏性**：已有 `components.json` 的覆盖授权沿用当前命令规则。允许重新初始化时，合法的已有 CSS 入口与 `tokensFile` 作为默认值；已有内联配置保持其模式，不强行覆写。配置无效时，在写入前返回可定位错误。
- **同路径安全回退**：同一解析路径作为入口与令牌文件时，沿用服务层的内联回退行为。路径越界拒绝、相对导入计算和事务回滚均由既有服务严格承载。
- **取消与幂等性**：取消交互发生在文件写入之前；重复执行保持配置、样式标记与导入幂等；更新保留目标文件中用户维护的自定义规则。

### M2：区块组件变体整理与豁免准则

**目标**：按[组件开发指南](../../../guides/COMPONENT_GUIDE.md)和[CVA 规范](../../../guides/CVA.md)集中管理真实的样式变体，杜绝形式主义空壳抽象。

CVA 提取判定树与豁免契约：

- **核心判定准则**：CVA 的第一性原理是管理**多轴度状态与样式分支组合（Compound Variants）**。
- **抽离范围**：对具备 2 个及以上变体轴度（如不同视觉风格 `variant`、尺寸 `size`、色彩模式）或复杂受控展开状态的复合区块组件，样式必须抽离至同目录 `*-variants.ts`。导出明确命名的派生类型（如 `DashboardShellVariants`）。
- **纯静态布局区块豁免准则**：
  - 对于仅包含固定网格、固定弹性布局且不存在任何样式分支的模板区块（如纯静态展示的 `FooterSection`、`HeaderSection`），样式直接在 SFC 根节点通过 `computed(() => cn(...))` 维护，保持高内聚；
  - **严禁**为了追求“文件完整性”为无变体组件创建仅包含单行 base 字符串的空壳 CVA 文件，避免制造无意义的间接层。
- **静态可扫描要求**：所有组件中的合并类名必须通过 `computed` 包裹 `cn`；Tailwind 类名使用可静态扫描的完整字面量，严禁运行时动态拼装字符串。
- **边界保留**：按现有 props 和内部状态组织变体，保留 `DashboardShell` 当前 `open` 状态语义。

### M3：Statistic 与 Countdown

**职责边界**：`Statistic` 负责数值解析、本地化格式化与多模态展示；`Countdown` 负责基于绝对时间的调度、剩余时长计算及到期事件派发，并在内部组合展示能力。两者具有独立 props、测试和文档。

#### Statistic 契约

- **大数与精度安全防护**：
  - `value` 接收有限数值或数值字符串；
  - 底层格式化引擎必须依托原生 `Intl.NumberFormat`，结合字符串安全解析与 BigInt 支持，彻底杜绝 IEEE 754 双精度浮点数在超过安全整数（$2^{53} - 1$）时产生的静默精度截断与舍入失真；
  - 精度范围与舍入规则集中定义，不支持的非法字符串采用统一空态占位。
- **本地化与显式覆盖**：
  - 默认千分位与小数格式遵循当前项目 locale；
  - `precision`、`decimalSeparator`、`groupSeparator` 为显式覆盖项，未传入时保留 locale 语义，杜绝魔法数字与硬编码符号。
- **空态与插槽体系**：
  - 空值和无效输入统一渲染空态占位符（如 `-`），并通过国际化字典提供可配置的读屏文本；
  - `title`、`prefix`、`suffix` 提供文本 props 与同名插槽，插槽优先级高于 props；
  - 预留数值平滑过渡插槽（如结合数字翻牌或渐变动效），保证后续拓展不破坏结构。
- **视觉系统对齐**：数值字体、字号、边框硬阴影复用现有设计令牌；`trend` 属性表示上升或下降方向，必须同时提供文字/图标双重可感知提示，颜色遵循设计系统状态色彩规范。

#### Countdown 契约

- **绝对时间差调度**：
  - 接收以毫秒为单位的有限目标时间戳，展示 `max(目标时间 - 当前时间, 0)` 对应的剩余时长；
  - 调度核心基于系统绝对时间差（`performance.now()` / `Date.now()`），当浏览器标签页处于后台休眠后重新唤醒时，自适应校准时间差，彻底消除传统 `setInterval` 累积触发漂移。
- **事件单次触发保障**：
  - 目标更新立即重算；同一轮目标最多发出一次到期事件（`finish`）；目标时间戳实际变化后开启新的计时轮次；无效目标采用空态并立刻停止调度。
- **SSR 与水合一致性**：
  - 服务端渲染（SSR）与客户端水合首帧必须输出确定性的静态占位展示，组件挂载（`onMounted`）后启动真实调度，根除水合不匹配警告；
  - 到期、组件卸载（`onBeforeUnmount`）及目标失效时严格释放定时器与 RAF 句柄。
- **无障碍（A11y）降噪契约**：
  - 高频秒级/毫秒级数字刷新必须保持屏幕阅读器静默（`aria-live="off"` 或读屏降噪），禁止高频语音轰炸；
  - 倒计时到达零值时，通过 `aria-live="polite"` 触发一次性完成状态通知。

### M4-T：公开 API 源码与消费端类型门禁

**目标**：构建兼顾内部研发与外部消费真实场景的双层类型回归防护网，彻底杜绝类型漂移与 `any` 退化。

工具链认知对齐：
- 明确 Vitest 纯 `expectTypeOf` 在 Vue 3 单文件组件（SFC）泛型推导、模板插槽宏（`slots`）和自定义事件（`emit`）上的解析局限；
- 确立以 TypeScript 编译器结合 `vue-tsc` 为核心的自动化类型验证方案。

双层门禁架构：

1. **源码级类型契约（Internal Source Contract）**：
   - 针对 DataTable、Form、Select 等复杂泛型组件，编写专项目录下的 `.test-d.ts` 或 `type-test.vue`；
   - 通过专门配置的 `vue-tsc --noEmit` 验证泛型推导、类型收窄、必选属性以及错误用法（预期编译失败）；纯函数与变体工具类型辅以 Vitest `expectTypeOf` 检查。
2. **独立消费端隔离契约（Isolated Consumer Contract）**：
   - 在 `packages/ui` 下设立独立的 `test-d/consumer` fixture 目录；
   - 其 `tsconfig.json` 配置 `"moduleResolution": "bundler"` 且**严禁配置任何 `@/*` 路径别名**；
   - 所有用例直接从本地构建产物 `brutx-ui-vue` 及其子路径（如 `brutx-ui-vue/button`）导入类型与组件；
   - 通过命令行执行 `vue-tsc --project test-d/tsconfig.json --noEmit`，100% 模拟外部工程真实消费，有效拦截导出遗漏与隐式 `any` 污染。

CI 接入与熔断自测：
- 为类型门禁提供独立的包级脚本 `pnpm --filter brutx-ui-vue test:types`；
- 在验证规范中建立“故意制造类型故障注入”的流程，确认门禁能精准拦截编译失败，验证通过后恢复。

### M4-E：主入口生成与公开边界编排

**目标**：自动化维护公开 API 导出，彻底替代手工维护 `packages/ui/src/index.ts`（488行）的高风险模式。

生成与策略契约：

- **顶层非组件符号编排策略源（SSOT）**：
  - 建立集中的公开导出策略文件（如 `packages/ui/scripts/root-exports-strategy.ts`）；
  - 除了基于 `registry-manifest.json` 自动收割组件及变体外，显式编排：
    1. 必需的样式副作用导入（`import './styles.css'`）；
    2. 全局 Composables（`useDialog`、`useMessage`、`useToast` 等）；
    3. 全局 Directives（`vLoading`、`vWatermark` 等）；
    4. 国际化包（`zhCN`、`enUS` 等）；
    5. 公共 Utils 与底层类型。
- **确定性与幂等性**：
  - 导出符号按统一规则稳定排序，保证不同操作系统与 Node 环境下生成结果字节级一致；
  - 仅在输出内容真实发生变动时执行磁盘写入。
- **CI 只读防漂移检测（Drift Guard）**：
  - 提供 `pnpm --filter brutx-ui-vue prebuild:entry --check` 模式；
  - CI 中仅在内存计算预期生成内容并与现有文件比对，检测到文件内容不一致时报错退出，杜绝未提交代码生成的静默合入。

### M4-D：站点 API 元数据组件化渲染

**目标**：彻底解决文档 API 手工维护低效与 Markdown 正则标记替换脆弱的问题，升级为行业前沿的 Component-Driven Docs 架构。

架构升级与实施契约：

- **解耦 Markdown 与 API 文本（放弃 AST 正则注入）**：
  - 严禁在 `apps/docs/components/*.md` 中使用注释标记正则替换表格文本，避免格式化错位与大面积 git diff 污染；
  - 组件 Markdown 文档保留纯粹的人工用法解释、图文展示与代码示例。
- **结构化元数据提取**：
  - `packages/ui/scripts/generate-api-docs.ts` 复用 `vue-component-meta` 提取器，将全量组件的 Props、Emits、Slots、Expose 与类型注释抽取为标准化 JSON 产物：`apps/docs/.vitepress/api-manifest.json`；
  - 提取支持展示标签格式化与集中覆盖扩展（如 locale 默认值、高级联合类型别名）。
- **VitePress 动态组件渲染**：
  - 在 `apps/docs/.vitepress/theme/` 中封装并全局注册 `<ComponentApi name="组件名" />` Vue 组件；
  - 在 Markdown 文档尾部仅需书写一行干净的标签：
    ```markdown
    ## API 参考
    <ComponentApi name="button" />
    ```
  - 页面加载时由组件读取 manifest 并渲染出带类型标签、属性筛选与折叠交互的现代化 API 表格。
- **全量门禁与覆盖验证**：
  - manifest 生成脚本接入 docs 构建流水线，并在缺失关键组件元数据或提取失败时返回明确错误码。

## 五、 质量门禁与验证矩阵

开发阶段严格执行最小化匹配验证；具体命令以[完整指令参考手册](../../../guides/COMMANDS.md)为准。

| 变动领域 | 必需验证命令与要求 |
| --- | --- |
| **CLI 命令与初始化逻辑** | `pnpm --filter brutx-vue test <相关测试路径>`；涉及配置接口时执行该包 `typecheck` |
| **UI 行为、格式化或倒计时** | `pnpm --filter brutx-ui-vue test <相关测试路径>`；补充 SSR 水合、可访问性（A11y）与可控时钟跳时断言 |
| **公开类型与消费端契约** | `pnpm --filter brutx-ui-vue test:types`；执行包构建并在 `test-d/consumer` 中运行消费端类型验证 |
| **样式、令牌与静态契约** | `pnpm check:contracts`；变动样式时补充多端与暗黑模式视觉核验 |
| **主入口生成与防漂移** | `pnpm --filter brutx-ui-vue prebuild:entry --check`，`test:package` 与 `check:isolation` |
| **文档与动态 API 表** | `pnpm check:docs`；执行 docs 站点构建与页面渲染视觉检查 |
| **新组件注册与构建** | 执行预构建生成链，以及 registry 包的 `pnpm --filter brutx-registry-vue build` 与 `validate` |

跨包集成与版本发布遵循全局完整门禁：`pnpm build && pnpm typecheck && pnpm lint && pnpm test`。

## 六、 技术依据与标准

- [Tailwind CSS 主题变量与解耦](https://tailwindcss.com/docs/theme)：说明主题变量独立文件拆分与 `@import` 导入规则。
- [MDN Intl.NumberFormat 规范](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/NumberFormat)：现代浏览器与 Node 原生国际化数值、BigInt 与高精度格式化规范。
- [W3C WAI-ARIA Live Regions 规范](https://www.w3.org/WAI/ARIA/apg/practices/aria-live/)：高频数字刷新的降噪原则与完成态单次提醒指南。
- [Vue Language Tools 元数据提取](https://github.com/vuejs/language-tools)：`vue-component-meta` 提取 SFC Props、Slots、Emits 结构化类型定义。
- [TypeScript 消费端类型隔离验证模式](https://www.typescriptlang.org/docs/handbook/declaration-files/publishing.html)：采用无路径别名的独立 fixture 验证打包产物类型推导的行业最佳实践。
