# 阴影过渡与焦点体系统一方案

> 方案类型：缺陷修复 + 架构收敛
> 状态：**superseded**（已被 [阴影组装化重构方案](../../plans/阴影组装化重构方案.md) 取代）
> 日期：2026-08-12（归档于 2026-08-14）
> 归档说明：本方案实施了 @utility 单层阴影与 outline 焦点体系；2026-08-14 经「阴影组装化重构方案」升级为 @theme 阴影组装化与 ring 五件套焦点体系，本方案已完成历史使命并归档。

## 背景

经浏览器实测（Chrome + docs dev server），发现并坐实两个相互关联的 box-shadow 属性争用问题：

1. **阴影悬停/按压抖动、硬切**：`--shadow-brutal*` 声明在 `@theme` 中，Tailwind v4 据此自动生成 5 层 `--tw-shadow` 组合工具类；悬停时 `:hover` 版本特异度（0,2,0）压过手写单层类（0,1,0），导致 box-shadow 在**单层 ↔ 5 层**间过渡，浏览器补零插值产生双影鬼影。
2. **焦点体系并行分裂**：ring 系（box-shadow 实现）与 outline 系并存。ring 与 brutal 阴影争用同一 box-shadow 属性，聚焦时互相顶掉，是同一根因的另一表现。

## 关键实测结论

- calc() **不是**抖动原因：同款 calc() 阴影、两端均为单层时过渡完全平滑（4→6px 连续插值）。
- 抖动原因：悬停时基态单层 `4px` 与悬停态 5 层组合（4 层透明 + 末层 `6px`）层数不匹配。实测过渡中途同时存在两条硬阴影（`2.7px@0.68` + `1.9px@0.32` 对穿），即"抖动"；不补零的浏览器则表现为"硬切"。
- 修复方向已验证：注入 `.hover\:shadow-brutal-lg:hover { box-shadow: var(--shadow-brutal-lg) }` 后，过渡变为干净的单阴影 4↔6px。
- 第三条路（`@utility`）已用独立 Tailwind v4.3 编译验证：**`--shadow-brutal*` 移出 `@theme` 为普通 `:root` 变量 + `@utility` 定义**，输出仅 12 条单层规则、变体（hover/focus/focus-visible/focus-within/data-[highlighted]/enabled:hover/disabled）全自动生成、无 5 层死代码。

## 方案 A：阴影过渡修复（已实测验证）

### 根因

[styles.css](../../../packages/ui/src/styles.css) 的 `@theme` 内 `--shadow-brutal*` 令牌使 Tailwind 自动生成 5 层 `--tw-shadow` 组合工具类，与手写单层类并存；悬停/按压等变体类（含 `:hover`/`:active`/`[data-highlighted]` 等）特异度更高，5 层版胜出，与单层基态之间发生 1↔5 层过渡 → 双影鬼影/硬切。

### 改动 1：`generate-styles-tokens.ts`

文件：[generate-styles-tokens.ts](../../../packages/ui/scripts/generate-styles-tokens.ts)

1. 从 `THEME_GROUPS` 删除 "Dynamic: shadows use --brutal-shadow-* for dark mode" 分组，即 6 条 `--shadow-brutal*` 不再进入 `@theme`；分组内容提取为顶层 `SHADOW_ENTRIES` 常量。
2. 在 `generateRootBlock()` 中将这 6 条表达式（`var(--brutal-shadow-offset-x, ...) ...` 等，fallback 取自 `BASE_THEME.light`，与原文 `@theme` 的 `build()` 完全一致）追加到 `:root` 声明。**只发 `:root`，不发 `.dark`**——它们引用运行时 `--brutal-*`，亮/暗同一份。

令牌唯一源仍是 `design-tokens.ts`（[design-tokens.ts](../../../packages/shared/src/design-tokens.ts) 的 `shadowOffsetX/Y`/`shadowColor` 映射），仅改变发射位置。

### 改动 2：`styles.css`

文件：[styles.css](../../../packages/ui/src/styles.css)

将 `@layer utilities` 内的 6 条手写 `.shadow-brutal*` 类**替换**为顶层 `@utility`（单一来源，变体由 Tailwind 按需自动生成，无需手写任何变体规则）：

```css
@utility shadow-brutal          { box-shadow: var(--shadow-brutal); }
@utility shadow-brutal-sm       { box-shadow: var(--shadow-brutal-sm); }
@utility shadow-brutal-lg       { box-shadow: var(--shadow-brutal-lg); }
@utility shadow-brutal-xl       { box-shadow: var(--shadow-brutal-xl); }
@utility shadow-brutal-primary  { box-shadow: var(--shadow-brutal-primary); }
@utility shadow-brutal-secondary{ box-shadow: var(--shadow-brutal-secondary); }
```

### 实施验证（2026-08-12）

1. `pnpm --filter brutx-ui-vue prebuild:tokens` → `@theme` 已无 shadow 令牌、`:root` 新增 6 条派生变量、`.dark` 未发。
2. `pnpm --filter brutx-ui-vue build` → `dist/styles.css` 中 `shadow-brutal*` box-shadow 规则全部单层（无 `var(--tw-inset-shadow),` 组合）；hover / focus / focus-visible / focus-within / active / enabled:hover / disabled / disabled:hover / data-[highlighted] / data-[state=...] 变体规则齐全。
3. `pnpm --filter brutx-ui-vue typecheck` 通过；`vitest run` 3596 用例全通过。
4. **docs 二次编译链路**：docs 通过 `@import 'tailwindcss'` + `@import packages/ui/dist/styles.css` 二次编译（[apps/docs/.vitepress/theme/style.css:19-20](../../../apps/docs/.vitepress/theme/style.css#L19-L20)），不会重新生成库源码未扫描到的变体——全库用法均为完整字面量（[brutal-interaction-variants.ts](../../../packages/ui/src/lib/brutal-interaction-variants.ts#L2-L4) 的扫描约定），dist 变体齐全。

### 波及与风险

- **行为无变化**：`shadow-brutal*` 类名与全部变体用法保留，仅改底层实现。唯一实现差异：规则存在性从"手写类无条件输出"变为"@source 扫描驱动"——全库用法均为完整字面量（项目既有扫描约定，见 [brutal-interaction-variants.ts](../../../packages/ui/src/lib/brutal-interaction-variants.ts#L2-L4) 注释），实际产物无差异；消费者侧无感知。
- **消费者 `@theme { --shadow-brutal-lg: ... }` 覆盖失效**：令牌移出 `@theme` 后该路径不可用；但正规主题化路径是 `--brutal-shadow-*` 运行时变量，`--shadow-brutal*` 本就是其派生值。写进变更说明。
- `active:shadow-none`（Tailwind 内置 5 层透明）与单层基态过渡的鬼影不可见（目标全透明），无需处理；如需彻底干净可后续覆盖为字面 `none`（可选项）。
- **`shadow-brutal-primary/secondary` 的 `--tw-shadow-color` 死规则（既有现象，记录备查）**：`brutal-primary/secondary` 命中 `@theme` 主题色，Tailwind 额外把 `shadow-brutal-primary/secondary` 按 shadow-{color} 工具输出 `--tw-shadow-color` 规则（共 8 条死规则）。box-shadow 直接 `var()` 引用不受影响、无视觉回归，旧 `@theme` 实现同样存在该解析；唯一风险是消费方把 `shadow-brutal-primary` 与内建 `shadow-{size}` 同挂一元素会污染其阴影色。
- 本方案只解决悬停/按压阴影，不改变聚焦体系（方案 B）。

## 方案 B：焦点与选中指示体系合一——统一到 outline

### 结论

ring 系（box-shadow 实现）与 outline 系两条实践**能合成一条**，且应合到 **outline**——连同选中态状态 ring 一并迁移，根除 ring 系在库内的残留。

### 为什么分裂、为什么选 outline

- ring 系（box-shadow 实现）与 brutal 阴影（也是 box-shadow）在**同一属性上争用**，聚焦时只能赢一个：ring 组合赢则 brutal 偏移阴影被顶掉（聚焦瞬间"跳动"）；ring 输则聚焦无指示器。textarea 同时挂 `focus:shadow-brutal` + `focus-visible:ring-2` 即典型受害者。这是属性级必然冲突，不能靠共存，只能二选一。
- 选 outline：不用 box-shadow → 与 brutal 阴影**永不冲突**；符合已文档化的项目约定"焦点态优先 outline"（ring 基于 box-shadow、特异度高于 brutal 阴影导致聚焦瞬间阴影跳动）与 Button 前例；forced-colors 下 outline 仍可渲染而 ring 会被 UA 禁用（现状组件多配 `focus-visible:outline-none`，forced-colors 下完全无指示器，迁移同时修复此点）；视觉契合粗野硬边。
- 选中态状态 ring（tags-input item 的 `data-[state=active]:ring-2`、color-picker swatch 的 `selected:ring-2`）与本根因同源：前者与 `shadow-brutal-sm` 争用、选中时阴影被顶掉，应随迁移一并消解。

### 现状核实（2026-08-12）

- `FOCUS_RING_CLASSES`（[utils.ts](../../../packages/ui/src/lib/utils.ts#L15-L16)）**零组件引用**：全库仅定义 + [index.ts](../../../packages/ui/src/index.ts#L322) 再导出 + 一份 plan 文档提及，属未落地死导出。组件用的是各自内联的 ring 类（前缀与宽度不统一：`focus:` / `focus-visible:` / `focus-within:` / `ring-1` / `ring-2`），与常量内容（`ring-3` + `outline-transparent`）都不一致。
- 可见 outline（`focus:outline focus:outline-[2/3px] focus:outline-brutal-ring focus:outline-offset-2`）目前仅 [button-variants.ts](../../../packages/ui/src/components/button/button-variants.ts#L12) 与 [Image.vue](../../../packages/ui/src/components/image/Image.vue) 的 8 处内操作按钮。
- 引入时间：button outline = f5f4dbe3（2026-06-02，v0.3.0 前）；image outline = f428f7e6（2026-07-05，v0.3.0 后）；`FOCUS_RING_CLASSES` = d2e80718（2026-07-04）。

### 统一常量

将 `FOCUS_RING_CLASSES` 改造为统一常量（命名 `FOCUS_OUTLINE_CLASSES`），**统一 `focus-visible:` 前缀**——键盘导航触发、鼠标点击不残留焦点环（WCAG 2.4.7 语义；badge/pagination 等原 `focus:` 组件点击聚焦不再显示指示器，属行为统一而非回归，写入变更说明）。常量**不写裸 `outline` 样式段**：Tailwind v4 的 `outline-<n>` 自带 `outline-style: var(--tw-outline-style)`（`--tw-outline-style` 经 `@property` 默认 `solid`），且裸 `outline` 经 `cn()`/twMerge 会与 `outline-2` 同组冲突被合并丢弃（实测走 twMerge 的组件会缺类）：

```ts
export const FOCUS_OUTLINE_CLASSES =
    'focus-visible:outline-2 focus-visible:outline-brutal-ring focus-visible:outline-offset-2'
```

### 风险

- 迁移面 21 个组件 + 2 个共享变体文件 + 测试更新，是本次最大变更面；但均为**模式明确的替换**（4 种模式见 A 组表格），逐文件核对即可，非自由改写。
- 视觉近似但非完全等价：ring-2/offset-2 ↔ outline-2/offset-2 等价；**无 ring-offset 的组件（date-picker/color-picker/dropdown-menu/cascader .vue 内联）迁移后新增 outline-offset-2**（轻微视觉变化）；data-table ring-1 → outline-1 保留；Button/Image 3px → 2px。
- **行为统一**：badge/pagination/cascader/tree-select/ColorPicker.vue/Button/Image/dialog/sheet 从 `focus:` 统一为 `focus-visible:`——鼠标点击后不再残留焦点环，键盘 Tab 仍显示（WCAG 2.4.7 语义），写入变更说明。
- 统一后聚焦时 brutal 阴影不再被顶掉，属修复而非回归；input/number-input/textarea/hardcore-input 的 focus 阴影 + outline 共存是新组合，浏览器实测确认。
- outline 是否跟随圆角：rounded-brutal 默认 0px，pastel/warm 主题下 4-8px；旧版浏览器 outline 为矩形角而 ring 跟随圆角，差异极微小，可接受。
- **Tailwind v4 `--tw-outline-style` 变量陷阱（实施确认）**：任何 `outline-none`（含 `focus:outline-none`、常驻 `outline-none`）会把 `--tw-outline-style` 置为 `none`，使同元素上 `outline-<n>` 的 `outline-style: var(--tw-outline-style)` 解析为 none、焦点环不渲染。**凡是迁移到 outline 的组件一律不得保留任何 `outline-none`**。实施时已清理 select（删 `focus:outline-none`）与 dropdown-menu（删 base 常驻 `outline-none`）。
- **Safari 点击焦点环（已知限制）**：统一 `focus-visible:` 后，Chrome/Firefox 鼠标点击不显示系统焦点环，但 Safari 的 UA 焦点环作用于 `:focus`（鼠标点击命中）——原 `focus:outline-none` 抑制的这些按钮类控件（badge/pagination/cascader/tree-select 清除钮等）在 Safari 上点击会出现系统环。保留 `focus:outline-none` 会彻底破坏键盘焦点环（上述变量陷阱），两害取其轻接受 Safari 差异。
