# 组件状态与音频资源深化方案

> 集中 Kanban 移动规则、表格数据编排和音频资源生命周期，以统一的状态所有权减少组件协作成本，并共享选择值的基础判定。

## 一、目标与交付范围

本方案以 2026-09-12、提交 `7d30ca7e` 对应的 UI 源码为核对基线。实施开始时记录实际提交、工作区相关变更和工具链版本，按当前源码复验本文引用的契约。

深化以调用者需要掌握的规则为衡量对象：模块应隐藏操作顺序、状态同步和资源释放规则，调用者通过稳定的 interface 获取行为。内部可以继续由多个函数或 composable 组成；验收关注规则是否集中、同一行为是否由同一实现提供，以及测试能否穿过实际调用的 seam 验证结果。

| 工作包 | 优先级 | 目标 | 完成后的主要收益 |
| --- | --- | --- | --- |
| K：Kanban 移动控制器 | 首批 | 组件与 headless 用法共享卡片移动、列移动及交互状态 | 移动规则修改和回归集中，拖拽与键盘结果一致 |
| T：DataTable 数据编排 | 第二批 | 集中过滤、排序、分页、选择和数据替换之间的协作 | 调用者直接消费表格视图数据，组合规则可独立验证 |
| A：音频运行时 | 第二批 | 共享上下文、缓存白噪声缓冲、管理使用者生命周期 | 多组件共享资源，单个实例释放与其他实例播放相互隔离 |
| P：选择值判定 | 随相关组件整理 | 共享基础空值语义 | 清除按钮与触发器空态采用同一判定规则 |

K、T、A 分别组织实现和验收，彼此没有运行时依赖。建议先交付 K，再分别推进 T、A；P 可独立提交。本文作为这四个工作包的统一执行方案，各包有独立退出条件。

### 1.1 与工程架构方案的衔接

[架构交付契约第三批修复方案](../core/架构交付契约第三批修复方案.md)负责公开 API 分类、入口生成、依赖层级和工程门禁。本方案负责 UI 运行时行为与调用关系，沿用其实施后提供的公开契约和生成入口。

新增内部实现优先落在 `packages/ui/src/lib/` 的领域目录，通过具体文件相对路径导入。每个内部文件都要进入组件源码安装的依赖闭包；公开入口登记按第三批方案管理。在该契约生成机制落地前，使用当前生成器检查实际入口与安装闭包，逐项核对内部模块的可见性。

Kanban 的类型与输入所有权调整采用 0.x 的直接迁移方式：同步更新调用方、声明、示例和 changeset。DataTable 既有四个状态 composable 继续提供各自独立能力；新增流水线属于内部编排。音频调用方继续使用现有声音语义。

## 三、K：Kanban 移动控制器

### 3.1 模块与 interface

以 `useKanban` 作为共享控制器，`KanbanBoard` 调用该控制器。卡片、列和移动结果类型归属于 `packages/ui/src/lib/kanban/`；组件类型文件与公开 composable 具名重导出同一声明。

| 接口部分 | 约定 |
| --- | --- |
| 输入 | 响应式列数据读取入口，以及必填的 `onColumnsChange(nextColumns, change)` 更新出口 |
| 状态输出 | 只读的鼠标拖拽、键盘抓取和目标列状态；集合、对象采用深只读视图 |
| 卡片命令 | 指定卡片、源列、目标列和目标插入位置；提供列内前后移动、相邻列移动的语义入口 |
| 列命令 | 指定源列与目标位置；返回本次计算的目标索引 |
| 交互命令 | 开始或结束拖拽、抓取或释放卡片、更新目标列；接受业务标识和语义动作 |
| 结果 | 以 `moved`、`unchanged`、`invalid` 区分结果；`moved` 携带本次计算的 change，`invalid` 携带原因 |

`change` 通过 `kind` 区分 `card-move` 与 `column-move`。卡片变更包含 `cardId`、`fromColumn`、`toColumn`、`fromIndex`、`toIndex`；列变更包含 `columnId`、`fromIndex`、`toIndex`。索引分别对应本次命令的工作快照和计算出的 nextColumns。

控制器负责决定变更和交互状态。组件在 `onColumnsChange` adapter 内按顺序发出 `update:modelValue(nextColumns)` 及对应移动通知：`card-move(cardId, fromColumn, toColumn)` 或 `column-move(columnId, fromIndex, toIndex)`。卡片事件保持三个参数，完整索引通过控制器结果提供。`moved` 和移动通知表示计算出的更新请求；父级是否采纳以及最终位置由外部输入回流确定。headless 调用方将同一更新出口连接到自己持有的数据。DOM 事件解析、焦点和 ARIA 播报放在组件 adapter 中。

### 3.2 数据所有权与连续操作

列输入由外部持有，控制器按不可变方式计算下一份数据，保持调用方传入的数组和卡片对象内容。内部保留当前更新批次的工作快照，使同一 tick 的连续移动基于前一条命令的结果。

每次有效移动同步推进工作快照并调用更新出口。同步回调中的重入命令使用已推进的快照；观察到新的外部输入时，先同步权威数据再计算后续命令。在 Vue 更新批次结束后再次读取外部值，收敛父级接受、规范化或拒绝更新的情况。即使父级拒绝更新且 prop 引用保持原样，也完成本批次回读。工作快照仅覆盖当前更新批次。

异步到达的外部替换按到达顺序成为权威输入；请求排序、过期响应过滤与服务端确认由父级负责。控制器接收当前列数据和同步更新出口。

输入支持整体替换，以及响应式列数组、cards 数组的原地增删和重排。控制器跟踪列 ID、卡片 ID 与所属列、顺序组成的结构投影，以识别实体位置和有效性变化；卡片其他内容由外部输入继续持有。外部回流时同步校正交互状态：

- 键盘抓取按卡片 ID 重新定位所属列；卡片不存在时清理抓取状态。
- 鼠标拖拽的卡片不存在、所属列已改变，或拖拽列不存在时，取消当前拖拽；失效的目标列状态同步清理。
- 校正与清理保持幂等，后续命令从校正后的状态开始。

组件在本批次外部数据收敛且 DOM 更新后，按卡片 ID 定位焦点并播报实际位置。父级拒绝请求时保留原位置的焦点，完成播报仅在实际位置改变时触发；父级规范化落点时使用规范化后的位置。实体删除后将焦点移交仍存在的来源列或看板容器。同一批次反馈只使用最新交互目标，取消、卸载或后续交互会使旧调度失效。异步数据替换负责更新状态与渲染，主动焦点恢复和移动播报由当前用户交互批次触发。

### 3.3 移动与交互规则

1. 卡片 ID 在看板内唯一，列 ID 在列集合内唯一；目标、源和实体有效性在一次移动提交前完成检查。无效操作返回原因，更新出口保持静默。
2. 卡片插入索引统一表示“移除被移动卡片后，目标列中的插入位置”。组件测量 DOM 时排除被拖卡片，再把剩余元素几何位置转换成该索引；最终位置钳制到目标列允许范围。
3. 同列移动、跨列移动和键盘移动共用卡片迁移实现。移动结果中的索引与最终数据位置相同。
4. 相邻列键盘移动把卡片放到目标列末尾；列内方向移动到达边缘时返回 `unchanged`。列排序采用移动到目标列索引的语义。
5. 每次命令计算出位置变化时触发一次更新出口及一次对应移动通知；原位释放返回 `unchanged`，无效命令与原位命令均保持事件静默。父级回流引发的校正只同步状态。事件次数与更新请求语义同步写入组件使用说明与 changeset。
6. 鼠标拖拽、列拖拽和键盘抓取保持互斥；开始新的交互时清理冲突状态，结束与取消均可重复调用。
7. RAF 延迟点击抑制、DataTransfer、DOM 焦点和国际化播报由组件管理，drop adapter 保持 `preventDefault`；卸载时释放自身调度资源。

### 3.4 测试与退出条件

| 场景 | 通过标准 |
| --- | --- |
| 同列与跨列移动 | 卡片数量与 ID 集合守恒，目标顺序和结果索引一致 |
| DOM 顺序、源数据顺序不同 | 组件按目标插入位置契约传入命令，控制器得到正确结果 |
| 数据边界 | 空列、末尾插入、原位释放、实体删除和无效标识均有确定结果 |
| 同 tick 连续移动 | 后续命令及回调重入基于最新有效快照；父级保持原 prop 引用拒绝时仍完成回读 |
| 权威数据回流 | 接受、拒绝、规范化后，抓取位置、下一次方向命令、焦点与实际数据一致；异步替换按外部到达顺序同步 |
| 原地结构更新 | 响应式数组增删及重排后实体和目标有效性同步；卡片原地换列后抓取位置校正、鼠标拖拽取消 |
| 移动事件与反馈 | 每个 moved 发出一次更新请求及对应参数的移动通知；原位与无效命令静默，父级拒绝后保持原焦点并结束完成播报调度 |
| 交互切换 | 鼠标与键盘状态互斥，取消、结束、卸载后状态与调度释放 |
| 组件交互 | Enter 点击、Space 抓取、方向移动、Escape 释放、焦点和播报符合现有用法 |
| 输入所有权 | 原始输入保持完整，所有更新经过统一出口，公开状态只读 |
| 实现集中 | Board 与 headless 路径都调用同一移动实现，双方的行为用例覆盖实际调用链 |

使用 [useKanban 测试](../../../../packages/ui/src/composables/useKanban.test.ts)覆盖控制器命令和输入所有权；[Kanban 组件测试](../../../../packages/ui/src/components/kanban/kanban.test.ts)与[看板测试](../../../../packages/ui/src/components/kanban/kanban-board.test.ts)保留事件、DOM 和无障碍行为。原位用例同时断言数据、事件次数与交互结束状态，测试名称与断言一致。重复的移动算法断言集中到控制器测试，组件保留代表性接线断言。

## 四、T：DataTable 数据编排

### 4.1 模块与职责

在 `packages/ui/src/lib/data-table/` 建立内部 `useDataTablePipeline`，复用现有排序、过滤、分页和选择模块。其输入包括响应式 data、columns、rowKey、功能开关及 pageSize；输出包括展示行、过滤后总数和各状态域的只读视图与命令。

行身份以唯一、稳定的字符串或数值 key 为前提。同一挂载周期内，rowKey 的字段或函数身份规则保持稳定，函数所依赖的外部数据也保持行身份语义稳定。切换身份规则时，调用方更新组件 `key` 重新挂载，headless 调用方销毁旧作用域并创建新流水线；外部 expandRowKeys 同时切换为新身份规则下的输入。该约定同步到表格使用文档和示例。

流水线持有从输入到展示数据的 computed 链及跨状态 watcher。组件直接消费结果，通过结果与状态转发当前组件事件。数据层测试使用 Vue 响应式作用域即可运行；展开与虚拟滚动继续通过组件测试验证。

### 4.2 集中管理的规则

1. 数据按过滤、排序、分页的顺序处理；分页总数来自过滤后数据，结果缓存位于流水线内。
2. “全选当前页”使用展示行；选中结果回查完整输入，支持保留其他页及被过滤行的选择。
3. 整体替换 data 时比较 rowKey 集合：集合相同保留页码与选择；集合变化同时清空选择并回到第一页。增删行由调用方提交新的 data 数组引用以触发该同步规则；行内容原地更新继续通过响应式计算影响展示结果。该规则作为本表格整批数据更新的既有策略保留。
4. 列过滤增量 patch 在流水线内按当前状态合并，删除条件和新增条件共享同一更新出口；同 tick 不同列或日期两端更新都保留。`DataTableColumnFilter` 负责输入事件及本地 pending 缓冲。
5. 隐藏列、过滤类型与日期解析、排序比较、pageSize 校验、页码钳制继续由现有领域模块处理。流水线通过它们的命令更新状态。
6. 组件事件名称、参数及实际触发条件逐项从当前处理器迁移；数据 watcher 导致的内部重置按现有行为处理，用户命令与内部同步分别覆盖测试。

### 4.3 功能开关与事件矩阵

| 输入变化 | 状态与展示行为 |
| --- | --- |
| sortable 关闭与重新开启 | 关闭时阻止切换排序，已有有效列的排序状态继续参与数据处理；重新开启后从保留的排序状态继续切换 |
| filterable 关闭与重新开启 | 关闭时暂时绕过过滤，过滤状态保留；重新开启后使用当时的过滤状态 |
| selectable 关闭与重新开启 | 关闭时隐藏选择入口并阻止行选择和全选命令，已选 key 保留且可通过 clearSelection 清空；重新开启后按当时的选择集展示 |
| paginated 关闭与重新开启 | 关闭时展示全部排序后数据，页码和页大小保留；重新开启后按当前页码分页，页码始终服从总页数钳制 |
| 外部 pageSize 更新 | 合法值同步为页大小，非法值回到既有默认值；当前页保留并在超出总页数时钳制 |
| setPageSize 命令 | 合法值更新页大小并回到第一页；非法值保持原状态 |

| 事件来源 | 对外通知规则 |
| --- | --- |
| 用户排序、行选择和全选 | 沿用组件处理器的有效性检查及 sort、select 参数和次数 |
| 过滤状态变化 | 组件监听过滤状态并按 Vue watcher 调度发送 filter，覆盖用户输入与程序化过滤命令；同批次按最终状态通知 |
| 用户翻页 | 页码实际变化时发送 page-change |
| 用户设置页大小 | 沿用页大小处理器发送 page-size-change，内部回到第一页保持 page-change 静默 |
| 程序化排序、选择与分页命令 | 只更新相应状态，sort、select、page-change、page-size-change 保持静默 |
| data 替换引发重置、页码钳制、开关和外部 pageSize 同步 | 选择与分页内部同步保持 select、page-change、page-size-change 静默；实际过滤状态变化仍遵循 filter watcher 规则 |

事件转发由组件持有，流水线负责状态结果。表格使用文档与上述来源矩阵一致，程序化过滤命令同样受过滤状态 watcher 观察。

### 4.4 测试与退出条件

新增 `data-table-pipeline.test.ts`，经流水线 interface 验证组合行为：

- 使用能区分处理顺序的数据，断言过滤、排序、分页后的完整行 ID 序列及总数。
- 切换分页、取消当前页全选后，其他页及被过滤行的选择保持正确。
- 相同 key 的内容替换保留状态；增删 key 同步重置选择与页码。
- 同 tick 多列更新、日期范围两端更新及清除过滤后，最终过滤状态和展示数据完整。
- 功能开关、页大小、隐藏列及空数据变化后，各模块状态与展示结果一致。
- 逐项覆盖开关关闭、重新开启、外部 pageSize 与程序化命令的状态和事件矩阵。
- 用字段与函数两种 rowKey 验证稳定身份；通过重新挂载或重建作用域切换身份后，选中数量、实际选中行和新输入的展开状态一致。

现有四个 composable 的独立行为测试继续覆盖各自公开能力。[DataTable 集成测试](../../../../packages/ui/src/components/data-table/data-table.test.ts)覆盖组件事件、受控展开、虚拟滚动测量及列过滤接线。退出时，组件中数据 computed 链与 key 集合重置规则均由流水线持有，相关外部事件契约通过。

## 五、A：音频运行时与资源所有权

### 5.1 模块分工

在 `packages/ui/src/lib/audio/` 建立共享运行时和 Web Audio adapter。共享范围为同一 JavaScript realm 中同一 UI 模块实例；每个隔离 realm 或重复打包的模块实例拥有自己的运行时。

| 模块 | 负责的行为 | 主要 interface |
| --- | --- | --- |
| `useAudioEngine` | 实例启用状态、type 音效节流、永久 dispose 与 Vue 卸载接线 | 保留 `playSound(type)`、`dispose()` |
| 共享运行时 | 延迟获取、使用者 lease、待播请求时效、resume 协调、最后释放、异步代次检查 | 获取 lease；lease 播放与幂等释放 |
| Web Audio adapter | 上下文与节点、声音配方、白噪声缓存、实际播放和设备清理 | 状态读取与订阅、resume、返回播放句柄的声音调度、close |
| 测试 adapter | 可控状态、可延迟或拒绝的异步操作、播放与释放记录 | 实现相同设备 interface |

adapter seam 放在运行时内部，通过工厂注入。浏览器环境探测在首次有效播放路径进行；组件继续使用语义音效接口。`HardcoreInput` 保留 `type/success/fail`，触觉门面保留 `click/snap/beep`，数值配方沿用 [集中常量](../../../../packages/ui/src/lib/defaults.ts)。

`useBrutalHaptics` 的 sound 输入采用 `MaybeRefOrGetter<boolean | undefined>`，通过 `toValue` 建立启用状态依赖；[NumberInput](../../../../packages/ui/src/components/number-input/NumberInput.vue) 与 [Switch](../../../../packages/ui/src/components/switch/Switch.vue) 传入 sound getter 或 prop ref。[HardcoreInput](../../../../packages/ui/src/components/hardcore-input/HardcoreInput.vue) 继续以 prop ref 接入引擎。三个组件的动态开关均由同一引擎生命周期规则处理。

每次声音调度返回播放句柄，提供幂等 `cancel()` 与播放结束通知。运行时按 lease 持有句柄集合；自然结束、取消和调度失败均清理节点引用及所属记录。adapter 负责停止声源、断开连接与撤销结束回调，运行时负责把释放命令限定到对应 lease。设备状态订阅在对应代次退役时解除。

### 5.2 生命周期规则

1. 挂载、导入和静音调用保持资源空闲；首次有效播放才获取 lease 并按需创建上下文。创建失败时结束该次请求，按现有引擎不可用状态终止该实例后续设备创建。
2. 多个有效 lease 共享上下文；type 节流按引擎实例计算，用户在不同控件输入时各自得到反馈。
3. suspended 或 interrupted 状态下，由有效播放交互触发 resume，同一上下文合并为一个进行中的恢复操作。恢复完成与 statechange 到达时重新检查实际设备状态，仅在 running 且当前代次可用时调度有效请求。恢复失败结束所属请求；后续有效交互可重新尝试，状态通知本身只检查就绪和清理状态。
4. `dispose` 永久终止对应引擎，清理其待播请求和待获取设备的请求，取消其全部播放句柄，再释放 lease；调用方持有的旧 `playSound` 引用保持静默。单个 lease 释放时，其他 lease 的播放保持有效。
5. 启用状态变为关闭时，执行本实例请求、句柄和 lease 的清理；重新启用后由下一次交互获取资源。永久 dispose 与临时关闭采用不同状态。动态关闭即使发生在 acquire、resume 或 close 等待期间也使所属请求失效。
6. 最后一个 lease 释放时立即进入 closing，停止向该代设备调度声音，并发获取等待本次关闭结果。关闭成功并确认设备释放后，新请求按需创建下一代上下文。关闭拒绝时，adapter 根据设备状态与关闭阶段给出结果：已确认关闭的设备退役；确认关闭尚未启动且设备仍可恢复时保留原设备，后续有效交互重新检查状态；关闭已启动或状态尚未确认时继续隔离该代设备，等待确认释放后再创建替代设备。等待请求始终服从实例生命周期与时效规则。
7. 旧代次的 resume、close、statechange 和节点结束回调只影响其所属资源。每次关闭失败有一次对应诊断记录，清理操作与重复 dispose 保持幂等；测试 adapter 覆盖关闭前拒绝、关闭中、已关闭等真实状态转换。
8. 创建部分节点后发生连接或调度失败时，adapter 清理已经创建的节点，并终止该次播放；其他实例仍可继续使用运行时。

### 5.3 待播请求与时效

每个引擎实例只保留最新一条待播请求。通过启用状态与节流检查的新请求替换旧请求，包含 success 与 fail 在内的六种语义都按调用顺序更新。请求由引擎实例持有生命周期，分配 lease 后关联其资源代次；等待 acquire、resume、interrupted 恢复及 close 结束期间使用同一记录。运行时以集中记录管理等待请求，每次恢复只读取当时仍有效的最新记录。

请求记录单调时间戳和到期时间。待播时效在 `defaults.ts` 中以具名策略常量统一定义；资源基线阶段结合浏览器首次与恢复播放耗时、交互反馈可接受的等待窗口确定取值，并在进入运行时实现前记录该值及测量依据。测试注入时钟验证时效边界，浏览器验收记录首声反馈是否满足该窗口。实际调度前同时校验实例存活、启用状态、lease、设备代次、请求是否仍为最新以及是否到期。年龄达到时效上限即丢弃，重新启用由新的交互产生新请求。

上述容量限制作用于等待中的交互反馈，已开始播放的声音沿用现有配方与实例节流。设备恢复后只播放各实例仍及时有效的最新反馈。规范允许 resume 保持 pending；实现与测试据此覆盖长时间等待。[Web Audio resume](https://webaudio.github.io/web-audio-api/#dom-audiocontext-resume)

### 5.4 缓冲缓存与可测量目标

白噪声 AudioBuffer 按上下文代次和配方参数缓存。当前 snap 固定使用既有时长常量，因此同一代次首次 snap 生成缓冲，后续播放复用该缓冲；每次播放创建自己的 BufferSource。采样率和配方参数参与缓存身份，设备释放后清空所属缓存。

| 场景 | 通过标准 |
| --- | --- |
| 多实例播放 | 同一运行时的多个有效使用者共享一个存活上下文 |
| 中间实例卸载 | 其节点和 pending 请求释放，其他实例继续播放 |
| 最后实例卸载 | 尝试关闭上下文，节点、lease 和缓冲引用释放；失败路径按生命周期规则处理 |
| 连续挂载卸载 | 记录每轮构造、缓冲生成、释放完成、首声恢复与空闲占用，确认立即关闭策略下的资源释放和恢复表现 |
| 连续 snap | 每个上下文代次及参数组合只生成一次缓冲，每次播放使用独立声源 |
| resume / dispose / 关闭开关竞态 | 失效请求不会创建节点，旧回调不会改变新代次 |
| close / acquire 竞态 | 关闭完成前保持单个存活上下文，等待请求服从 lease 生命周期 |
| 长时间等待与连续请求 | 每实例待播记录至多一条，新请求替换旧请求；到期请求丢弃，恢复后播放数量与最新有效记录一致 |
| interrupted 与 statechange | 中断时保持设备就绪检查，恢复到 running 后按时效调度；失败后的新交互可恢复，旧状态通知保持代次隔离 |
| 三个组件动态启停 | NumberInput、Switch、HardcoreInput 均覆盖初始静音、启用、等待中关闭、播放中关闭与重新启用，其他实例继续有效 |
| SSR 与默认静音 | 导入、服务端渲染和静音交互均不访问设备构造器 |
| 配方与节流 | 六种现有音效语义、配方常量和实例级 type 节流通过回归 |

### 5.5 验证层次

共享运行时测试使用可控 adapter 与时钟验证所有权、待播记录、时效和竞态；Web Audio adapter 测试用设备形状替身验证缓冲复用、播放句柄取消、结束通知、设备状态与失败清理。组件测试覆盖三个调用方 sound 的响应式切换、等待期间释放及配方转发。

浏览器验证通过实际交互触发多个 HardcoreInput、NumberInput 和 Switch，记录构造次数、存活数量、缓冲复用、卸载过程、首次与恢复播放耗时及到期丢弃结果；构造计数包装必须转发到真实 AudioContext。分别执行多实例并存和连续挂载卸载，并在 sound 动态关闭后确认所属声音停止、其他实例继续播放。

首批至少在本项目可运行的 Chromium 浏览器完成真实设备验证，并在记录中列明浏览器、系统和音频环境。interrupted 与恢复逻辑通过可控 adapter 覆盖；Safari 等浏览器的实际中断恢复能力按对应真实验证结果声明。浏览器验证范围、设备中断复现条件与模拟 adapter 结果分别登记。[MDN 设备状态说明](https://developer.mozilla.org/en-US/docs/Web/API/BaseAudioContext/state)

资源退出采用最后 lease 释放后立即关闭的策略，验收同时报告并存场景的共享收益与连续挂载场景的创建成本。结论以构造、缓冲、释放和实际反馈耗时为依据。

## 六、P：共享选择值判定

在 `packages/ui/src/lib/selection-value.ts` 提供内部纯函数，由 `useClearable` 和 `useSelectableTrigger` 调用。基础语义如下：

| 输入 | 已有值 |
| --- | --- |
| `null`、`undefined`、空字符串、空数组 | 否 |
| 有元素的数组、有字符的字符串 | 是 |
| 数值零、布尔 false、对象 | 是 |

字符串按长度判定，保留空白字符作为有效值。触发器继续按“显式 hasValue、getHasValue、基础判定”的优先级求值。基础判定只统一值语义，响应式依赖继续由各自 computed 持有。

`useClearableSelection` 负责清除值和事件处理，`useSelectionDisplayText` 负责文本格式化。组件的自定义判定保持独立；基础函数共享不改变组件选择业务。

利用现有清除与触发器测试验证基础值、显式 false、自定义判定及响应式切换；组件回归验证清除前的事件阻止、清除后事件名称与次数、悬停和聚焦显示。该工作包以现有调用方行为一致、基础规则只有一个实现为退出条件。
