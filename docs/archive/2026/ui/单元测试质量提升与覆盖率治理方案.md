# 单元测试质量提升与覆盖率治理方案

## 一、目标与范围

测试的首要价值是发现可观察行为和公共契约的退化。覆盖率用于定位执行盲区与约束退化，不能单独证明断言有效、交互正确或符合无障碍规范。

本期治理范围为 `packages/ui` 的 SSR 测试、TreeSelect 键盘导航、Upload 交互与公开方法、SubMenu 交互，以及 UI 覆盖率配置和 PR 检查。实施顺序为：固定基线、建立可靠的失败判定、补齐行为测试、校准覆盖率、接入合并前门禁。

测试揭示的行为缺陷应按照组件契约修复，并保留回归用例。测试矩阵以外的 API 扩展、其他包的覆盖率治理及全仓变异测试平台建设不属于本期交付。

### 2. 基线采集要求

实施开始时，保存 UI 包完整覆盖率与 SSR 运行结果，记录 Git 提交、工作区是否有未提交变更、操作系统、Node、pnpm、Vitest 版本、锁文件状态、命令、退出码及告警来源。机器报告作为 CI 产物保存，PR 中列出运行链接和四维汇总。

全量报告与筛选测试产生的局部报告应分目录保存，避免局部结果覆盖完整基线。覆盖率对比必须使用相同 provider、采集范围和测试集合；SSR、浏览器测试在各自配置下独立验收，其通过结果不自动计入 happy-dom 覆盖率。

## 三、SSR 失败判定与合法装配

主要修改 [ssr-smoke.test.ts](../../../../packages/ui/src/ssr/ssr-smoke.test.ts)。

1. 合法装配用例直接等待 `renderToString`，任意非预期异常均使测试失败。移除通过错误信息黑名单放行其他异常的逻辑。
2. 对 ScrollBar、Command 子组件、ToggleGroupItem、TagsInput 子组件等逐一核对实际上下文依赖，优先通过库公开的组合方式装配，必要时使用对应 Reka Provider。复用现有渲染 helper 和表驱动夹具。
3. 按组件真实 props 补齐最小合法输入，包括 DataTable 的 `rowKey`、TreeSelect 的 `nodes`，以及树节点需要的选择与展开集合。夹具遵循严格类型约束。
4. 对应当输出 DOM 的组件断言关键元素、角色或内容。合法的空输出、注释占位或 Portal 输出按组件逐项定义，不以统一的字符串类型断言替代渲染验证。
5. 在 SSR 测试范围内收集 Vue 告警及相关 `console.warn` / `console.error`，非预期诊断使测试失败；每个用例后恢复监听和应用配置，避免污染其他测试。
6. 错误用法的测试单独断言预期异常或告警及次数。框架或 Node 环境诊断按来源记录和处理，豁免必须限定具体条件与复查要求，禁止全局静默控制台。

验收时用局部故障注入验证失败通道：渲染夹具抛出普通错误、合法夹具产生非预期告警时，测试均应失败。故障注入只在验证期间使用，交付前恢复源码；保留有实际价值的断言辅助逻辑测试。

## 四、按行为与公共接口组织测试

### 1. TreeSelect 键盘导航

新增 `packages/ui/src/components/tree-select/tree-select-keyboard.test.ts`，复用既有挂载、语言和清理方式。挂载到真实 document 容器后触发 DOM 键盘事件，断言 `document.activeElement`、ARIA 状态、唯一的 `tabindex="0"` 和公开更新事件。

| 场景 | 行为断言 |
| --- | --- |
| ArrowDown / ArrowUp | 在可见可导航项之间移动，跳过禁用项与折叠子树，首尾边界保持稳定 |
| ArrowRight | 折叠父节点展开；已展开父节点进入首个可导航子节点；首子节点禁用或全部禁用时行为明确 |
| ArrowLeft | 已展开父节点折叠；子节点返回可导航父节点；根节点边界保持稳定 |
| Home / End | 跳到首个或最后一个可导航节点，焦点与 tabindex 一致 |
| Enter / Space | 按单选、多选契约验证叶子选择、取消选择、父节点展开以及公开更新事件 |
| 嵌套事件 | 深层节点的一次按键仅产生一次预期动作，祖先不得重复处理冒泡事件 |
| 禁用状态 | 不触发选择和展开；需要移出禁用节点的导航场景具有回归断言 |
| 浮层生命周期 | 打开后的初始焦点、关闭后的焦点返回符合组件公开交互契约 |

键盘导航与选择状态分别断言，不能用 tabindex 更新替代真实焦点移动。以 WAI-ARIA APG 为行为参考，结合 TreeSelect 自身契约确定单选、多选和父节点激活语义；字符搜索等能力需单独评估，不能以本次按键矩阵宣称完整符合 APG。

新增 `tree-select-keyboard.browser.test.ts`，复用现有 Vitest Browser / Playwright 配置，验证进入浮层、跨层移动、嵌套事件和关闭后焦点返回的代表性流程；完整边界矩阵放在快速组件测试中。

### 2. Upload 交互与命令式接口

复用 [upload.test.ts](../../../../packages/ui/src/components/upload/upload.test.ts) 和 [upload-trigger.test.ts](../../../../packages/ui/src/components/upload/upload-trigger.test.ts) 等既有测试。涉及维护的 PascalCase 测试文件按项目约定重命名为 kebab-case，并检查引用；不得同时保留两份重复测试。

按职责分层：

| 层次 | 验证目标 |
| --- | --- |
| UploadTrigger | 文件输入事件、拖拽状态、禁用与单选限制、键盘触发 |
| Upload 集成 | 用户选文件或拖放后，校验、列表更新、公开事件和上传回调的完整链路；点击删除和重试后的结果 |
| 公开方法 | 经 `defineExpose` 暴露的方法保留类型明确的契约测试，验证参数、异步完成与可观察结果 |
| 可独立业务逻辑 | 仅在职责清晰且可合理复用时提取函数，覆盖配额、并发、重试及取消等边界 |

具体要求：

- `input.files` 的替身与 Vue Test Utils 事件派发属于模拟 DOM 测试；选择后断言文件列表和公开事件，必要时等待实际异步操作完成。
- 在实际存在的 `role="button"` 触发器上派发 `dragenter` 激活高亮，`dragover` 验证阻止默认行为，`dragleave` 和 `drop` 验证高亮复位。高亮类在内层默认区域，应选取实际承载状态的元素；自定义 slot 的 `isDragging` 作为公开契约独立验证。
- 补齐拖动到内部子元素时保持高亮、离开区域时清除高亮、拖动过程中禁用或关闭 drag、空文件和多文件限制等边界。对拟定行为与实现不一致之处，先核对组件契约再修复。
- 删除与重试使用对应文件项的按钮；固定测试 locale，以 `upload.deleteFile`、`upload.retryUpload` 对应的可访问名称定位，禁止假设不存在的属性或固定英文文案。
- 保留并发、取消、重试上限及外部列表同步等已有断言。异步测试优先使用可控 Promise、回调和合适的计时器，不依赖任意休眠时间。
- 命令式接口通过明确类型访问，避免 `any`。测试私有实现与测试公开方法分别处理，不以出现 `wrapper.vm` 作为删除用例的依据。

### 3. SubMenu 悬停与嵌套交互

在现有 `menu.test.ts`、`menu-keyboard.test.ts` 基础上补充；独立的悬停生命周期矩阵可放入 `submenu.test.ts`。

覆盖进入与离开触发区、进入子菜单内容、延迟开关与快速往返、嵌套菜单展开和关闭、禁用行为，以及卸载后的定时器清理。先核对已有契约和用例，避免重复覆盖。

涉及延迟时使用假计时器，并依据源码中的实际延迟配置验证边界；每例恢复真实计时器并卸载组件。断言可见菜单、展开状态与焦点，不直接调用私有定时回调。真实指针路径或布局决定行为的代表性场景放入 `submenu.browser.test.ts`。

## 五、覆盖率采集与门禁设计

### 1. 统计口径

[vitest.config.ts](../../../../packages/ui/vitest.config.ts) 保持组件、Composable 与 lib 运行时源码的采集范围，并继续统计未被测试导入的匹配源码。

整体覆盖率按已覆盖的可执行项与总可执行项计算，不是各文件百分比的平均值。纯类型文件可执行项为零，不会稀释整体比例；清理报告展示与提升测试覆盖是两个独立目标。

- 保留 `.d.ts` 排除，并核验既有具体文件排除项的职责。
- 不使用 `src/**/*types.ts` 或 `src/**/index.ts` 统一推断文件没有运行时逻辑。`color-picker/types.ts` 的 `normalizePresets`、`menu-types.ts` 的注入键等应继续采集。
- 仅在核实为纯类型或生成式分发文件后，按明确范围排除；记录理由，并检查排除前后的文件清单与可执行计数。
- 测试文件与测试辅助代码不参与业务覆盖率。检查 Vitest 实际报告，确保 browser 测试文件等没有被 include 意外采集。
- 排除范围变化应与测试补齐带来的变化分别说明，运行时函数和分支不能因报表整理退出门禁。

### 2. 阈值校准与维护

完成行为测试后，在固定采集口径下运行 UI 完整覆盖率，确定最终阈值：

| 范围 | 校准规则 |
| --- | --- |
| UI 全局 | 行、函数、分支、语句分别以完成后的实际百分比向下取整为阈值；分别不低于 85%、85%、72%、85% |
| TreeSelectNode.vue、UploadTrigger.vue | 行覆盖率至少 90%；四维局部门禁按完成后的实际百分比向下取整设置 |
| SubMenu.vue | 完成行为矩阵后，四维局部门禁按实际百分比向下取整设置 |

上述全局下限是本期项目目标，不代表通用质量标准；向下取整提供不足一个百分点的数值余量。若目标未达到，应核对未覆盖分支、补齐有价值的测试或明确调整交付目标，不得通过隐藏运行时代码达标。

重点文件使用 Vitest 的具体文件或 glob 阈值；一个 glob 覆盖多个文件时显式设置 `perFile: true`。局部规则显式填写四个维度，不假设继承全局阈值。

阈值在配置中显式维护，提升后通过 PR 审查；CI 不自动改写仓库配置。新基线提高时同步上调阈值，降低阈值或调整排除范围必须说明契约、统计口径和影响。覆盖率达到目标仍需逐项通过行为矩阵。

## 六、PR 检查与合并保障

修改 [ci.yml](../../../../.github/workflows/ci.yml)，在面向 `main`、`vue` 的 PR 和现有分支推送上运行 UI 覆盖率。复用现有依赖安装、缓存和作业编排，保持检查名称稳定。

1. 覆盖率命令失败必须使所属检查失败，不使用忽略退出码或 `continue-on-error` 放行。
2. 保留 SSR 和浏览器检查，明确各自的执行条件及结果。浏览器关键流程通过不能代替覆盖率检查，反之亦然。
3. 保存完整覆盖率报告与运行摘要；检查路径过滤、作业条件和报告目录，确保必需检查不会意外跳过或使用局部报告。
4. 使用 `gh` 核对目标分支的保护规则或 ruleset，确认覆盖率所属检查为合并必需项。配置文件本身不等于合并保护已经生效；需要仓库管理权限的配置由维护者落实，并在验收记录中提供证据。
5. 通过隔离的失败验证确认低于阈值会产生非零退出码、CI 检查失败，并核实必需检查会阻断合并。故障注入不得进入最终交付代码。

若合并保护尚未落实，应明确记录为验收未完成，不将“PR 已运行覆盖率”视为“合并前门禁已生效”。

## 八、验证命令与完成标准

开发阶段针对改动目录运行测试，例如：

```bash
pnpm --filter brutx-ui-vue test src/components/tree-select
pnpm --filter brutx-ui-vue test src/components/upload
pnpm --filter brutx-ui-vue test src/components/menu
pnpm --filter brutx-ui-vue test:ssr
```

浏览器测试按新增的具体文件筛选运行 `pnpm --filter brutx-ui-vue test:browser <文件路径>`；最终 CI 执行现有完整浏览器任务。测试数据、异步控制与新增 helper 遵循 TypeScript 严格类型约定。

行为测试完成与门禁校准时运行 `pnpm --filter brutx-ui-vue test:coverage`，以完整 UI 测试集合验收阈值。对修改文件执行 ESLint；涉及类型接口时运行 UI 包 typecheck，涉及样式、令牌、导出或依赖时运行 `pnpm check:contracts`。文档更新运行 `pnpm check:docs`，避免在每个开发步骤重复全仓重型检查。

完成标准为：行为矩阵通过、SSR 失败判定可靠、采集范围正确、全局与局部门禁通过，以及合并保护生效。审查 PR 时同时列出关键用例、四维覆盖率、运行耗时与剩余风险，不以用例数量或单一行覆盖率替代验收。

所有实施任务完成后，遵循文档治理的收尾检查与归档流程：

```bash
pnpm doc:archive docs/plans/ui/单元测试质量提升与覆盖率治理方案.md
pnpm check:docs
pnpm check:contracts
```

修订方案文档不代表实施完成；实施验收前保持 `active` 状态。

## 十、实践依据

- [Vue 测试指南](https://vuejs.org/guide/scaling-up/testing.html)：以公开接口和可观察行为组织组件测试，按执行环境选择验证方式。
- [Vitest 覆盖率配置](https://vitest.dev/config/coverage)：明确采集范围，使用全局和 glob 阈值约束退化。
- [WAI-ARIA Tree View Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/)：区分焦点、选择与键盘导航，结合组件契约设计测试。
