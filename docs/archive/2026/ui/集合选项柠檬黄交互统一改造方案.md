# 集合选项柠檬黄交互统一改造方案

## 一、目标与设计依据

Classic 主题在明暗模式下使用柠檬黄 `#FFE600` 与黑色文字，以实心整行背景标识当前交互项；选项文字、图标和整行的位置、尺寸、字重保持稳定。选择标记表达所属组件的选值或勾选状态，描边表达可见键盘焦点。弹层外框继续使用粗边框与硬阴影，维持新粗野主义视觉风格。

[成熟 UI 库选择项交互调研](../../../reports/research/2026-10-31-成熟UI库选择项交互调研报告.md)表明，稳定行布局、区分高亮与选择、提供独立键盘焦点反馈，是可以跨组件复用的交互规则。[官方依据核验](../../../reports/research/2026-10-31-集合选项交互统一方案官方依据核验.md)明确了各控件的焦点、选择与提交策略边界。本方案统一视觉表达，由各组件映射自身状态并保留现有行为。柠檬黄是 Classic 的品牌选择；其他预设主题使用各自的成对语义颜色。

当前代码中的主要问题具有明确来源：

| 位置 | 当前实现 | 用户感知 |
| --- | --- | --- |
| Select 选项 | 行级悬浮抬升与按压位移 | 文字随整行突然移动 |
| Command / Combobox 选项 | 高亮时增加边框反馈、阴影、位移及字重 | 悬浮项像独立按钮，文字宽度和视觉重心变化 |
| 树形、级联与穿梭列表 | 各自组合背景、边框和阴影 | 同类交互缺少统一辨识方式 |
| DropdownMenu 选项 | 焦点填色与悬浮阴影并存 | 鼠标和键盘反馈规则不一致 |

## 二、改造范围

### 直接接入的组件

| 组件 | 统一部分 | 保留的业务语义 |
| --- | --- | --- |
| Select | 普通选项的高亮、焦点、稳定布局 | 单选、勾选标记、分组、显式颜色变体 |
| Command / Combobox | 搜索结果行与选项行反馈 | 命令执行；组合框单选、多选、创建、加载和搜索 |
| Cascader | 各列当前项反馈 | 导航路径、已选路径、父节点聚合三态、列导航 |
| TreeSelect | 树节点的高亮与焦点 | 展开、单选、多选、异步加载和缩进 |
| TreeView | 树节点的高亮与焦点 | 节点选择、展开、拖放和异步状态 |
| Transfer | 两侧列表行的交互反馈 | 勾选、半选、过滤、全选和左右转移 |
| DropdownMenu | 普通项、复选项、单选项和子菜单触发项反馈 | 动作执行、关闭策略、子菜单、危险动作语义 |

TimePicker、Pagination 页大小、DataTableColumnFilter、ColorModeSwitcher 等复用 Select 的入口随基础组件生效，并纳入集成验收。

Menu 导航保留当前路由的持续定位反馈；Tabs、Radio、Checkbox、日历日期格、颜色色块等继续使用各自的控件语义。统一对象是上述集合中的交互行。按钮、触发器及弹层外壳继续遵循现有视觉系统。

### 兼容边界

- 保留现有 props、事件、插槽、受控状态与 `v-model` 行为。
- 各组件的确认、展开、勾选、转移和动作执行沿用现有值提交时点，具体映射见下表。TreeSelect 的禁用导航补齐首末节点边界。
- 保留现有 `primary`、`secondary` 等显式颜色变体及其前景色配对；本方案统一默认变体及各变体的布局和焦点规则。
- 保留使用者通过 `class` 和 CSS 变量定制的能力。新增样式不得突破现有类名合并优先级。
- 搜索、输入法组合输入、过滤、加载、空状态、节点展开和拖放继续由各组件及现有原语管理。

## 三、统一视觉与状态规则

### 状态含义与组件映射

“当前项”表示所属导航域中由原语或本地导航逻辑维护的交互目标；“可见焦点”表示键盘操作所指向的位置；“选择标记”表示组件的选值、待操作勾选或聚合三态。业务值提交由所属组件管理，各组件的映射如下。

| 组件 | 当前项与焦点来源 | 选择标记来源 | 值提交与操作规则 |
| --- | --- | --- | --- |
| Select | 原语 `data-highlighted` 与真实 DOM 焦点 | `modelValue` 对应选项的勾选 | 方向键导航；确认选项时更新值 |
| Command | 原语当前项；输入框持有 DOM 焦点时使用 `aria-activedescendant` | 普通命令使用动作语义 | 确认当前命令时执行动作 |
| Combobox | 复用 Command 的当前项与虚拟焦点 | `modelValue` 对应的单选勾选或多选复选标记 | 确认选项或执行创建时，按现有单选、多选规则更新值 |
| Cascader | 导航路径 `activePath`、当前列交互项与真实焦点 | 已保存的选择路径；多选父节点根据后代叶子选值计算三态 | 展开路径、单选提交沿用现有规则；多选父节点操作增删后代叶子路径 |
| TreeSelect | 本地聚焦节点与真实 DOM 焦点 | 已选节点 ID 集合对应的勾选 | 展开与节点确认沿用现有单选、多选规则 |
| TreeView | 本地节点焦点与当前节点反馈 | `modelValue` 对应的节点勾选 | 保留现有选择事件；折叠分支按 ArrowRight、展开分支按 ArrowLeft 时，同时展开或收起并选择该节点 |
| Transfer | 左右面板各自的指针位置及 Checkbox 可见焦点 | 各面板待转移勾选；表头按可选项计算全选、半选 | `modelValue` 决定目标面板成员；行勾选更新面板选择状态，执行转移时更新 `modelValue` |
| DropdownMenu | 原语高亮与真实 DOM 焦点 | 复选项、单选项各自的选中状态 | 普通项执行动作；复选、单选项更新各自状态；保留关闭与子菜单策略 |

Cascader 的祖先路径、TreeView 的展开与拖放位置、DropdownMenu 的子菜单展开状态由组件分别表达。TreeSelect 的选择标记按当前已选节点集合映射。

### 状态矩阵

本表中的“已选或已勾选”使用上表定义的标记来源；Cascader 父节点及 Transfer 表头的半选继续使用各自三态标记。

| 状态 | 行背景与前景 | 持久标记 | 焦点反馈 |
| --- | --- | --- | --- |
| 普通 | 组件默认背景与文字 | 按组件标记来源显示 | 按实际可见焦点显示 |
| 鼠标当前项 | 主题高亮色对；Classic 为柠檬黄配黑字 | 按组件标记来源显示 | 真实焦点依据 `:focus-visible`；虚拟焦点依据 Command 输入模式 |
| 键盘当前项 | 同一高亮色对 | 按组件标记来源显示 | 显示独立的行内描边 |
| 已选或已勾选、当前项在别处 | 普通行背景 | 勾选、复选框或单选标记持续可见 | 按实际可见焦点显示 |
| 已选或已勾选且为当前项 | 同一高亮色对 | 选择标记持续可见 | 按实际可见焦点显示 |
| 按下 | 延续当前项颜色与标记 | 按组件标记来源显示 | 保留已有键盘焦点反馈 |
| 禁用 | 使用禁用令牌与现有禁用透明度 | 保留已有标记 | 导航遵循下述组件规则；可见焦点保持可辨识 |

普通命令和菜单动作使用当前项反馈；复选、单选或选值组件按各自状态显示标记。禁用项禁止触发激活、值提交及可操作高亮，禁用样式优先于交互填色；键盘导航按组件分别验收：

- Select、Command / Combobox、Cascader、TreeView 及 Transfer 沿用各自的禁用筛选与焦点规则。
- TreeSelect 的相邻导航及 Home/End 统一使用可导航节点集合，跳过禁用节点；全部可见节点禁用时保留输入框、触发器或其他现有有效焦点。
- DropdownMenu 保留 Reka 跳过禁用项的键盘导航契约，禁用项保持不可激活。

### 布局不变量

1. 普通、悬浮、键盘高亮、选中和按下状态使用相同的行尺寸、内边距、边框宽度与字重。
2. 行级反馈使用背景色、前景色及行内描边；行级 `translate`、抬升阴影与按压位移从这些组件的选项变体中移除。
3. 勾选、复选框、展开箭头、图标与快捷键区域固定占位。显示或隐藏标记不得挤动文字。
4. 保留各组件已有密度、尺寸和树形缩进；不强行统一不同业务组件的行高。
5. 颜色直接切换，避免 `transition-all` 意外作用于布局；展开箭头、加载指示等有意义的动效继续使用各自规则。
6. 高亮时文字、图标、快捷键和辅助说明使用成对前景色，避免继承灰色或透明度后失去对比度。

### 键盘焦点与输入模式

- 真实 DOM 焦点使用 `:focus-visible`；内部 Checkbox 获得焦点时，Transfer 适配层将可见焦点投射到所属行。
- Select、DropdownMenu 及其他持有真实 DOM 焦点的选项复用原语状态与 `:focus-visible`。
- Command 搜索框持有 DOM 焦点时，结果行使用原语当前项与 `aria-activedescendant` 显示虚拟焦点；输入框焦点与结果项选择分别表达。
- 在 Command 根接入私有输入模式适配，Combobox 随 Command 复用：导航键切换到键盘模式，实际指针移动切换到指针模式。模式只控制虚拟焦点描边，当前项的更新、离开与清理由原语管理。
- 模式跟踪继续复用原语的导航、滚动、提交和焦点恢复；输入文字、修饰键和输入法组合输入保留现有处理。初始模式依据打开集合的键盘或指针操作确定。
- 每个独立导航域内只呈现一个当前交互项；级联祖先路径、子菜单展开和多选标记分别表达。输入模式变化只影响呈现。
- 为集合行定义共享的行内焦点样式，复用视觉系统的焦点宽度与颜色令牌；普通状态使用焦点色，高亮状态使用对应前景色。绘制保持行几何稳定，焦点在滚动与弹层边界完整可见。
- 实施集合行焦点样式时，同步在 [视觉系统 R7](../../../guides/VISUAL_SYSTEM.md#r7-焦点指示体系-focus-ring) 定义其适用范围与静态检查规则。通用控件继续使用 `FOCUS_RING_CLASSES`，集合行使用统一的行内焦点样式。
- 强制颜色模式允许系统调色板接管背景与前景，使用系统色描边保留焦点，勾选、复选和单选形状保持可辨识；焦点绘制同时提供可见的 outline。

## 四、设计令牌与主题投影

在手写事实源 [design-tokens.ts](../../../../packages/shared/src/design-tokens.ts) 增加集合选项专用色对：

| TypeScript 字段 | CSS 变量 | Classic 明暗模式默认值 | 用途 |
| --- | --- | --- | --- |
| `itemHighlight` | `--brutal-item-highlight` | `#FFE600` | 当前交互项的实心背景 |
| `itemHighlightForeground` | `--brutal-item-highlight-foreground` | `#000000` | 高亮文字、图标与焦点描边 |

实施规则：

- 通过具名柠檬黄调色板常量、`ThemeTokens`、`BASE_THEME` 与 `TOKEN_TO_CSS_VAR` 建立唯一来源。组件使用语义类，颜色字面值集中在令牌层。
- 现有全局 `accent`、通用黄色与警告状态保持各自用途；本次令牌作用域限定在集合选项。
- Pastel、Mono、Warm 将新色对显式映射到各自现有强调色对，保持预设主题身份。复用具名色值来源，Mono 继续使用单色体系。
- 自定义主题通过新色对覆盖集合高亮。文档提供 CSS 变量覆盖与 TypeScript 主题配置示例，说明明暗模式默认值及完整 `ThemeTokens` 对象需要补齐的字段；已有仅覆盖 `accent` 的自定义主题通过新色对继续定制集合高亮。
- 向主题编辑器的 `ColorTokenKey`、颜色控件和 `contrastPairs` 增加新色对；在 `packages/shared/tests/design-tokens.test.ts` 与 `packages/ui/src/lib/theme-contrast.test.ts` 的显式色对清单中同步加入，并覆盖各预设明暗模式。色彩编译器自动将新映射投影为 Tailwind 语义颜色。
- 通过 `pnpm generate:tokens` 更新 UI 与 CLI 模板中的令牌产物。生成区块、颜色清单和预编译样式由生成器维护。

Classic 柠檬黄与黑色的文字对比度约为 **16.57:1**。实施验收仍需对实际生成 CSS、主题覆盖和辅助文字分别测量。

## 五、共享模块与组件适配

### 私有模块边界

新增私有模块 `packages/ui/src/lib/collection-item-variants.ts`，提供稳定行布局、高亮色对、行内焦点与禁用样式。由组件目录中的 `*-variants.ts` 引用，并继续通过 CVA 声明变体。

模块通过颜色变体及组件已归一化的 `data-highlighted`、`data-focus-visible`、`data-disabled` 属性表达呈现状态，输出可合并的静态类名。状态成立时使用空字符串，解除时移除属性；真实焦点同时由 `:focus-visible` 表达。完整静态类覆盖默认、显式颜色变体及必要的状态组合，便于 Tailwind 与注册表静态分析。选择标记、路径、半选与拖放状态由组件变体管理。

Command 输入模式放在其目录内的私有模块 `packages/ui/src/components/command/command-focus.ts`，由 Command 根接入事件并提供只读呈现状态，Combobox 复用该根。事件随组件生命周期注册与释放，状态由组件实例持有。

组件适配层负责把 Reka `data-highlighted`、可见焦点或本地当前项映射为呈现状态。共享模块依赖这些呈现状态，原语和组件分别维护导航与业务状态。选择值、节点路径、展开状态、动作执行和拖放逻辑继续由所属组件负责。共享样式及 Command 输入模式模块保持私有，按内部依赖闭包分发。

### 各组件实施落点

| 文件或模块 | 实施内容 |
| --- | --- |
| `select/select-variants.ts`、`SelectItem.vue` | 接入新默认色对与稳定行样式；以原语高亮和真实可见焦点映射呈现；保留固定勾选槽和显式变体 |
| `command/command-variants.ts`、`CommandItem.vue` | 使用统一高亮，固定字重；对接原语当前项及虚拟焦点，协调禁用状态 |
| `command/Command.vue`、`CommandInput.vue`、`command-focus.ts` | Command 根级输入模式适配；保留原语虚拟焦点；搜索区使用普通背景与配对前景，保留独立输入焦点 |
| `combobox/Combobox.vue` | 保留普通触发器反馈；核验单选勾选与多选复选框的固定占位、加载及创建行 |
| `cascader/cascader-variants.ts`、`Cascader.vue` | 分别映射当前项、导航路径、已选路径与父节点聚合三态；祖先路径使用稳定标记或箭头 |
| `lib/tree-variants.ts`、`tree-select/*` | 拆分节点选择标记与当前项；保留缩进和异步反馈；相邻导航与 Home/End 共用可导航节点筛选，覆盖首末禁用及全部禁用边界 |
| `tree-view/tree-view-variants.ts`、`TreeViewNode.vue` | 接入统一节点反馈；单选节点增加固定勾选槽；保留方向键展开、收起及选择事件；分别适配拖放前、后与内部目标反馈 |
| `transfer/Transfer.vue` | 将行状态类移入所属变体文件并接入共享模块；Checkbox 表达待转移勾选，表头表达全选/半选；目标面板成员继续由 `modelValue` 决定 |
| `dropdown-menu/dropdown-menu-variants.ts` 及各项组件 | 普通项与子菜单项接入统一反馈；复选、单选项保留指示器；危险动作通过显式 `data-tone="danger"` 使用危险色对 |

危险动作沿用现有属性透传能力，以显式标记指定语义，并同步相应示例；共享样式不通过文本或使用者类名猜测动作类型。默认插槽内容继续可定制。

组件类名使用 `computed(() => cn(...))` 合并；新增文本通过国际化机制提供；固定尺寸优先复用现有令牌。树形节点只调整行反馈，保持展开图标、拖放指示与加载状态的独立表现。

## 七、实施顺序与交付检查点

1. **建立公共规则**：补齐新色对、主题映射与私有行样式；同步视觉系统 R7 的集合行焦点规则及对应静态检查。按组件状态表记录现有值提交行为，验证高亮、标记、焦点和禁用的组合。
2. **落地基础选项**：接入 Select、Command、Combobox；仅在 Command 根接入虚拟焦点所需输入模式；完成文字位置稳定、搜索、多选和组合输入的浏览器验收。
3. **落地复合集合**：接入 Cascader、TreeSelect、TreeView、Transfer、DropdownMenu；验证各自路径、聚合三态、临时勾选、值提交、拖放和菜单关闭行为，补齐 TreeSelect 首末禁用导航。
4. **验证消费链**：生成令牌、注册表与候选包，运行 U1、C1 消费验证，覆盖新私有依赖及高亮样式；完成主题编辑器、新色对测试和中英文示例同步。
5. **完成交付**：执行相关测试与静态契约门禁，审查本次文件范围，归档方案；按模块提交，仅包含本次相关变更。

每个检查点通过后进入下一步。实施前核对工作区已有修改，按文件及变更块确认归属，保留其他并行修改。

## 八、验证与验收标准

### 浏览器行为验收

在 UI 包测试目录增加集合交互浏览器用例，使用 UI 包内部真实组件夹具和生成后的样式；按行为验证，避免以类名快照代替交互证据。

| 验收维度 | 通过条件 |
| --- | --- |
| 布局稳定 | 悬浮、移出、按下、抬起和键盘切换前后，行与文字的边界、位置、尺寸和字重一致 |
| 当前项与选择 | 按组件状态表分别断言活动项、ARIA 状态、选择标记与业务值；切换当前项时保留已有标记；TreeView 指定方向键的选择事件及 Transfer 转移前后的值符合既有契约 |
| 输入模式 | Select、DropdownMenu 的真实焦点、Command 的虚拟焦点及 Transfer 内部 Checkbox 可见焦点均可辨识；每个导航域只呈现一个当前项；Command 的模式切换仅影响描边 |
| 禁用 | 禁用项禁止激活、提交及可操作高亮；各组件按采用的原语导航规则验收；TreeSelect 相邻导航及 Home/End 跳过禁用项，覆盖首末及全部禁用边界 |
| 复合交互 | 搜索、组合输入、创建、异步加载、Cascader 路径及聚合三态、Transfer 勾选及表头三态、级联列导航、树拖放、菜单子项与关闭策略通过相关测试 |
| 主题与对比度 | Classic 明暗模式为柠檬黄配黑字；其他预设及自定义色对生效；按项目 AA 目标验证普通文字至少 4.5:1，必要的焦点和状态指示与相邻颜色至少 3:1 |
| 展示边界 | 长文本、窄屏、滚动容器、嵌套弹层及减少动态效果模式下，内容与焦点完整可见；强制颜色模式下，系统色焦点边界与选择标记均可辨识 |
| 消费端 | TimePicker、Pagination、DataTableColumnFilter、ColorModeSwitcher 反馈一致；U1 的 npm 包和 C1 的 CLI 安装、更新产物包含私有依赖与所需样式，并通过类型检查及构建 |

沿用 Select、Combobox、Command、Cascader、TreeSelect、TreeView、Transfer、DropdownMenu 的相关单元和键盘测试；新增断言集中在组件状态映射、选择标记、值提交时点与几何稳定性等行为边界。消费夹具覆盖本次变更的基础选项和复合集合，确保新增私有模块进入实际交付依赖闭包。

### 按领域执行的检查

- 共享包：将新色对加入 `design-tokens.test.ts` 后运行该测试及 `token-style-compiler.test.ts`；UI 包将新色对加入 `theme-contrast.test.ts` 后运行该测试与受影响组件测试；主题编辑器覆盖颜色控件及对比度显示。
- 浏览器：运行新增集合交互用例，以及 Select、Combobox、树形组件和叠层的相关浏览器用例。
- 类型与风格：对受影响包执行定向 `typecheck`，对修改源码执行 ESLint。
- 生成与分发：执行 `pnpm generate:tokens`、`pnpm --filter brutx-ui-vue generate`、`pnpm --filter brutx-registry-vue build` 与 `pnpm --filter brutx-registry-vue validate`。
- 消费端：按现有候选包流程准备本次产物，使用 `pnpm test:consumers --filter U1 --artifacts <候选产物目录>` 与 `pnpm test:consumers --filter C1 --artifacts <候选产物目录>` 分别验证 npm 包和 CLI 交付；C1 完整执行 `init`、`add`、`update`、类型检查及 Vite 构建。
- 契约与文档：执行 `pnpm check:generated`、`pnpm check:api-dependencies`、`pnpm check:contracts`、`pnpm check:docs` 与 `git diff --check`。

方案完成的判据是：覆盖范围内的默认选项行形成统一的主题高亮反馈，Classic 使用柠檬黄配黑字，各预设保持自身配色；字体与位置稳定，组件选择标记与键盘焦点可区分，值提交行为符合组件状态表，集合行焦点规范与实现一致，npm 与 CLI 消费链均通过实际产物验证。
