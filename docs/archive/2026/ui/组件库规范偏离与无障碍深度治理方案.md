# 组件库规范偏离与无障碍深度治理方案

---

## 一、 背景与第一性原理

在完成组件模板样式计算收敛后，组件库在渲染层已实现无抖动和计算纯粹化。然而，经由全局深层专项审计，在可访问性（A11y）、Composable 状态封装、DOM 结构合法性、国际化规范（i18n）以及设计令牌单一源方面，仍存在若干违背组件库核心原则与现代 Web 标准的技术债务。

从第一性原理出发分析各领域的本质问题：

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        组件库深层规范偏离全景矩阵                      │
├────────────────────────────────────────────────────────────────────────┤
│ 1. 结构与可访问性阻断 (A11y & DOM Validity):                           │
│    ├─ Input.vue 缺失 id 声明与属性透传: 根容器捕获 id，Label 无法聚焦    │
│    ├─ ColorPicker.vue 交互元素非法嵌套: <button> 嵌套可交互清空 <span> │
│    ├─ Image.vue 预览浮层缺 role="dialog" / aria-modal 与操作 accessible name│
│    └─ 纯图标控件 Accessible Name 缺失: 屏幕阅读器无法理解操作意图        │
│                                                                        │
│ 2. 状态机边界泄漏 (Composable Readonly Violation):                    │
│    ├─ useTheme / useDataTablePagination / useDialogGeometry 导出可变   │
│    │  Ref，调用方直接赋值破坏响应式管道与副作用管理                   │
│    └─ useUpload.ts 存在同名自等比较 (item.lastModified 恒真比较)       │
│                                                                        │
│ 3. 国际化与文案契约 (i18n & Default Values):                           │
│    ├─ defineProps 中硬编码中英文字符串默认值，跳过 useLocale().t() 动态链│
│    └─ 复合组件内部模板硬编码操作文案                                   │
│                                                                        │
│ 4. 令牌单一源与层级语义 (Tokens & Z-Index Escalation):                 │
│    ├─ 散落非 Brutal 原始色 (text-white / bg-black 等)                  │
│    ├─ 出现 z-[999]、z-40、z-10 等非语义硬编码，Backtop 缺失专属令牌    │
│    └─ 动效与时间常量包含魔法数字                                       │
└────────────────────────────────────────────────────────────────────────┘
```

本方案针对上述领域，确立明确的代码契约与自愈标准，彻底消除技术债务。

## 二、 核心治理架构与设计决策

### 专题一：交互原语合法性与 DOM 结构解构

#### 1.1 Input 组件属性透传与 Label 关联架构
- **本质问题**：`Input.vue` 根节点为包装容器 `<div class="w-full">`，且组件未在 `props` 中显式声明 `id`。外部通过 `:id="id"` 传入时，Vue 3 的属性透传（Fallthrough Attributes）机制会将 `id` 绑定至根 `div` 容器上，原生 `<input>` 无法获取该标识，导致 `<Label :for="id">` 点击聚焦失效，屏幕阅读器也无法将标签与表单控件正确关联。
- **最佳实践规范**：
  - 在 `Input.vue` 中显式声明 `id?: string` prop；
  - 内部基于 `computedId = computed(() => props.id ?? generatedId)` 进行标识解析，若外部未显式传入则通过安全的 ID 生成机制（如 `useId()`）派生内部唯一标识；
  - 将 `computedId` 显式绑定至原生 `<input :id="computedId">`；
  - 在 `variant === 'error'` 且存在 `errorMessage` 时，原生 `<input>` 显式通过 `:aria-describedby="errorTextId"` 与错误文本容器（标记 `role="alert"`）建立语义关联。

#### 1.2 ColorPicker 按钮非法嵌套与平级解构
- **本质问题**：HTML Living Standard §4.10.6 明确规定：`<button>` 元素严禁包含交互式内容（Interactive Content）。`ColorPicker.vue` 原结构中，Trigger 是由 `<PopoverTrigger as-child>` 包装的原生 `<button>`，内部嵌套了一个绑定 `@click.stop` 且附带 `role="button"` 的清空 `<span>`。该结构违背 HTML 与 ARIA 标准，造成辅助技术解析混乱与按键事件冒泡歧义。
- **最佳实践规范**：
  - 拒绝使用 `<div>` 模拟 Button（避免承担繁重的键盘可访问性代理包袱）；
  - 采用**平级绝对定位解构架构（Sibling Positioning Architecture）**，与库内成熟的 `DatePicker.vue` 对齐：
    - 外层使用 `div.relative` 容器包裹；
    - Trigger 维持为标准的原生 `<button>`（通过 `<PopoverTrigger as-child>`），负责承载主触发行为与焦点状态；
    - 清空按钮提取为平级的独立绝对定位 `<button>`，通过 `@pointerdown.stop` / `@click.stop` 阻止触发下拉；
    - Trigger 内部仅放置透明占位符（占据空间保持布局稳定，不响应指针事件）。

#### 1.3 Image 预览浮层模态语义与可访问性补齐
- **本质问题**：`Image.vue` 虽然已具备 `FocusScope trapped loop` 和基础键盘监听（`Esc` 退出、方向键切图），但预览浮层容器缺少标准模态语义，工具栏按钮采用原生标签且仅使用 `title` 提示，缺乏屏幕阅读器识别的 Accessible Name。
- **最佳实践规范**：
  - 预览浮层遮罩容器补充 `role="dialog"`、`aria-modal="true"` 以及 `:aria-label="t('image.preview', '图片预览')"`；
  - 预览工具栏的操作按钮（放大、缩小、向左旋转、向右旋转、左右翻转、关闭）全面替换为库内统一的 `<Button>` 组件，消除内联按压手写样式；
  - 工具栏按钮移除裸 `title` 属性，强制绑定 `:aria-label="t(...)"`，接入多语言翻译；
  - **保留装饰性图片语义**：`Image.vue` 的 `alt` prop 默认值**严格维持 `''`（空字符串）**，遵循 WCAG 2.1 规范标记为装饰性图片，严禁将默认值设为 `undefined` 导致 DOM 丢失 `alt` 属性引发 A11y 违规。

### 专题二：全域交互无障碍（A11y）合规化

#### 2.1 纯图标控件 Accessible Name 强制补齐
所有仅包含 Lucide 图标、无直观可视文本的交互按钮必须具备屏幕阅读器可识别的 Accessible Name：
- **`ColorModeSwitcher.vue`**：
  - 绑定当前动态状态的可访问名称：`:aria-label="t('colorModeSwitcher.currentToggle', { mode: currentLabel })"`。
- **`NumberInput.vue`**：
  - 步进器增加按钮绑定 `:aria-label="t('numberInput.increase', '增加数值')"`；
  - 步进器减少按钮绑定 `:aria-label="t('numberInput.decrease', '减少数值')"`。
- **`Cascader.vue`**：
  - 清空按钮补充 `:aria-label="t('common.clear', '清空')"`。
- **`SelectTrigger.vue`**：
  - 保持内部图标 `tabindex="-1" aria-hidden="true"` 的装饰性隔离，避免在原生 Trigger `<button>` 内部构成非法嵌套；清空能力通过 Trigger 自身键盘监听（`Backspace`/`Delete`）保障。

#### 2.2 状态驱动的 ARIA 动态属性与角色绑定
- **校验状态联动**：
  - `DatePicker.vue`、`DatePickerRange.vue`、`DateTimePicker.vue`、`MonthPicker.vue`、`WeekPicker.vue`、`YearPicker.vue` 以及 `ColorPicker.vue` 的触发器在错误时绑定 `:aria-invalid="variant === 'error' || undefined"`。
- **阻断确认对话框角色**：
  - `Popconfirm.vue` 浮层容器声明 `role="alertdialog"`；
  - 同时显式绑定 `:aria-labelledby="titleId"`（关联操作确认标题）与 `:aria-describedby="descId"`（关联确认提示正文），达成 WAI-ARIA 1.2 严格合规。

### 专题三：Composable 状态只读化与生命周期防御

#### 3.1 状态只读边界强制闭环（Readonly Boundary）
依据项目红线与单向数据流原则，Composable 内部状态可变，但向调用方暴露的响应式引用必须使用 `readonly()` 保护，杜绝外部绕过状态机直接改写：

| 模块 | 导出项 | 规范只读签名 | 驱动修改机制 |
| :--- | :--- | :--- | :--- |
| `useTheme.ts` | `theme`, `colorMode` | `Readonly<Ref<ThemeName>>`, `Readonly<Ref<ColorMode>>` | 必须通过 `setTheme()` / `applyColorMode()` / `toggleColorMode()` 触发 DOM 与存储联动 |
| `useDataTablePagination.ts` | `currentPage`, `currentPageSize` | `Readonly<Ref<number>>`, `Readonly<Ref<number>>` | 必须通过 `goToPage(n)` / `setPageSize(n)` 触发边界校验与切片计算 |
| `useDialogGeometry.ts` | `isDragging`, `isResizing` | `Readonly<Ref<boolean>>`, `Readonly<Ref<boolean>>` | 仅内部拖拽与缩放事件处理函数拥有写入权限 |
| `useColorPicker.ts` | `displayValue` | `Readonly<Ref<string \| null>>` | 面板值同步统一通过 `handlePanelUpdate()` 驱动 |
| `useDatePicker.ts` | `displayValue` | `Readonly<Ref<Date \| null>>` | 面板值同步统一通过 `handlePanelUpdate()` 驱动 |

#### 3.2 逻辑缺陷修复与单例资源回收
- **`useUpload.ts` 自等比较逻辑修复**：
  - 纠正第 78 行的比对缺陷，修正为：
    ```typescript
    return !selectedFiles.value.some(
        (item) => item.name === file.name
            && item.size === file.size
            && item.lastModified === file.lastModified,
    )
    ```
- **`destroyFallbacks.ts` 音频单例销毁管线接入**：
  - 在 `destroyBrutxUI()` 清理列表中引入 `resetSharedAudioRuntime`（来自 `shared-audio-runtime.ts`），在测试隔离与应用注销时彻底关闭 Web Audio `AudioContext` 并重置单例。
- **Observer 资源安全解绑**：
  - 严格审查 `ResizeObserver` 与 `IntersectionObserver` 的注册点，统一在 `onScopeDispose` 中执行 `disconnect()`，防范在动态 Effect Scope 或微前端沙箱中的实例泄漏。

### 专题四：国际化（i18n）规范统一化

#### 4.1 Props 默认值解耦规范
- **红线契约**：在 `defineProps` / `withDefaults` 中，一切涉及界面可读文本的 prop（如 `placeholder`、`title` 等）默认值**一律设为 `undefined`**。
- **统一响应式解析链**：
  ```typescript
  const props = withDefaults(defineProps<{
      placeholder?: string
  }>(), {
      placeholder: undefined,
  })

  const { t } = useLocale()
  const resolvedPlaceholder = computed(() => {
      return props.placeholder ?? t('select.placeholder', '请选择')
  })
  ```
- **重点修复清单**：
  - `Select.vue`：移除 `placeholder = 'Select an option'` 硬编码默认值；
  - `UploadFileItem.vue`：重试上传、删除文件等操作文案收敛至 `t()` 动态链；
  - `Backtop.vue`：`aria-label="Back to top"` 收敛至 `t('backtop.backToTop', '回到顶部')`。

---

### 专题五：设计令牌单一源与层级收敛

#### 5.1 Z-Index 语义阶梯闭环对齐
严禁在 UI 组件库中随意使用未定义的类名。必须遵循设计令牌单一数据源（SSOT）工作流：
1. **源头增补**：在 `packages/shared/src/design-tokens.ts` 中正式引入 `floating: 50` 语义令牌，更新 `Z_INDEX_TOKENS` 与 `Z_INDEX_CLASS_ENTRIES`；
2. **代码生成**：运行 `pnpm generate:tokens`，将 `--z-index-floating: 50;` 自动编译同步到各子包样式表与 `twMerge` 白名单；
3. **组件类名替换**：
   - `Backtop.vue`：移除硬编码 `z-[999]`，替换为新生成的语义类 `z-floating`；
   - `HeaderSection.vue`：移除硬编码 `z-40`，替换为既有语义类 `z-header`；
   - `DataTable.vue`：移除硬编码 `z-10`，替换为既有语义类 `z-sticky`。

#### 5.2 色彩令牌与魔法数字常量化
- 移除散落的裸写色彩（如 `text-white`、`bg-black`），收敛至 `text-brutal-white`、`bg-brutal-black` 或对应语义色；
- 将组件内部裸写的节流延时、动效缓冲时间及尺寸极值抽离至 `packages/shared/src/tokens/constants.ts`。

---

### 专题六：高层复合组件原生元素收敛

全面复用库内基础组件与交互变体，保持视觉质感与按压反馈一致：
- `ColorPicker.vue`：清空按钮解构后采用 `<Button variant="ghost" size="sm">`；
- `Image.vue`：预览工具栏按钮采用统一的 `<Button>` 包装，原生集成焦点环与硬边框反馈。

## 四、 验证契约与质量门禁

每个批次完成后必须严格执行以下四道验证闸门：
1. **类型严苛性**：`pnpm --filter brutx-ui-vue typecheck` 严格零报错；
2. **定向单元测试**：针对所修改组件与 Composable 运行专项测试集；
3. **静态契约门禁**：运行 `pnpm check:contracts`，确保导出表、令牌与全局 manifest 无偏移；
4. **文档与规范门禁**：运行 `pnpm check:docs`，确保全库链接健康、Frontmatter 合规。
