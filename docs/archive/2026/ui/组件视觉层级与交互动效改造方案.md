# 组件视觉层级与交互动效改造方案

## 一、目标与依据

本方案对照本地 `neobrutalism-components` 项目的组件源码与示例，提升 BrutxUI 的导航连续性与内容层级。保留粗边框、硬阴影、主题色与机械反馈，通过明确装饰职责提升组合后的整体效果。图表读数反馈由[图表数据契约与读数交互方案](../../../plans/ui/图表数据契约与读数交互方案.md)独立管理。

分析基线为 2026-09-21 的本地源码。已确认的是样式声明、渲染结构和交互实现；流畅度、触摸手感、实际主题对比度与视觉偏好尚需浏览器验证。本方案中的目标行为是拟实施设计，不代表当前能力。

### 基线与机会

| 领域 | 参考项目的实现 | BrutxUI 当前实现 | 改造目标 |
| --- | --- | --- | --- |
| 横向导航 | `src/components/ui/navigation-menu.tsx` 按前后项方向切换内容，并提供共享视口 | `SubMenu.vue` 横向浮层条件渲染，竖向分支具备高度过渡 | 补齐开合连续性，独立验证网站导航的共享视口需求 |
| Tabs | `src/components/ui/tabs.tsx` 的内容区只承担布局；激活项以底色和边框强调 | 列表、激活项与内容区均有实体装饰 | 明确内容外壳归属，降低嵌套时的视觉竞争 |
| Accordion | `src/components/ui/accordion.tsx` 使用彩色标题栏、中性正文与简单箭头 | 默认项、标题触发器和图标具有多层立体反馈 | 建立标题色块与正文阅读区的清晰分工 |

## 二、范围与实施原则

本方案分为可独立交付的组件工作包，按菜单、Tabs、Accordion 的顺序推进。图表方案先完成数据契约验收，再实施交互，独立交付和归档。网站导航共享视口与移动端 Drawer 在完成场景验证后另立功能设计。

1. 一个组合区域由明确的一层承担主要边框和阴影，激活态优先通过颜色、边框与位置关系表达。
2. 动效解释打开、关闭、切换和读数状态；位移幅度与组件尺度匹配。所有动效类名同步声明 `motion-reduce:transition-none` 或 `motion-reduce:animate-none` 防御。
3. 容器承担布局语义时默认内边距清零，交由内嵌独立卡片/表单容器维护，消除内外嵌套留白累加。
4. 优先扩展现有组件、变体与内部工具；公共状态、键盘语义和主题能力保持一致。
5. 颜色、边框、圆角、层级、时长和缓动优先复用现有令牌。确需新增时，在手写单一数据源中声明语义与默认值，通过生成器同步。
6. 组件私有动画参数使用命名常量或 CSS 变量，说明其用途；禁止散落硬编码和动态拼接 Tailwind 类名。
7. 视觉默认值调整按项目 0.x 策略直接落实目标行为，同步示例、测试及迁移说明。

Button、Switch、Slider、ImageCard 的现有机械反馈保持各自职责。Dialog、Sheet、Popover 等通用浮层已具备相近基础动效，本轮重点集中在上述工作包。

外壳职责清楚、状态反馈可理解、键盘可达与减少动态效果属于验收原则；`plain` 默认值、标题色块和阴影强度属于产品设计选择。基线阶段须统计 Tabs 消费点，并在独立正文、嵌套 Card、密集 Accordion 页面中对比目标样式。记录阅读层级、重复外壳、焦点可见性和主题对比度，确认目标默认值后再进入样式实施。

## 三、横向菜单：开合连续性

### 目标行为

横向子菜单沿浮层实际出现方向做短距离进入，配合透明度变化；关闭时完成退出过渡后卸载。触发器箭头与展开状态同步。快速往返悬停时以最新状态为准，避免旧过渡结束后误关新面板。

### 实现边界

- 保留现有 `Menu` / `SubMenu` 的动作菜单职责、索引、焦点管理和键盘契约。
- 鉴于 `SubMenu.vue` 当前采用轻量模板与状态机实现，横向浮层使用 Vue 原生 `<Transition name="menu-pop">` 调度生命周期，定义专用进入/离开过渡类名（fade + 短位移缩放），确保关闭过渡在视觉完成前 DOM 保持挂载，过渡完成后由 Vue 统一卸载，避免条件渲染即时销毁导致的退场动效丢失。
- 架构契约与 Reka UI Menubar / NavigationMenu 保持语义对齐，为后续无头原语演化保持平滑升级路径。
- 样式收敛到菜单所属变体模块；过渡仅作用于浮层面板，避免影响触发器定位和命中范围。
- 延迟关闭计时结束或明确关闭操作生效时，立即更新逻辑状态；离场 DOM 仅用于视觉过渡。按关闭原因先处理仍在面板内的焦点，再使离场内容退出键盘导航、辅助技术可访问树与指针交互，避免焦点滞留在隐藏内容中。
- Esc 关闭后焦点返回触发器；外部点击关闭尊重实际点击目标；切换到其他菜单时避免焦点被旧面板抢回。
- 尊重减少动态效果偏好，显式声明 `motion-reduce:transition-none`，焦点逻辑与完整动效模式一致。
- 悬停触发的面板允许指针移入并持续操作；Esc 在焦点位于触发器或面板内时关闭相应菜单，纯悬停打开时也提供关闭处理。关闭后在新的进入或显式打开操作前保持关闭。

### 网站导航的方向性切换

参考项目的 NavigationMenu 属于网站链接导航，其共享视口与本库动作菜单语义不同。后续若有产品需求，优先核验已安装 Reka UI 的导航原语能力，再明确导航项顺序、共享视口尺寸、进入退出方向和链接语义，形成独立方案。

本轮菜单工作包以横向开合过渡为验收对象；跨项共享视口不纳入本轮完成条件。

### 验收

- 鼠标从触发器移动到面板时，现有延迟关闭机制仍有效。
- 连续打开、关闭、重新打开时，退场过渡完整执行且最终可见面板与状态一致。
- 键盘进入子项、Esc 返回、点击外部、禁用项和嵌套菜单行为通过回归。
- 面板过渡期间无位置跳变、阴影裁切或退出内容拦截点击。
- 竖向折叠行为通过已有回归测试。

## 四、Tabs：内容外壳与选中态分工

### 目标设计

- `TabsList` 承担分组边框与布局，默认弱化阴影强调。
- `TabsTrigger` 通过主题底色、前景色和实体边框表达选中状态；默认激活项保持位置稳定，避免悬浮时反复抬升。
- 默认 Trigger 的 hover 和 active 使用成对背景与前景色反馈，位置及阴影保持稳定；选中状态由 `data-state` 表达，瞬态按压不覆盖选中态边框。`slots` 的选中位移独立定义，hover 与 active 保持该位置。显式加入 `motion-reduce:transition-none`。
- `TabsContent` 增加拟议的 `surface: 'plain' | 'panel'` 属性，默认 `plain`：
  - `plain`（默认）：声明 `mt-3 p-0 focus-visible:outline-hidden`。去除独立外壳与内边距，使内嵌 `Card`、表单容器时实现零缝隙贴合，根治嵌套留白冗余。
  - `panel`：声明 `mt-3 p-6 bg-brutal-bg text-brutal-fg border-3 border-brutal shadow-brutal rounded-brutal`，为独立正文提供完整新粗野物理外壳与标准内边距。
- `Tabs.vue` 模板内置的 `tabs` prop 快捷渲染模式与 `surface: 'plain'` 默认行为协同，内嵌 `Card` 承担主要视觉外壳。
- `slots` 变体保留插片语义，在变体组合中明确其位置和边框规则，避免被默认态反馈覆盖。

### 落地与迁移

修改 `tabs-variants.ts` 和 `TabsContent.vue` 的类型与类名派生。新属性只作用于内容表面；既有颜色、尺寸与方向属性继续承担原职责。

逐一检查内部 Tabs 消费点：内容嵌套 Card 的场景使用 `plain`；直接依赖内容区外壳的场景显式使用 `panel`。同步中英文文档中的默认值与升级示例。

### 验收

- `TabsContent → Card` 组合由 Card 承担主要外壳，嵌套无冗余间距，边框贴合。
- `panel` 独立承载文字或表单时具有完整表面与充足内边距。
- 横向溢出、纵向布局、长文本、禁用项与焦点环保持可用。
- 激活状态在亮暗主题中清楚可辨，边框预留避免选中时尺寸跳动。
- 验证属性默认值和内容组合行为；沿用现有键盘测试核验切换契约。

## 五、Accordion：标题与正文分层

### 目标设计

默认 Accordion 遵循状态化色彩节奏与结构解耦。整体边框与硬阴影由 Item 承担，标题以色彩变化提示交互，箭头采用简单旋转表达展开状态。

- **收起态（closed）**：默认 Trigger 采用 `bg-brutal-bg` 中性底色，保持列表整洁宁静；hover 时以 `bg-brutal-muted` 与对应前景色微交互，避免列表常态铺满高饱和彩色条带引发视觉疲劳。
- **展开态（open）**：Trigger 通过 `data-[state=open]` 激活主题强调色（`bg-brutal-primary` 或对应语义色）与底部粗分隔线（`data-[state=open]:border-b-3`），形成鲜明的阅读聚焦。
- **正文区（content）**：采用中性次级背景（`bg-brutal-muted`），与高亮标题形成清晰的主次明暗反差。
- **高度过渡与边框解耦**：顶部分隔线收敛至 Trigger 展开态底部边框（`data-[state=open]:border-b-3`）；外层 `AccordionContent` 仅负责基于 `--reka-accordion-content-height` 的几何高度裁切（`overflow-hidden`），内层容器负责 `p-6` 内边距与排版，避免 0 高度时 3px 边框产生瞬时跳动。
- 默认 Item 开合保持位置稳定。
- 图标尺寸和旋转保持一致，默认图标去除独立的实体外壳。
- `interactive` 继续承担整项悬浮反馈；`flat`、`ghost` 各自保留表面强度，逐项定义标题配色。
- 多行标题、较长正文和多个同时展开的项目保持对齐与阅读节奏。

### 状态反馈契约

| 状态 | 默认、flat、ghost | interactive |
| --- | --- | --- |
| hover | Trigger 使用成对背景与前景色反馈，Item 与 Trigger 位置稳定 | Item 复用整项悬浮反馈，Trigger 只变色 |
| active | Trigger 以颜色表达按下，位置与阴影稳定 | Trigger 只变色，Item 保持当前悬浮位置 |
| closed | Trigger 保持中性背景，分隔线隐藏 | Trigger 保持中性背景，Item 保持稳定 |
| open | Trigger 激活强调背景与底部边框，正文使用中性次级背景 | Trigger 激活强调背景与底部边框，正文使用次级背景 |
| focus-visible | Trigger 使用统一焦点环 | Trigger 使用统一焦点环 |

Trigger 采用颜色反馈时不挂载 `brutalPress`；颜色切换同时定义背景与对应前景，校验各主题的 hover、active 和展开组合。减少动态效果模式下显式声明 `motion-reduce:transition-none motion-reduce:animate-none`，高度和箭头旋转即时切换，整项悬浮保持位置稳定，以颜色保留反馈。

实施 Tabs 与 Accordion 样式时，在同一交付中更新 [视觉系统指南](../../../guides/VISUAL_SYSTEM.md) R4/R5：明确分段选择控件和外壳由 Item 承担的 Accordion Trigger 使用稳定位置的颜色反馈，保留其他组件的机械反馈规则。现行规范与组件实现同时生效。

### 验收

标题、图标与正文层级在展开前后清楚；开合没有父子重复位移；展开态色彩聚焦与收起态中性整洁；高度动画完整结束且无正文闪现与边框跳动。以单项、多项、多行标题、交互变体和减少动态效果偏好覆盖验收。

## 七、Drawer 后续验证

移动端 Drawer 作为独立验证课题，验证内容包括拖拽跟手、松手关闭阈值、内容滚动与拖拽的边界、背景缩放、焦点恢复和减少动态效果模式。

参考项目启用 Vaul 及其背景缩放选项只能证明接入意图，实际效果受页面结构与依赖行为影响。开展此项时，需要在真实移动端尺寸与触摸输入下验证，再决定复用现有 Sheet、增加模式或建立独立组件。当前文档的核心改造完成不依赖此项。
