# 命令式宿主控制器与弹层调度栈重构方案

---

## 一、 背景与第一性原理

### 1. 现状痛点分析

在 BrutxUI Vue 3 当前的底层基础设施中，命令式 UI 弹层与通知挂载链路存在接口分裂、契约不对称以及上下文透传缺失等架构缺陷：

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│                          当前命令式弹层体系架构现状                         │
├─────────────────────────────────────────────────────────────────────────────┤
│ 1. packages/ui/src/lib/render-imperative.ts (接口分裂与能力残缺)            │
│    ├─ mountOverlay: 暴露完整 OverlayInstanceHandle（含 promise/close）      │
│    ├─ renderImperative: 丢弃 promise 与受控关闭，仅返回 { destroy }         │
│    └─ 缺少全局一键清理逃生通道与组件树 AppContext 自动化透传                │
│                                                                             │
│ 2. packages/ui/src/components/dialog/functional.ts & useDialog.ts           │
│    ├─ ShowDialogOptions 声明了 onConfirm 回调，但实现中完全未接通（幽灵参数）│
│    └─ showDialog 仅返回 OverlayInstanceHandle<void>，缺乏结构化终态反馈     │
│                                                                             │
│ 3. packages/ui/src/composables/useMessageBox.ts (上下文捕获缺失)            │
│    ├─ 仅对 functional.ts 进行机械转发，未捕获调用方组件的 AppContext        │
│    └─ 导致组合式调用无法自然继承父级 provide 的依赖（如 Pinia/Router/Theme） │
│                                                                             │
│ 4. packages/ui/src/composables/useMessage.ts (容器挂载通道分裂)             │
│    ├─ 使用残缺的 renderImperative 挂载 MessageContainer 容器                │
│    └─ 生命周期管理虽具备活跃消息守卫与宽限期，但依赖旧式挂载接口            │
└─────────────────────────────────────────────────────────────────────────────┘
```

1. **接口分裂与浅层封装（Shallowness）**：
   - `render-imperative.ts` 内部同时导出 `mountOverlay` 与 `renderImperative`。后者丢弃了确定性终态 Promise 与两阶段受控离场动效，沦为仅提供销毁能力的浅包装。全库应统一收敛至 `mountOverlay` 单一 Seam。
2. **契约不对称与幽灵参数（Dead Contracts）**：
   - `packages/ui/src/components/dialog/functional.ts` 的 `ShowDialogOptions` 声明了 `onConfirm?: () => void`，但在实际构建包装组件与传递 props 时从未消费该回调，形成静默失效的死契约。
   - `MessageBox` 具备清晰的 `{ action: 'confirm' | 'cancel' | 'destroy', value?: string }` 结构化终态，而通用 `showDialog` 仅返回 `OverlayInstanceHandle<void>`，缺乏区分用户确认、取消或遮罩关闭的结构化反馈机制。
3. **组合式门面上下文缺失（Context Loss）**：
   - `useMessageBox.ts` 纯粹机械透传底层函数，未利用 `getCurrentInstance()?.appContext` 捕获组件调用上下文，导致脱离根节点时无法透明继承应用层 provide 的服务与主题注入。

### 2. 第一性原理与分层职责划分

现代 Vue 3 + 无头原语（Reka UI）架构下，命令式体系的高杠杆抽象遵循清晰的**分层单一职责原则**：

```text
┌──────────────────────────────────────────────────────────────────────────────────┐
│                                 分层职责单一模型                                 │
├────────────────────────────────────────────────────────┬─────────────────────────┤
│ 宿主传输桥接层 (Imperative Transport Bridge)            │ 无头领域原语层 (Reka UI)│
├────────────────────────────────────────────────────────┼─────────────────────────┤
│ • DOM 容器的物理创建、挂载与销毁 (render/remove)        │ • 焦点捕获、陷阱与安全归还│
│ • Vue 组件树上下文无缝桥接 (AppContext Inheritance)    │ • 顶层键盘响应与 ESC 冒泡│
│ • 独占模态 LIFO 栈深 Z-Index 递增注入                  │ • 遮罩交互与点击穿透防护│
│ • 两阶段受控离场动效与确定性终态 Promise 状态机        │ • 内部动画状态机与无障碍│
└────────────────────────────────────────────────────────┴─────────────────────────┘
```

- **宿主传输桥接器（`mountOverlay`）**：专职负责脱敏的 DOM 容器分配、Vue 上下文桥接、动态 Z-Index 步进注入以及终态 Promise 兑现。不越界干预键盘捕获与焦点移动，无障碍行为完全信任并委托给底层无头原语。
- **弹层形态分型治理（Distinct Lifecycles）**：
  - **独占模态浮层（Modal Overlays: Dialog / MessageBox）**：每次调用创建独立实例，拥有独占背景遮罩与焦点陷阱，入栈分配步进 Z-Index，离场后执行物理 GC。
  - **常驻通知架（Notification Shelves: Message / Toast）**：全局唯一宿主，`pointer-events-none` 穿透，固化顶层 Z-Index，不进入模态调度栈，其容器由**活跃消息队列长度 + 宽限期（Grace Period）**双重生命周期守卫。

## 二、 目标与非目标

### 1. 目标
- **深化命令式宿主控制器（Imperative Host Controller）**：在 `packages/ui/src/lib/render-imperative.ts` 中内聚 DOM 容器分配、两阶段受控离场动效、Z-Index 步进注入、AppContext 自动继承与全局测试清理能力；弃用并收敛 `renderImperative`。
- **消除幽灵契约并对齐结构化终态**：
  - 清理 `showDialog` 中无效的 `onConfirm` 幽灵参数；
  - 为 `showDialog` 提供与 `MessageBox` 对齐的结构化终态 Promise（`DialogResult<T>`）。
- **深化组合式门面（Context-Aware Composables）**：为 `useDialog` 与 `useMessageBox` 注入自动捕获调用方 `appContext` 的能力，实现跨层级依赖注入的无缝透传。
- **规范通知容器挂载通道**：规范 `useMessage` 容器的挂载实现，同时保持其活跃消息守卫与宽限期 GC 机制，确保跨路由跳转时提示不被异常掐断。
- **强化测试隔离与沙箱支持**：提供零 DOM 泄漏的 `destroyAllOverlays()` 测试清理通道，全面覆盖 SSR 安全与多层弹层场景。

### 2. 非目标
- 不改动组件既有的视觉表现与 Neo-Brutalism 设计令牌。
- 不接管或篡改 Reka UI 内部已有的 `FocusScope` 与 `DismissableLayer` 无障碍逻辑。
- 不破坏声明式组件（`<Dialog>`、`<MessageBox>` 等模板标签形式）的既有 Props 契约。

## 三、 核心架构设计与领域契约

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        Call Sites & Composables                        │
│     useDialog()        useMessageBox()       useMessage()   useToast() │

└────────────┬───────────────────┬───────────────────┬─────────────┬─────┘
             │                   │                   │             │
             ▼                   ▼                   │             │
┌────────────────────────────────────────────────────│───────────┐ │
│            Modal Overlay Host Controller           │           │ │
│  • mountOverlay<P, R>(component, factory, options) │           │ │
│  • Modal LIFO Stack Manager (Z-Index 自动步进)     │           │ │
│  • Two-Phase Controlled Closing (动效离场 -> GC)   │           │ │
```

### 1. 命令式宿主控制器契约（Imperative Host Controller）

位于 `packages/ui/src/lib/render-imperative.ts`，专职管理模态弹层的挂载、动效与生命周期：

```typescript
export interface MountOverlayOptions<R = unknown> {
    /** 注入的 AppContext，默认自动继承调用处组件实例或全局注册的 AppContext */
    appContext?: AppContext
    /** 过渡离场动画保护时长（毫秒），用于守护自动物理 GC */
    transitionDuration?: number
    /** 自定义基准或指定 z-index（若未指定则按栈层级自动步进） */
    zIndex?: number
    /** 关闭开始时的回调（触发离场动效时调用） */
    onClose?: (result?: R) => void
    /** 完全销毁/DOM 移除后的回调 */
    onDestroy?: () => void
}

export interface OverlayInstanceHandle<R = unknown> {
    /** 触发受控关闭：置 open 为 false 播放离场动效并在动画结束后自动 GC */
    close: (result?: R) => void
    /** 强制物理销毁：立即卸载组件并从 DOM 移除容器（幂等） */
    destroy: (result?: R) => void
    /** 确定性终态 Promise，在弹层关闭或销毁时兑现 */
    promise: Promise<R>
}

export type OverlayPropsFactory<P extends object = Record<string, unknown>, R = unknown> = (context: {
    isOpen: Ref<boolean>
    zIndex: number
    close: (result?: R) => void
    destroy: (result?: R) => void
    resolve: (result: R) => void
}) => P
```

### 2. 模态弹层栈与层级调度（Modal Stack Manager）

1. **模态 LIFO 栈与 Z-Index 步进**：
   - 维护独占模态栈 `modalOverlayStack`；
   - 每次调用 `mountOverlay` 时压栈，计算当前实例的 `calculatedZIndex = (options.zIndex ?? DEFAULT_OVERLAY_Z_INDEX) + stackDepth * OVERLAY_Z_INDEX_STEP`，并通过 Props 注入给包装组件；
   - 弹层触发 `close()` 或 `destroy()` 时出栈。
2. **两阶段受控离场过渡（Two-Phase Controlled Closing）**：
   - **Phase A（状态变更）**：调用 `close(result)` 时，置 `isOpen.value = false`，通知组件播放 Tailwind / Vue 离场动效；同时兑现终态 Promise；
   - **Phase B（物理 GC）**：延迟 `transitionDuration`（默认 `DEFAULT_DIALOG_TRANSITION_MS`）后，调用 `render(null, container)` 并移除容器 DOM 节点。
   - 若调用方显式调用 `destroy()`，则无视动效立即同步卸载并 GC。
3. **全局重置通道**：
   - 导出 `destroyAllOverlays()`，供测试沙箱（`afterEach`）或页面切态时同步强制清理全部挂载容器与栈状态。

### 3. Dialog 结构化终态契约（Structured Dialog Outcome）

消除原有的无效回调，建立确定性的行为反馈通道：

```typescript
export type DialogAction = 'confirm' | 'cancel' | 'close' | 'destroy'

export interface DialogResult<T = unknown> {
    action: DialogAction
    data?: T
}

export interface ShowDialogOptions<T = unknown> {
    title?: string
    description?: string
    content?: RenderableContent
    footer?: RenderableContent | ((context: { close: (result?: DialogResult<T>) => void }) => RenderableContent)
    draggable?: boolean
    dragHandle?: string | HTMLElement
    bounds?: 'parent' | 'viewport' | { top: number; left: number; right: number; bottom: number }
    initialPosition?: { x: number; y: number }
    resizable?: boolean
    minWidth?: number
    minHeight?: number
    maxWidth?: number
    maxHeight?: number
    aspectRatio?: number
    showCloseButton?: boolean
    forceMount?: boolean
    fullscreen?: boolean
    beforeClose?: () => boolean | Promise<boolean>
    destroyOnClose?: boolean
    zIndex?: number
    class?: string
    size?: DialogSize
    appContext?: AppContext
    transitionDuration?: number
}

export type DialogInstance<T = unknown> = OverlayInstanceHandle<DialogResult<T>>
```

### 4. 组合式门面的上下文自动继承（Context-Aware Composables）

在 `useDialog()` 与 `useMessageBox()` 的工厂入口处，自动提取当前 Vue 组件实例的上下文，实现依赖无感透传：

```typescript
export function useDialog(): UseDialogReturn {
    // 捕获调用本 hook 处的组件上下文（支持 Pinia、Vue Router、i18n、Theme 等注入）
    const instanceContext = getCurrentInstance()?.appContext

    const show = <T = unknown>(options: ShowDialogOptions<T> = {}): DialogInstance<T> => {
        return showDialog({
            appContext: options.appContext ?? instanceContext,
            ...options,
        })
    }
    // ...
}
```

### 5. 常驻通知架（useMessage）生命周期规范化

`useMessage` 的宿主是展示轻量非模态卡片的容器（`MessageContainer`），其生命周期模型维持“通知架”专用逻辑：
- 容器挂载使用轻量级单一宿主模式，保持 `pointer-events-none` 与固化层级 `Z_INDEX.MESSAGE`，**严禁混入模态调度栈**；
- 维持既有的**活跃消息计数守卫**（`messageStore.length > 0` 拒绝销毁容器）与 **Grace Period** 机制，确保路由导航与弹窗切换时正在展示的提示信息完整播放进出场动效。

## 四、 涉及模块重构与接口收敛

### 1. `packages/ui/src/lib/render-imperative.ts`
- **重构 `mountOverlay`**：内聚 DOM 容器创建、Z-Index 步进下发、`appContext` 继承、两阶段离场 GC 与 Promise 状态机；
- **废弃 `renderImperative`**：标记 `@deprecated` 并将其实现内部直接对齐 `mountOverlay`；
- **新增 `destroyAllOverlays()`**：导出全局清理函数，供测试环境彻底重置 DOM 与状态栈。

### 2. `packages/ui/src/components/dialog/functional.ts`
- **移除 `onConfirm` 幽灵参数**：从 `ShowDialogOptions` 中彻底清除该死字段；
- **实现结构化终态**：将返回类型重构为 `DialogInstance<T> = OverlayInstanceHandle<DialogResult<T>>`；遮罩/ESC 退出兑现为 `{ action: 'cancel' }`，受控关闭兑现为对应 action。

### 3. `packages/ui/src/composables/useDialog.ts`
- **上下文自动捕获**：在 `setup()` 执行期间自动捕获 `getCurrentInstance()?.appContext`；
- **泛型终态对齐**：透传泛型参数与结构化 `DialogResult<T>` 终态。

### 4. `packages/ui/src/composables/useMessageBox.ts`
- **上下文自动捕获**：在 Composable 内部捕获调用方 `appContext`，自动赋给 `showMessageBox`、`showConfirm`、`showAlert`、`showPrompt`；
- **统一类型信源**：完全复用 `functional.ts` 导出的领域类型。

### 5. `packages/ui/src/composables/useMessage.ts`
- **规范容器挂载**：使用规范化的 DOM 挂载逻辑替换过时的 `renderImperative`；
- **生命周期守卫坚守**：保留活跃消息守护与宽限期定时器，杜绝提前 GC。
