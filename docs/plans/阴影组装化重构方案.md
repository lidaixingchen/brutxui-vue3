## 背景与动机

《阴影过渡与焦点体系统一方案》方案 A 为消除 1↔5 层过渡鬼影，把 `--shadow-brutal*` 移出 `@theme`，
改为 `:root` 派生变量 + `@utility shadow-brutal*` **直挂 `box-shadow: var(--shadow-brutal)`**（绕过
Tailwind v4 的 `--tw-shadow` 五层组装）。

经代码质量 / 可维护性 / 可扩展性评审（2026-08-13），直挂实现的代价是实打实的：

1. **组合通道整体关闭**：与 ring（同写 box-shadow）同元素必冲突——方案 B 的 21 组件 outline 迁移正是这份代价的实证；
   `shadow-{color}` 修饰、内置 `shadow-{size}`、inset 阴影均无法与 brutal 阴影混用。
2. **命名空间语义错位**：`shadow-brutal-primary/secondary` 命中主题色，被额外解析出 `--tw-shadow-color` 死规则（旧方案 2026-08-12 记录 8 条，现行 dist 实测 10 条：primary/secondary/destructive 各 2 条 base + focus-within 各 2 条，计数随变体引用面演化）。
3. **覆盖粒度粗**：消费方只能改 `--brutal-shadow-*` 派生源，无法单独覆盖某一级阴影。
4. **与框架演进脱钩**：不享受组装通道的框架级改进。

结论：重新设计为**走 Tailwind v4 标准 `@theme` 派生 → `--tw-shadow` 五层组装**。视觉与过渡行为不变
（两端恒为 5 层、末层有色 → 过渡插值干净，无鬼影），但拿回组合能力。

> **基线说明（2026-08-13 起草，2026-08-14 修订）**：《按压反馈盖影设计》已落地提交（`--brutal-pressed-offset`
> 移除、`brutalPress*` 按压位移派生自 `--brutal-shadow-offset-x/y`、组件与测试同步，docs/index.md 已登记 done）。
> 与组装化正交（translate 类与 box-shadow 组装互不影响），无冲突；执行时以当前工作区为基线。

## 目标

- 阴影工具类全部由 `@theme` 令牌派生，经标准组装输出；删除 `@utility` 直挂实现。
- 组件类名、共享变体（`brutalHoverLift*` / `brutalPress*`）**零改动**；视觉与过渡行为不变。
- 恢复能力（变更说明向消费方宣告）：ring / inset / `shadow-{color}` 可与 brutal 阴影同元素共存。
- 消除 `--tw-shadow-color` 死规则。
- 焦点体系**回退 ring**（与组装化同批）：组装化消除 ring 的历史硬伤（box-shadow 争用）；统一常量以
  `outline-hidden` 补上 forced-colors 短板（实测 UA 恢复系统焦点环）并干净抑制 Safari 点击残留；
  消除 `--tw-outline-style` 变量陷阱（outline 体系下 `outline-none`/`outline-hidden` 均会静默杀死焦点环）。

## 关键实测结论（2026-08-13，tailwindcss 4.3.2 CLI 编译 + 4.3.0 引擎源码核对）

用与 `SHADOW_ENTRIES` 完全一致的主题值编译验证：

### 1. 组装产物形态（5 层）

```css
.shadow-brutal {
    --tw-shadow: var(--brutal-shadow-offset-x, 4px) var(--brutal-shadow-offset-y, 4px) 0px 0px var(--brutal-shadow-color, #000);
    box-shadow: var(--tw-inset-shadow), var(--tw-inset-ring-shadow), var(--tw-ring-offset-shadow), var(--tw-ring-shadow), var(--tw-shadow);
}
```

变体全自动生成：`hover:` / `focus:` / `focus-visible:` / `focus-within:` / `data-[highlighted]:` /
`active:`（`shadow-none`）等；`hover:` 变体包在 `@media (hover:hover)` 内（v4 行为，触屏不触发 hover，
语义正确）。4.3.0 引擎源码（dist/lib.js 的 `shadow` handler）确认同一模板。

### 2. 主题值内联；@theme 变量按"扫描命中"发射

- 工具类把 `@theme` 值**内联**进 `--tw-shadow`（引擎源码 `l("--tw-shadow", j, ...)` 直接使用主题值），
  不引用 `var(--shadow-brutal)`。
- `@theme` 变量是否发射到 `@layer theme` 的 `:root, :host` 取决于**扫描面命中**：类名使用与
  文本中出现变量名（含 `var()` 引用字样）均可触发；完全未使用且未提及的条目不发射（隔离编译实测：
  `--zzz-unused` 未出现；把 `--shadow-qqq7` 字样写入被扫描 html 即发射，文本命中不生成工具规则）。
  本库构建中 `--shadow-brutal*` 被组件类名（`@source` 扫描）命中 → **必然随 `@layer theme` 发射**。
- **推论**：消费方 `@theme { --shadow-brutal-lg: ... }` 覆盖路径保持不可用（dist 预编译值内联，
  与现状一致，非回归）；正规主题化路径仍是运行时 `--brutal-shadow-*`。→ 因此 `:root` 的
  `--shadow-brutal*` 派生变量**保留发射**（双发射）：消费方自定义 CSS 引用 `var(--shadow-brutal-lg)`
  不破，check-brutalist-tokens 门禁的 `:root` 提取点不动。双发无冲突：`@layer theme` 同值副本
  < `@layer base` 的 `:root`，后者胜；两处值同源（同一 SHADOW_ENTRIES），任一层生效均无差异。

### 3. ring 与 brutal 阴影共存（能力验证通过）

```css
.ring-2 { --tw-ring-shadow: var(--tw-ring-inset,) 0 0 0 calc(2px + var(--tw-ring-offset-width)) var(--tw-ring-color, currentcolor); box-shadow: <同一 5 层组装> }
```

ring 层与 `--tw-shadow` 层在同一 `box-shadow` 声明内分层渲染——同元素 `shadow-brutal` + `ring-2`
同时可见，互不顶掉（neobrutalism-components 即此用法）。

### 4. 颜色包装不对称（记录备查，非缺陷）

| 阴影 | 偏移形态 | 末层颜色是否包 `var(--tw-shadow-color, …)` | 可被 `shadow-{color}` 修饰 |
| --- | --- | --- | --- |
| `shadow-brutal` | 纯 var 偏移 | 否 | 否 |
| `shadow-brutal-sm/xl/lg`（含全部变体） | calc 偏移 | 是 | 是 |
| `shadow-brutal-primary/secondary` | 纯 var 偏移 | 否 | 否 |
| `shadow-brutal-destructive` | var 偏移 + color-mix 颜色 | 是（base 规则含 @supports color-mix 双规则） | 是 |

库内无 `shadow-{color}` 用法，视觉零差异；包装与否只影响消费方叠加 `shadow-{color}` 时的表现。

### 5. 副产品（均为改善）

- **`--tw-shadow-color` 死规则消失**：`shadow-brutal-primary/secondary` 现在被解析为尺寸工具类
  （`--shadow-brutal-primary` 在 `@theme` 内），不再额外按颜色语义输出 `--tw-shadow-color` 规则
  （旧方案 L119 曾断言"旧 @theme 实现同样存在该解析"，实测否定：死规则系 `@utility` 时代
  阴影键缺失于 `@theme`、颜色语义回退的特有产物）。
- **destructive 兜底改善**：不支持 color-mix 的浏览器获得 `var(--brutal-destructive)` 兜底色；
  现实现下 `color-mix(...)` 在旧浏览器为无效值 → 阴影静默消失。

## 焦点介质实测对比（2026-08-14，Playwright 1.60 bundled Chromium〔build 1223〕，8px 圆角按钮）

回退 ring 的决策依据，全部为浏览器实测（非推断）：

| 用例 | 普通模式 | forced-colors 模式 |
| --- | --- | --- |
| outline 体系（现状）：`focus-visible:outline-2 outline-offset-2` | ✓ 2px solid 黑 | ✓ 2px solid 系统色（UA 强制） |
| ring 候选：`focus-visible:ring-2 ring-offset-2` | ✓ ring 渲染（0 0 0 2px+offset，跟随圆角） | ✗ box-shadow 被禁用；未配抑制类时 UA 默认 outline（1px auto）仍在 |
| **ring + `outline-hidden`（推荐组合）** | ✓ ring 渲染 + UA outline 被抑制（无双环） | ✓ **outline-hidden 被 UA 强制恢复为 2px solid 系统焦点环** |
| outline + `outline-none`（陷阱复现） | ✗ outlineStyle:none，焦点环不可见 | ✗ 同样不可见（UA 不恢复） |
| outline + `outline-hidden`（陷阱复现） | ✗ 同上 | ✗ 同样不可见 |
| ring + `outline-none`（旧组合） | ✓ ring 正常 | ✗ 完全无焦点指示（方案 B 记录过的 forced-colors 缺口，实测复现） |

结论：

1. **`--tw-outline-style` 变量陷阱是 outline 体系的固有缺陷**：任何 outline 抑制类（`outline-none` 或
   `outline-hidden`）都会经 `var(--tw-outline-style)` 杀死 `outline-<n>` 的渲染，forced-colors 下
   UA 也不恢复——组件里误加一个抑制类即静默丢焦点环（select/dropdown-menu 已实踩）。
2. **ring + `outline-hidden` 两全**：普通模式干净（ring 显示、UA 环抑制）；forced-colors 下
   `outline-hidden` 自带的 `@media (forced-colors: active)` 恢复块（`outline: 2px solid transparent`，
   编译产物实证）配合 UA 颜色强制呈现系统焦点环（实测 2px solid 系统色）；ring 不依赖
   `--tw-outline-style`，无陷阱；Safari 点击残留环同样被 `outline-hidden` 抑制（不再有
   方案 B 的"两害取其轻"）。
3. **ring 与 brutal 阴影共存**（组装化前提）：实测 `shadow-brutal` + `ring-2` 同元素 box-shadow
   组装内 ring 层（0 0 0 2px）与阴影层（4px 4px 0 0）同时渲染。
4. **v4 宽度语义核对**：`ring-2`=2px（硬编码）、`ring-offset-2`=`--tw-ring-offset-width:2px`、
   `ring-offset-brutal-bg`=`--tw-ring-offset-color:var(--color-brutal-bg)`（暗色跟随，回退时统一
   使用，避免 v3 遗留的暗色白圈）。
5. 圆角跟随：ring 为 box-shadow 必然跟随 border-radius；outline 现代浏览器实现也跟随（方案 B
   已确认差异极微小），此维度不构成决策差异。

  无鬼影回归面；旧方案第 3 类"安全用法"清单不受影响。

  层级无变化），VitePress 无层样式特异性相对 utilities 层升高；docs 现有 `.vp-raw` revert-layer
  机制覆盖按钮类样式，无 box-shadow 冲突面（旧 @theme 时代同构，已运行验证）。

  `:root` 变量面保留，自定义 CSS 引用不破。写入变更说明。
- **ring 回退迁移面**：21 组件 + 2 共享变体 + 测试断言反向迁移，是阶段二最大变更面；均为方案 B
  清单的反向机械替换（ring-offset 色统一 `ring-offset-brutal-bg`，避免暗色白圈），逐文件核对即可；

  作用域字面量（ThemePlayground 等）同步面。
- **forced-colors 差异**：ring 本体在 forced-colors 下被禁用，焦点指示由 `outline-hidden` 自带的
