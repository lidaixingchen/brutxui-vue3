# 架构交付契约第三批修复方案

> 明确公开 API 的所有权，以消费者度量控制基础组件成本，并通过覆盖等价验证收敛工程门禁职责。

## 实施状态

代码实现、成本裁决与本地验收记录见[第三批验收报告](../../reports/audits/第三批架构交付契约验收报告.md)。Button 保留 effect 配置，公开入口和源码安装由显式契约约束，生成与检查已接入统一任务图。G5 的远程 CI 运行及 artifact 链接待候选提交后补充；该项完成后执行第九节归档流程。

## 一、目标与范围

本方案落实[项目架构与工程实践审查报告](../../reports/audits/项目架构与工程实践审查报告.md)第三批工作，承接[首批方案](../../archive/2026/core/架构交付契约首批修复方案.md)与[第二批方案](../../archive/2026/core/架构交付契约第二批修复方案.md)。源码核对基线为 `7d30ca7e`，核对日期为 2026-09-12；实施时重新记录实际提交及工具链版本。

| 工作主题 | 完成后的契约 | 主要交付 |
| --- | --- | --- |
| API 分层 | 公开入口与符号由显式契约决定；新增内部实现文件不会扩大公开面；源码分发保留完整依赖闭包 | API 契约清单、入口投影、依赖方向检查、迁移说明 |
| 基础组件成本 | Button 的缺省路径只承担实际启用的行为；特效组织方式由生产构建和浏览器度量决定 | 消费者成本基线、资源生命周期修复、特效拆分裁决及必要实现 |
| 工程规则精简 | 每个风险都有明确检查者；生成任务拥有唯一写入入口；职责替换经过正反样本验证 | 门禁覆盖表、统一生成编排、等价性回归、CI 与命令文档同步 |

保留现有五包结构及 Vue、Reka、Tailwind、Turbo 技术栈。API 分层在现有包内完成，组件目录继续使用现有组织方式。成本治理首先覆盖 Button，并用 Input、DataTable 和 GlitchText 作为基础、复合、特效场景的对照；扩展其他组件须有本批度量或依赖检查指出的具体问题。

本方案按阶段实施，代码、性能基准与消费者复验的实际结果记录在验收报告中。各阶段以退出条件和第八节验收矩阵判定完成。

## 二、现行代码证据与承接条件

### 2.1 API 公开面

- [prebuild-scan.ts](../../../packages/ui/scripts/prebuild-scan.ts) 的 `listPublicSourceFiles()` 将 composables、directives 目录第一层符合条件的 TypeScript 文件纳入导出清单；当前清单包含 92 个组件目录、35 个 composable 文件和 1 个 directive 文件。该数量描述文件入口，不代表公开符号数量。
- [generate-exports.ts](../../../packages/ui/scripts/generate-exports.ts) 据此派生包子路径；[Vite 配置](../../../packages/ui/vite.config.ts) 使用同一清单构造多入口构建。目录中的新 helper 可以因此成为可导入的包 API。
- [组件 index 生成器](../../../packages/shared/src/component-index.ts) 将扫描到的 Vue 文件以及 TypeScript 文件机械重导出；TypeScript 文件使用 `export *`。只限制 composable 目录仍会留下组件子路径的符号扩张通道。
- [根入口](../../../packages/ui/src/index.ts)和 [composables 聚合入口](../../../packages/ui/src/composables/index.ts)另行维护具名导出及星号导出。公开面需要同时核对根入口、包子路径、组件 index、类型声明和源码分发 index。
- [组件元数据](../../../packages/shared/src/component-metadata.ts)的 `category`、`kind`、`docsHidden` 服务于产品分类和文档展示，不能直接推导 API 可见性或依赖层级。
- [Button.vue](../../../packages/ui/src/components/button/Button.vue)的 `ButtonProps` 是 SFC 内部声明，组件可推导的 Props 形状与模块实际导出的具名类型需要分别盘点。

### 2.2 Button 的实际成本来源

[Button.vue](../../../packages/ui/src/components/button/Button.vue)缺省 `effect` 为 `none`，但仍调用 `useGlitchEffect()`，并在 mounted、updated 中读取 `textContent`、写入 `data-text`。[useGlitchEffect.ts](../../../packages/ui/src/composables/useGlitchEffect.ts)创建响应式状态、多个 watcher 和生命周期回调，同时调用 [useReducedMotion.ts](../../../packages/ui/src/composables/useReducedMotion.ts)查询并监听媒体偏好。

Button 传入特效控制器的 `disabled` 仅包含按钮禁用与加载状态，未包含 `effect` 开关。静态调用链表明，`effect="none"` 与 `glitchTrigger="autoplay"` 的组合仍可能进入特效计时路径；实施阶段先用可控定时器和真实浏览器分别核实资源与表现。

现有 [size-limit 配置](../../../packages/ui/package.json)覆盖完整根入口、从根入口导入 Button、聚合 CSS；[render.bench.ts](../../../packages/ui/perf/render.bench.ts)覆盖 DataTable、TreeView 的模拟 DOM 挂载。它们尚未给出 Button 的生产浏览器挂载、更新及特效资源成本。[Vite 配置](../../../packages/ui/vite.config.ts)采用 `cssCodeSplit: false`，因此 JS 入口隔离本身不能证明消费者 CSS 同时缩小。

以上为源码机制证据。本方案尚未测量新增字节数或渲染耗时，不据此宣称 Button 已经超过性能预算。

## 四、R1：公开 API 的所有权与分层

### 4.1 显式契约与源码发现

在 UI 包根目录新增 `api-contract.ts`，由 UI 维护公开入口意图。契约描述源码引用，不导入组件实现；仅由生成器、构建与检查工具读取。通用的校验、解析和投影函数放在 Shared 的构建工具入口，避免将编译工具带入 UI 运行时。

契约通过模块 ID 关联三组独立结构：公开入口投影、模块归属与依赖策略、Registry 安装关联。三者可以位于同一文件，分别由对应生成器或检查者消费；公共路径校验和模块引用复用同一实现。字段职责如下：

| 字段职责 | 约束 |
| --- | --- |
| 源码身份 | 包内相对路径；校验文件存在、路径大小写与路径范围 |
| 导出符号 | 明确源符号、对外名称及 value/type 属性；支持 Vue default 的具名映射 |
| 消费入口 | 明确根入口、包子路径和 Registry index 的投影；多个符号可以共享一个子路径 |
| 组件层级 | 在模块归属与依赖策略中记录 foundation、composite、effect、block；公共 runtime/helper 单独分类 |
| 源码安装身份 | 引用既有 Registry 组件 ID；安装单元与 npm 子路径允许不同，但映射必须明确 |
| 内部模块归属 | 对顶层 composable、组件组标明内部归属；内部符号不产生用户入口 |

组件标题、分类、示例及依赖元数据继续由 [COMPONENTS](../../../packages/shared/src/components.ts)负责，契约通过组件 ID 关联，不复制这些字段。`exports-manifest.json` 继续是派生产物，其结构随契约调整；消费者脚本共享结构定义，避免各自声明一份接口。

扫描器负责发现实际文件、符号和依赖边；契约负责决定公开内容。新增顶层模块但缺少公开或内部归属时，检查失败并指出待分类对象。既有模块内新增 helper 继承该模块的归属，只在存在层级差异时单独登记；内部 helper 无需填写公共符号、npm 子路径或独立安装映射。生成器不能把“发现了文件或新导出”自动写回公开契约。

### 4.2 本批分类与迁移边界

| API 类别 | 本批处理 |
| --- | --- |
| 现有公开组件及 CVA 变体 | 显式登记对外组件、已导出的具名类型及变体函数；组件 Props 推导形状单独验证，组件目录内实现文件按符号逐项筛选 |
| 应用集成 API | 保留 `BrutxUIPlugin`、locale、Toast/Theme 的 factory/provider、命令式弹层及清理入口；明确 App、组件上下文、SSR 前提 |
| 可独立使用的状态控制器 | 保留 `useToast`、`useTheme`、`useDialogGeometry`、DataTable 系列、`useClearable` 等公开用法，补齐输入、只读返回边界和生命周期说明 |
| 选择器内部协作 | 将 `useClearableSelection`、`useSelectableTrigger`、`useSelectionDisplayText`、`useTransferPanelSelection` 及仅供其内部调用的类型归为内部模块 |
| 动效与交互能力 | 将 `useGlitchEffect`、`useReducedMotion` 等登记为独立能力，公开承诺与 Button 的内部集成分别验证 |
| 样式与语言数据 | 显式登记 `style.css`、`preflight.css`、`locales`；保留各入口的副作用和消费说明 |

四个选择器 helper 的当前调用集中在 Combobox、Cascader、TreeSelect、Transfer。公开迁移指向对应组件的 props、事件与公开业务类型；这些 helper 的精细内部操作没有一对一公共替代，迁移说明必须明确这一点。公开 Props 若依赖相关类型，提取并登记必要业务类型，内部函数保持内部可见。

R0 分别列出“模块实际导出的具名类型”和“组件推导出的 Props 形状”。具名类型必须存在可重导出的源符号；SFC 内部 Props 声明由实际组件类型消费验证，不因接口名称存在就生成同名公共导出。具名类型的公开归属遵循本节分类，公开输入所需的业务类型具有明确声明与导出；其他新增具名 Props 类型须记录具体消费者用途及公开面影响。

R0 输出完整的“入口—符号—归属—处理”清单，覆盖全部当前导出，包括清理函数、注入 key、格式化函数和组件子类型。上述四项之外，本批保留既有公开名称并改为显式登记；进一步缩减须列出具体用途与迁移影响再评审，不能仅依据仓库内调用次数作决定。`useClearable` 与 `useDialogGeometry` 已有使用说明，不因承担底层逻辑就自动内部化。

内部化优先通过契约及具名入口实现，现有文件路径保持稳定，降低 Registry 基线迁移面。项目处于 0.x，公开项移除按破坏式变更一次完成，使用 changeset 与迁移文档说明，不保留重复公共别名承担同一职责。

### 4.3 统一入口投影

1. 根入口、公开 composable 聚合入口、组件 index、包 `exports` 和 Vite inputs 从同一契约派生。根入口保留当前样式副作用导入；生成前先确认手写入口中需要保留的运行时代码与副作用。
2. 为 composable 子路径生成只包含约定符号的入口文件，再让 Vite inputs 和 `exports` 指向其构建结果。不能只从根入口删掉符号，却继续把原实现文件的全部 export 暴露在子路径上。
3. 组件 index 使用明确符号与类型重导出。内部文件新增 export 不扩大根入口、组件子路径或 Registry index。
4. 子路径冲突按契约校验。同一个 `./loading` 涉及 Loading 组件和 `vLoading` 指令时，生成一个明确包含两者的公共入口；重复注册同名符号、来源不明或冲突覆盖均失败。
5. 所有生成文件只有统一生成过程写入，按内容比较后落盘；连续生成两次内容不变。`--check` 计算期望值并报告差异，全程只读。
6. 移除契约项后，由生成器同步收敛对应 `exports` 键，输出移除清单。残留派生文件按生成文件归属清单逐个处理，禁止手工维护自动生成的 `exports` 字段。
7. [脚手架](../../../packages/ui/scripts/scaffold/scaffold-engine.ts)创建基础骨架后登记公开或内部意图，barrel 交由生成过程统一更新。新组件、composable 仍通过根目录 `pnpm generate:component`、`pnpm generate:composable` 创建。

### 4.4 npm 与 Registry 的边界

公共可见性和分发必需文件是两个维度：内部模块可以出现在构建 chunk、声明依赖或 Registry 文件集合中，但不因此获得独立公共入口。

- npm 验证 `package.json exports`、根入口及子路径的实际 JS/DTS 符号。禁止通过通配子路径重新打开内部目录；封装边界验证使用包名导入，不把内部文件物理存在视作错误。Node 的 `exports` 用于限定按包名访问的入口。[Node 包入口说明](https://nodejs.org/docs/latest-v22.x/api/packages.html#package-entry-points)
- Registry 继续扫描组件运行必需的完整传递闭包，包括内部 composable、lib、样式及依赖组件。只有用户可安装单元和复制后的公共 index 受公开契约控制，不能先裁掉内部文件再做依赖展开。
- 扩展 [Shared index 生成逻辑](../../../packages/shared/src/component-index.ts)及 Registry 的对应调用，消费同一组公开符号投影。单独被依赖的内部文件仍以原路径进入源码包。
- [构建脚本](../../../packages/registry/scripts/build-registry.ts)的 `buildRegistryItem`、`computeSourceHash` 与核心编译器统一到同一组闭包、入口投影及 hash 实现；脚本保留的调用入口只委托核心。扫描 manifest 的写入由 UI generate 持有，Registry 构建读取准备好的清单。[构建测试](../../../packages/registry/tests/build-registry.test.ts)直接或通过委托入口验证生产核心；同一快照下普通构建、watch 与测试取得相同的文件集合、公共 index 和源码摘要。
- 验证 Combobox、TreeSelect、Transfer 的复制源码：内部 helper 可被相对引用，公共 index 不重导出它们，应用可以类型检查并完成生产构建。
- 使用两份本地 Registry 快照验证公开入口调整后的 `add/diff/update`；保留消费者已有改动及三方合并基线。需要文件迁移时，必须补充旧路径到新路径的重放场景。

### 4.5 组件依赖方向与检查

R0 先输出实际依赖图和模块归属，再启用方向检查。本批阻断规则优先覆盖 foundation 到上层、公开运行时到 AST/Node 构建工具的依赖以及模块循环；其余细分限制须有具体依赖问题及消费影响作为依据。下表定义模块归属和方向约束：

| 所属层 | 代表模块 | 允许依赖 |
| --- | --- | --- |
| runtime/helper | `cn()`、locale、令牌运行时投影、共享状态算法 | Vue、纯运行时工具及同层模块 |
| foundation | Button、Input、Badge、基础布局 | runtime/helper、Reka 原语及无环的同层依赖 |
| composite | DataTable、DatePicker、Combobox | foundation、runtime/helper；必要同层依赖要求有向且无环 |
| effect | GlitchText、视觉或动画组合组件 | foundation、runtime/helper；组合组件依赖按契约声明 |
| block | 页面区块、DashboardShell | 下层组件及 runtime/helper |

层级是架构元数据，与文档分类正交。`useGlitchEffect` 是可复用的运行时能力，Button 引用该 helper 是否合理由 R2 的资源与包成本约束决定；Button 引用上层特效组件则由依赖方向检查拦截。

复用已有 AST 解析设施提取模块引用，再通过共享文件解析层取得依赖目标。解析输入为 importer 文件路径、specifier 及当前 TypeScript/Vite 解析配置；别名取自实际配置，扩展名、目录 index 与 Vue SFC 的解析优先级在 R0 固定并验证。输出包含规范化文件路径、外部依赖身份及未解析或歧义诊断，供方向检查与 Registry 源码闭包共同使用。解析失败必须定位引用位置并阻断相应检查，不能降级为已通过的依赖边。

方向检查基于解析后的文件路径，覆盖相对路径、`@/`、跨组件 index、具名及星号重导出、静态可解析的动态导入。类型依赖独立记录，基础公共类型也不得经上层实现类型绕过分层；不可静态解析的动态引用要求显式依赖声明并复验。

源码方向检查、产物依赖隔离、消费者体积测量各负责不同事实。产物隔离继续覆盖编译器、Node 工具和私有 Shared 依赖；体积验证检查实际打包模块图，避免把字符串扫描当成完整运行时依赖分析。

## 五、R2：基础组件成本度量与修复

### 5.1 可重复的度量协议

复用第二批的 tarball 和临时消费者设施，新增 Button 成本场景。消费者安装实际候选 tarball，固定依赖 lockfile，清除工作区 alias 与 `NODE_PATH`，使用生产构建、固定浏览器版本和相同运行环境。

| 场景 | 观察内容 |
| --- | --- |
| 空消费者 | 框架、基础 CSS 与运行环境成本，作为差值参照 |
| 根入口导入 Button | 用户常见用法的实际 JS/CSS 和可选依赖解析 |
| Button 子路径导入 | 子路径与根入口差异、初始及异步 chunk 闭包 |
| 默认 Button 与 `effect="none"` 配置 autoplay | 缺省资源、媒体查询监听、定时器、DOM 文本同步 |
| glitch 的 hover/click/autoplay | 启用后的资源与更新成本、键盘和事件语义 |
| 动态 effect、loading、disabled、文本变化 | 启停、文本刷新、资源释放和更新耗时 |
| KeepAlive、卸载、减少动态效果 | 停用与恢复、清理完整性、偏好变化 |
| Input、DataTable、GlitchText 对照 | 基础、复合和特效层的依赖闭包与场景差异 |

每次报告记录提交、锁文件摘要、包摘要、Node/pnpm/浏览器版本、操作系统、构建模式、样本数及原始测量结果。样本规模、预热次数、重复轮数、超时和噪声容差集中放在 `packages/ui/perf/cost-profile.ts`，使用具名常量并说明采样目的。

体积同时报告原始、gzip、Brotli 字节，分别列出应用总量、相对空消费者增量、可选依赖和静态/动态 chunk；共享 chunk 按实际加载集合去重。浏览器指标包含挂载、文本更新、卸载的 p50/p95，以及资源创建、存活、释放数量。测试探针只进入测试构建；正式发布组件不增加调试计数接口。

性能计时使用真实生产页面；模拟 DOM 单测验证生命周期契约。通过受控环境适配器或测试 spy 观察媒体监听、定时器和文本读取，不依赖 Vue 私有字段统计 watcher 数量。R0 与 R2 使用相同脚本交替测量基线和候选，保留失败及离群样本。

现有 size-limit 中完整入口 `155 KB`、Button `22 KB`、CSS `20 KB` 继续作为现有工具口径的上限。消费者测量与 size-limit 的压缩、外部依赖计算方式分别记录，不能直接混用数值。新增时间预算从 R0 的重复样本及波动范围确定，在实现前落入版本化配置，不凭经验编造固定毫秒目标，也不在回归后自动抬高预算。Vue 官方同样建议在实际构建环境中测量依赖成本。[Vue 性能指南](https://vuejs.org/guide/best-practices/performance.html#bundle-size-and-tree-shaking)

### 5.2 缺省路径的资源契约

以下为必须满足的行为，不依赖耗时是否超标：

1. `effect="none"` 的 Button 不为 glitch 创建媒体查询监听、autoplay 定时器、DOM 文本同步或 `data-text`；传入 glitch 配置和调用暴露的 `play()` 均不得绕过关闭状态。
2. `effect` 开启时初始化当前触发方式与文本；关闭时停止并释放特效资源、清除激活态及特效属性。往返切换不重复注册监听或遗留回调。
3. loading、disabled、减少动态效果、KeepAlive 停用及卸载均按既有组件行为阻止或清理特效活动。Button 的 loading、提交、`asChild`、ARIA、焦点和事件透传契约保持完整。
4. 保留独立 `useGlitchEffect().play()/stop()` 的既有编程控制语义；Button 自己的 effect 开关在组件边界限制特效活动，不能把组件集成修复扩散成 composable 公共语义变更。
5. SSR 不读取 DOM 或创建浏览器资源；水合首帧与后续初始化分别验证。减少动态效果开关下仍应保持可访问名称、DOM 结构及交互一致。

实现优先为特效资源增加显式启用与释放边界，并让文本同步只随启用状态和相关内容更新发生。不能只在现有 `disabled` 中加一个条件就宣称成本已隔离，因为媒体查询订阅和 DOM 同步也需要纳入生命周期管理。

生命周期钩子在同步 setup 中注册；若控制器使用延后创建的 watcher/effect scope，必须返回明确释放句柄并由组件持有，在关闭、停用及卸载时回收。不能在动态 watch 回调中直接调用依赖当前组件实例的完整 composable。Vue 对异步创建 watcher 的自动清理有明确边界。[Vue watcher 生命周期](https://vuejs.org/guide/essentials/watchers.html#stopping-a-watcher)

### 5.3 特效组织方式的裁决

先完成资源契约修复，再比较完整 Button 与独立特效组合的候选成本。是否拆分由以下规则决定：

| 度量结论 | 实施结果 |
| --- | --- |
| 缺省资源契约通过，字节与浏览器指标满足预算 | 保留 Button 的 effect 配置，交付资源边界、测试和成本记录 |
| 默认入口因特效依赖或 CSS 超过预算，且移出特效后相关指标稳定改善超过测量噪声 | 将特效组合为独立 `GlitchButton`，通过 Button 复用基础交互，更新契约、文档、Registry 和消费者 |
| 测量波动过大或收益未能归因 | 修正采样或依赖分析后复测；保留已经验证的资源修复，拆分结论保持待验收 |

裁决结果记录输入摘要、改动前后数据、预算及最终选型。R2 不能仅留下“后续再测”；必须产生可重复的数据和明确组织结论。

若形成独立组件，通过脚手架创建；特效 CVA 与样式随特效归属，基础变体继续由原 Button 维护。组件提供 Button 的标准 props、slots、事件和 `asChild` 能力，特效参数及 `play/stop` 由特效组件负责；原 Button 移除对应特效 props、方法及实现依赖，迁移说明给出 `Button effect="glitch"` 到 `GlitchButton` 的用法。第 5.2 节的启停与交互验收随特效转移到该组件，基础 Button 验证特效资源始终为零，并确认没有额外可聚焦元素、嵌套按钮或多余可访问名称。

CSS 成本单独裁决：当前全量 `style.css` 的大小必须如实报告。只有实际拆出特效样式入口、消费者正确导入并通过计算样式检查后，才能声明按需 CSS 收益；共享令牌仍从既有数据源生成。若 CSS 预算没有要求拆分，保留聚合样式交付并记录该成本。

## 六、R3：工程门禁与生成职责收敛

第 6.2 节的生成编排、缓存边界和暂存快照检查属于 R3a；第 6.1、6.3 节所需的基线与对应基础样本随 R0、R3a 建立。完整覆盖等价、门禁职责替换和 CI 接入在 R1、R2 验收用例齐备后由 R3b 完成。

### 6.1 覆盖表先于步骤替换

R0 建立“风险—输入—检查实现—执行入口—失败证据”覆盖表，覆盖根脚本、各包脚本、Turbo、提交钩子、CI 和发布校验。R3a、R3b 在同一份表中登记最终所有者；可读表从测试用例和门禁登记派生，不另建一套全仓配置平台。

| 风险 | 最终检查责任 | 保留边界 |
| --- | --- | --- |
| 公开 API 意外扩张、入口漂移 | 扩展 `check-exports.ts`，校验显式契约和全部入口投影 | 检查源与生成清单，不能代替安装及 DTS 消费 |
| 跨层或内部构建依赖进入运行时 | 源码依赖方向检查、`check:isolation` 和消费者模块图 | 解析阶段不同，分别保留 |
| 自动生成内容与输入不一致 | 唯一生成入口及只读期望内容比较 | 比较完整输出清单，包含混合文件中的生成区域 |
| CSS、tokens、类名与依赖声明 | 现有 contracts 子检查 | 按各自断言保留，逐项证明重叠后才收敛 |
| 公开子路径与实际文件可解析 | UI package smoke | 覆盖所有入口，消费者代表场景不能替代它 |
| 实际安装、类型、生产构建及样式行为 | tarball 消费者及浏览器检查 | 复用产物和模板，保留各自行为断言 |
| Registry 完整性与版本重放 | Registry validate、快照及三方合并测试 | 不被 npm 成功替代 |
| 发布版本、摘要及恢复行为 | 现有 release 检查与协调器测试 | 本批只调整调用与结果复用，不改变发布状态机 |
| 文档链接、生命周期与组件用法 | 现有 docs suite | 与代码门禁分别保留 |

相同构建被多个独立 CI job 执行，不直接判定为可删除重复。只有候选提交、输入、工具链、产物摘要和所需准备条件一致时，才复用构建结果。检查事实不同的两项即使都能发现某个故障，也不因此等价。

### 6.2 唯一生成入口与命令职责

统一由包级 `generate` 编排扫描、公开入口、tokens 等生产者。根目录与各包的便捷命令经相同 Turbo 任务图进入该过程；lint、typecheck、build 的底层任务只消费其结果。

| 入口 | 目标职责 |
| --- | --- |
| UI `generate` | 扫描完整源码闭包，读取 API 契约，依次生成 manifest、公共入口、exports、样式等派生产物 |
| CLI `generate` | 从 Shared 生成 CLI tokens 与模板区域 |
| `build:artifact` | 消费 generate，构建 JS/DTS/CSS 并检查产物 |
| `lint:source`、`typecheck:source` | 消费准备结果，只读检查源码 |
| 根及包级 `build/lint/typecheck` | 通过统一任务图完成前置生成与对应检查 |
| contracts 默认检查 | 只读校验；显式 fix 动作调用对应 generate 后复测 |
| `pre-commit` | 对 Git index 对应的候选快照执行只读检查，报告需显式生成或暂存的文件及区域 |
| `prepack` | 调用公开构建入口；候选产物测试 pack 关闭生命周期，避免递归重建 |

表中的 `build:artifact`、`lint:source`、`typecheck:source` 和 CLI `generate` 为实施目标，当前尚不能视为已存在命令。定义 Turbo 消费边时确保普通 build 与底层 artifact 任务不会互相调用成环。

为 UI/CLI/Registry、检查和 watch 逐项声明真实输入、输出及依赖边，输出按唯一任务归属。R0 的生成清单逐文件记录生产者、完整生成内容或生成区域、手写区域、是否纳入版本控制及下游消费者。

UI、CLI 及其他写入源码树的 generate 任务统一设置 `cache: false`，冷缓存与热缓存均执行内容比较和必要生成。构建任务仅缓存 `dist` 等纯构建产物；`package.json`、`utils.ts`、样式等混合文件由生成器按字段或标记区域合并写入，保持手写内容，不作为整文件缓存恢复目标。API 契约、生成器、解析及构建配置、跨包 Shared 输入和参与构建的源码纳入下游构建哈希。Registry 保持 `cache: false`，先验证上游清单就绪与消费者结果。Turbo 按 `outputs` 恢复完整文件，源码区域的所有权由生成器维护。[Turborepo 缓存说明](https://turborepo.dev/docs/crafting-your-repository/caching)

检查进程不修改文件；公开便捷入口的前置 generate 可以写入派生产物，两者在日志和任务图中清楚区分。验证并行 build/lint/typecheck 时，一个任务图内 UI generate 只执行一次；对独立进程并发调用，使用包级生成锁串行保护并重新核对输入摘要，生成失败后必须可恢复。

提交钩子只校验 Git index 对应的候选快照，不修改工作树或 index，不运行工作区生成和自动 `git add`。检查使用同一组纯生成逻辑，在内存或隔离临时目录计算期望内容，对比快照中纳入版本控制的生成文件及生成区域；生成器、API 契约、组件源码、Shared 令牌、相关配置及混合文件的手写区域均取自该快照。Git index 定义待提交内容，可以据此构造候选树。[Git 暂存树说明](https://git-scm.com/docs/git-write-tree)

发现漂移时阻断提交，指出输入、派生文件或区域以及对应的显式 generate 命令；开发者生成后自行选择暂存内容。工作区中的未暂存修改和未跟踪文件不能参与快照校验；候选源码依赖的手写文件未纳入快照时明确失败。未纳入版本控制的完整生成文件由候选输入计算期望内容，供检查期间的依赖解析使用。混合输出中的未暂存手写修改保持原样。检查前后比较工作树文件内容及 index 条目，确保无额外内容进入提交。

### 6.3 等价性与故障注入

在隔离副本或内存文件系统中，对旧检查与候选检查运行相同正反样本。保留明确的样本清单及退出状态，替代检查必须覆盖原有合理拒绝，并补上本批契约要求；只比较“正常仓库都绿”不构成等价证明。

| 样本 | 必须得到的结果 |
| --- | --- |
| 内部文件新增具名 export | 生成公开面保持不变；手工泄露到公共入口时检查失败 |
| 删除已登记公共符号、错误路径大小写、子路径冲突 | 指明契约项和源码位置，阻断生成或检查 |
| 基础组件经 barrel 引入 block；引入 Shared AST/Node 工具 | 显示完整依赖链并失败 |
| Registry 缺少内部 helper | validate 或真实源码消费者失败 |
| Registry 相同快照经核心编译、脚本或 watch 构建 | 文件集合、公共 index 和源码摘要一致，测试验证同一核心实现 |
| SFC 局部 Props 声明、实际具名类型导出 | 组件 Props 类型消费通过；契约引用不存在的具名导出时失败 |
| 相对路径、别名、目录 index、Vue SFC 及重导出 | 解析到预期文件；未解析、歧义或缺少声明的动态引用被拦截 |
| 改动契约或源码后只保留旧 manifest/exports | 只读检查失败，统一 generate 后收敛 |
| 手改生成 CSS 或公共入口 | 只读检查失败，不隐式覆盖异常 |
| 构建配置或 API 契约变化 | 对应缓存哈希变化，产物反映新输入 |
| 源码生成任务热缓存、混合文件手写区域变化 | generate 实际执行；手写内容保留，下游构建缓存失效；缓存恢复只写纯构建产物 |
| 并发生成、写入中断与重试 | 锁与失败诊断正确，重试生成确定结果 |
| 同一输入部分暂存；跨文件存在未暂存输入 | 仅按 index 快照判定，工作树与 index 内容保持不变 |
| 已暂存组件引用未跟踪文件 | 报告候选快照缺少依赖并失败，工作区文件不能补足快照 |
| 候选源码依赖未纳入版本控制的完整生成入口 | 从候选输入计算入口并完成解析，工作树中已有生成文件不影响检查结果 |
| 混合输出含未暂存手写修改或暂存生成区域漂移 | 保留工作区内容；按暂存的生成区域决定通过或失败，不自动生成或暂存 |
| 未知消费者过滤值、空场景选择 | 明确失败，不能零用例成功 |
| 被聚合检查移除的任一风险样本 | 替代入口仍失败并定位同一风险 |

测试夹具只改明确登记的文件；临时输出逐项清理。生产源码、历史报告和方案文件不纳入批量清理。确定可以移除的脚本及命令逐项登记替代者后处理，保留仍有独立职责的检查。

### 6.4 CI 分层

- **相关代码 PR**：运行 API/源码边界、生成一致性、受影响单测、公开类型与产物隔离；API 或 Button 变化触发 U1/C1、Button 浏览器资源检查及体积预算。
- **构建与门禁变更 PR**：额外运行故障注入、任务图、缓存与部分暂存验收；职责调整前后对同一输入记录实际执行次数和耗时。
- **main 与候选交付**：执行覆盖率、现有完整消费者场景、Registry 与发布协调器回归。`test:types`、`check:isolation`、`test:coverage` 都必须有明确 workflow 调用；覆盖率沿用当前配置阈值，缺口通过补测试解决。
- **浏览器性能采样**：字节预算与资源数量作为确定性门禁；p50/p95 先产生对比报告，只有固定 runner 的采样稳定性得到验证后才作为阻断门禁。重试不能隐藏断言失败。

以实际执行日志确认覆盖表生效；任务过滤、缓存命中或产物复用导致检查没有运行时，必须能够证明复用结果对应同一契约输入。当前 `--all` 的含义以消费者场景清单为准，新增场景同步修改选择校验及 CI，不用名称暗示尚未实现的矩阵覆盖。

## 八、验收矩阵与聚焦命令

以下为实施阶段的完成标准，方案编写时仅执行文档校验。

| 编号 | 验收动作 | 通过标准 |
| --- | --- | --- |
| A1 | 全量入口与符号盘点 | 根入口、子路径、JS/DTS、Registry index 均可追溯到契约；实际具名类型与 Props 推导形状分列；内部模块可追溯到独立或继承的归属 |
| A2 | 内部模块及 export 扩展 | 新 helper 不扩大公开面；手工泄露可被拦截 |
| A3 | 公共入口类型消费 | 在隔离 tarball 消费者中检查根入口及子路径，使用 `skipLibCheck: false`；必要公共类型与组件 Props 可解析，具名类型均有实际源导出 |
| A4 | 内部入口负向消费 | 包子路径解析失败，根入口和组件 index 缺少内部符号；断言识别预期错误而非任意构建失败 |
| A5 | 依赖分层与产物隔离 | 解析规则样本通过；越层、barrel 绕行、循环及编译工具依赖被拦截；未解析引用有明确诊断 |
| A6 | 源码安装与更新 | 代表组件 helper 完整、公共 index 符合契约；生产、watch 与测试使用同一核心并取得相同源码摘要；add/diff/update 与本地修改保护通过 |
| B1 | 默认及关闭 effect | 特效媒体监听、定时器、文本同步为零，特效关闭不可被 play 或 autoplay 配置绕过 |
| B2 | 特效完整生命周期 | 切换、禁用、loading、KeepAlive、减少动态效果、卸载均通过，资源数量恢复到场景初始值 |
| B3 | Button 交互及 SSR/水合 | loading、表单、asChild、焦点、键盘、ARIA 与渲染一致性通过 |
| B4 | 成本度量与裁决 | 同环境基线与候选数据齐全，现有预算通过，拆分结论能由数据和规则复现 |
| B5 | 样式消费 | 实际生产 CSS 与计算样式通过；JS、聚合 CSS、按需 CSS 的成本分别说明 |
| G1 | 生成幂等与唯一写入 | 完整文件与生成区域均有唯一生产者；连续生成内容一致，独立并发安全，失败重试可恢复 |
| G2 | 检查只读与暂存保护 | 同文件部分暂存、跨文件未暂存输入、未跟踪依赖及混合输出样本按 index 快照判定；工作树与 index 内容均保持不变 |
| G3 | 缓存与输入关系 | 源码 generate 在冷、热缓存均执行；构建仅恢复纯产物；配置、契约、生成器或手写输入变化使对应哈希变化；热缓存、冷缓存、强制执行的目标产物一致 |
| G4 | 覆盖等价 | 覆盖表中的每次职责替换均有正反样本，未知或空消费者选择失败 |
| G5 | CI 执行证据 | 类型、隔离、覆盖率与本批门禁有实际运行结果，过滤与结果复用满足输入身份约束 |
| D1 | 文档与迁移 | 当前使用说明、破坏式变更、命令职责、验收报告及索引同步，前批限制明确 |
