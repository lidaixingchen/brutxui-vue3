## 一、 背景与第一性原理

### 1. 现状痛点

在 BrutxUI 组件库中，经过前期的阴影组装化和焦点体系回退，交互基础底座已逐步稳固。但在组件层面的状态语义呈现和无障碍支持上仍存在以下系统性不一致：

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        组件状态与交互痛点全景                          │
├────────────────────────────────────────────────────────────────────────┤
│ 1. 选中态语言分裂 (审查报告 §七):                                      │
│    ├─ Pagination: 黑底反转 + 彩色阴影 (shadow-brutal-primary)          │
│    ├─ Tabs: 边框式 + 阴影 + bg-brutal-accent                           │
│    ├─ Table: 仅 bg-brutal-accent / text-brutal-accent-foreground       │
│    ├─ Cascader: 边框 + 阴影 + 填充反转 (bg-brutal-primary)             │
│    ├─ Menu: 填充反转 + 边框 + 阴影 + 位移 (-translate-y-0.5)           │
│    └─ RadioGroup / Toggle: 各自手写 checked/on 配色，未复用共享定义    │
│                                                                        │
│ 2. 键盘导航缺失 (审查报告 §九):                                        │
│    ├─ MenuItem / SubMenu 所有启用项 tabindex="0"，无 roving focus      │
│    └─ 仅处理 Enter/Space，缺失方向键（ArrowUp/Down/Left/Right/Home/End）│
│                                                                        │
│ 3. 视觉规范脱节 (审查报告 §九):                                        │
│    ├─ Transfer 选项行使用 1px 细边框 (border) + 4px 细圆角 (rounded)    │
│    └─ 模板内联 cn() 违反组件库代码规范                                 │
│                                                                        │
│ 4. 晚挂载失效 (审查报告 §12.6):                                        │
│    └─ useCanvasInteraction 的 ResizeObserver 仅在 onMounted 执行一次   │
└────────────────────────────────────────────────────────────────────────┘
```

1. **选中态语言碎片化（审查报告 §七）**：
   - 库内存在 6 种以上选中/激活态实现方式。部分组件叠加了位移（Menu）、部分叠加了彩色阴影（Pagination）、部分仅改背景（Table）。
   - **违背第一性原理**：选中态（Selected）表达的是**「数据状态已确定」**，而悬停位移与阴影（Hover Lift）表达的是**「实体可交互」**。当选中项常驻保留位移与大阴影时，会与周围悬停项在物理层面上产生视觉空间歧义。
2. **Menu 键盘导航与 Roving Focus 缺失（审查报告 §九）**：
   - [MenuItem.vue](../../packages/ui/src/components/menu/MenuItem.vue) 与 [SubMenu.vue](../../packages/ui/src/components/menu/SubMenu.vue) 当前所有未禁用的项目均为 `tabindex="0"`，Tab 键会在每个菜单项间逐一穿透，且仅处理了 `@keydown.enter` 和 `@keydown.space`，完全缺失方向键导航，不符合 WAI-ARIA Menu / Menubar 模式规范。
3. **Transfer 选项行视觉违规与内联 cn 破窗（审查报告 §九）**：
   - [Transfer.vue](../../packages/ui/src/components/transfer/Transfer.vue) 选项列表行使用 `rounded border border-transparent`（1px 细边框与默认细圆角），违背了 VISUAL_SYSTEM R1「主边框一律 `border-3`、圆角一律 `rounded-brutal`」的硬性契约；且模板中直接内联了 `cn(...)`。
4. **画布尺寸监听晚挂载失效（审查报告 §12.6）**：
   - [useCanvasInteraction.ts](../../packages/ui/src/composables/useCanvasInteraction.ts) 在 `onMounted` 时尝试绑定 `containerRef.value`。若容器或画布处于条件渲染（`v-if`）或动态挂载，`ResizeObserver` 永远不会建立，尺寸变化将失联。

## 二、 目标与设计原则

```text
┌────────────────────────────────────────────────────────────────────────┐
│                      三态正交原则 (Three-State Orthogonality)          │
├─────────────────┬──────────────────────────────────────────────────────┤
│ 1. 悬停态 Hover  │ 位移 + 阴影浮起 (brutalHoverLift*) ── 表达「可交互」 │
├─────────────────┼──────────────────────────────────────────────────────┤
│ 2. 选中态 Select │ 填充反转 (bg-primary text-primary-fg) ── 表达「已选择」│
├─────────────────┼──────────────────────────────────────────────────────┤
│ 3. 焦点态 Focus  │ 无障碍焦点环 (FOCUS_RING_CLASSES) ── 表达「键盘所在」 │
└─────────────────┴──────────────────────────────────────────────────────┘
```

1. **三态正交原则（Three-State Orthogonality）**：
   - 悬停（Hover）、选中（Selected）、聚焦（Focus）三态职责解耦：
     - **Hover**：位移 + 阴影变化；
     - **Selected**：统一为「填充反转」（`bg-brutal-primary text-brutal-primary-foreground`），剥离常驻位移与彩色阴影；
     - **Focus**：标准双层 ring 焦点环（`FOCUS_RING_CLASSES`）。
2. **表单开关统一收敛与选择器兼容**：
   - RadioGroup、Toggle 等表单状态组件统一接入 `@/lib/form-toggle-base` 变体，同时兼容 `data-[state=checked]` 与 `data-[state=on]` 选择器，消除手写类串。
3. **完整无障碍键盘支持（WAI-ARIA Compliance）**：
   - Menu 组件体系实现标准的 Roving Tabindex（仅聚焦项 `tabindex="0"`，其余 `-1`）与 DOM 顺序方向键循环导航，严格区分水平模式（Menubar）与垂直模式（Menu）。
4. **新粗野主义视觉 100% 对齐与模板合规**：
   - Transfer 选项列表全面重构为 `border-3 border-transparent rounded-brutal` 占位，消除布局跳变，并通过 `<script setup>` 辅助方法计算类名，严禁模板内联 `cn()`。
5. **生命周期弹性自愈**：
   - `useCanvasInteraction` 接入 `watch([containerRef, canvasRef])` 动态监听挂载生命周期，并彻底清理 `onMounted` 冗余。

### 2. Menu 键盘导航与 Roving Focus 架构

在 [Menu.vue](../../packages/ui/src/components/menu/Menu.vue)、[MenuItem.vue](../../packages/ui/src/components/menu/MenuItem.vue) 与 [SubMenu.vue](../../packages/ui/src/components/menu/SubMenu.vue) 中建立统一的 Roving Tabindex 焦点管理：

```text
┌────────────────────────────────────────────────────────────────────────┐
│                     Menu Roving Focus 焦点流转                         │
├────────────────────────────────────────────────────────────────────────┤
│ [MenuItem 1 (tabindex=0)] <─── 当前聚焦 / 初始项                       │
│      │  ▲                                                              │
│  ArrowDown │ ArrowUp (垂直模式)                                        │
│  ArrowRight │ ArrowLeft (水平模式)                                     │
│      ▼  │                                                              │
│ [SubMenu Trigger (tabindex=-1)]                                        │
│      │                                                                 │
│      ├── (水平模式 ArrowDown / 垂直模式 ArrowRight) ──▶ 展开并聚焦子项 │
│      │                                                                 │
│      ▼                                                                 │
│ [MenuItem 2 (tabindex=-1)]                                             │
│                                                                        │
│ - 按 Home 键  ──▶ 聚焦首个可用项 [MenuItem 1]                          │
│ - 按 End 键   ──▶ 聚焦末尾可用项 [MenuItem 2]                          │
│ - 按 Enter/Space ──▶ 触发选中 handleClick() 或展开/收起 SubMenu        │
└────────────────────────────────────────────────────────────────────────┘
```

#### 2.1 Context 协议扩展 (`menu-types.ts`)
```typescript
export interface MenuItemEntry {
    index: string
    el: HTMLElement
    disabled: boolean
    isSubMenuTrigger?: boolean
}

export interface MenuContext {
    activeIndex: Ref<string>
    focusedIndex: Ref<string | null>
    mode: Ref<'horizontal' | 'vertical'>
    router: Ref<boolean>
    openedMenus: Ref<Set<string>>
    registerItem: (entry: MenuItemEntry) => void
    unregisterItem: (index: string) => void
    focusItem: (index: string) => void
    focusNextItem: (current: string) => void
    focusPrevItem: (current: string) => void
    focusFirstItem: () => void
    focusLastItem: () => void
    selectItem: (index: string, route?: string | object) => void
    toggleSubMenu: (index: string) => void
    openSubMenu: (index: string) => void
    closeSubMenu: (index: string) => void
    registerSubMenu: (index: string, children: ReadonlySet<string>) => void
    unregisterSubMenu: (index: string) => void
}
```

#### 2.2 DOM 排序与 Roving Tabindex 焦点管理 (`Menu.vue`)
1. **DOM 几何排序**：
   在 `registerItem` 中，使用 `compareDocumentPosition` 保持条目与实际 DOM 顺序完全一致：
   ```typescript
   const registeredItems = ref<MenuItemEntry[]>([])

   function registerItem(entry: MenuItemEntry) {
       const next = registeredItems.value.filter((i) => i.index !== entry.index)
       next.push(entry)
       next.sort((a, b) => {
           if (a.el === b.el) return 0
           const position = a.el.compareDocumentPosition(b.el)
           return (position & Node.DOCUMENT_POSITION_FOLLOWING) ? -1 : 1
       })
       registeredItems.value = next
   }
   ```
2. **Tabindex 计算规则**：
   - 若 `focusedIndex` 匹配当前项，则 `tabindex="0"`；
   - 若尚未聚焦（`focusedIndex.value === null`），且当前项为第一个未禁用的条目（或匹配 `activeIndex`），则 `tabindex="0"`；
   - 其余项目一律 `tabindex="-1"`。

#### 2.3 键盘事件监听与模式分流 (`MenuItem.vue` & `SubMenu.vue`)
根据 `mode` 区分方向键语义：
```typescript
function handleKeydown(e: KeyboardEvent) {
    if (props.disabled) return
    const isHorizontal = context?.mode.value === 'horizontal'

    switch (e.key) {
        case 'ArrowDown':
            e.preventDefault()
            if (isHorizontal && isSubMenuTrigger) {
                // 水平模式：向下键展开子菜单并聚焦首项
                context?.openSubMenu(props.index)
            } else {
                context?.focusNextItem(props.index)
            }
            break
        case 'ArrowUp':
            e.preventDefault()
            context?.focusPrevItem(props.index)
            break
        case 'ArrowRight':
            e.preventDefault()
            if (isHorizontal) {
                context?.focusNextItem(props.index)
            } else if (isSubMenuTrigger) {
                // 垂直模式：向右键展开子菜单
                context?.openSubMenu(props.index)
            }
            break
        case 'ArrowLeft':
            e.preventDefault()
            if (isHorizontal) {
                context?.focusPrevItem(props.index)
            } else if (parentSubMenu) {
                // 垂直模式在子项中向左键：收起当前子菜单并回退焦点到父级触发器
                parentSubMenu.closeAndFocusTrigger()
            }
            break
        case 'Home':
            e.preventDefault()
            context?.focusFirstItem()
            break
        case 'End':
            e.preventDefault()
            context?.focusLastItem()
            break
        case 'Enter':
        case ' ':
            e.preventDefault()
            handleClick()
            break
    }
}
```

### 4. useCanvasInteraction 晚挂载自愈机制

- **文件**：[packages/ui/src/composables/useCanvasInteraction.ts](../../packages/ui/src/composables/useCanvasInteraction.ts)
- **改造方案**：
  1. 监听 `[containerRef, canvasRef]` 双 Ref，并在 watch 回调中完成初次与动态绑定的自愈；
  2. 彻底清理原有 `onMounted` 中的冗余代码；
  3. 保留 `onUnmounted` 中的 `disconnect` 与定时器清理。

  ```typescript
  // 建立 ResizeObserver 监听，支持动态挂载与条件渲染自愈
  watch(
      [containerRef, canvasRef],
      ([newContainer, newCanvas], [oldContainer]) => {
          if (oldContainer && resizeObserver) {
              resizeObserver.unobserve(oldContainer)
          }
          if (newContainer && newCanvas) {
              syncCanvasSize()
              const ResizeObserverCtor = getResizeObserverCtor()
              if (ResizeObserverCtor) {
                  if (!resizeObserver) {
                      resizeObserver = new ResizeObserverCtor(syncCanvasSize)
                  }
                  resizeObserver.observe(newContainer)
              }
          }
      },
      { immediate: true, flush: 'post' }
  )

  onUnmounted(() => {
      if (resizeObserver) {
          resizeObserver.disconnect()
          resizeObserver = null
      }
      if (revealTimerId) {
          clearTimeout(revealTimerId)
          revealTimerId = null
      }
  })
  ```
