## 背景

用户实测 Button 按压反馈后反馈：按下按钮时按钮「直接向下」移动，而不是斜向滑到右下角、落在阴影原本的位置上把阴影盖住（经典 Neo-Brutalist 物理按键效果）。经排查，当前行为是**刻意设计且已被文档固化**，并非回归缺陷；但用户期望的交互模型与现行模型不同，已确认改为「盖住阴影」式按压。

## 现状与根因

### 现行按压语义（文档固化）

视觉规则 VISUAL_SYSTEM R4 规定：

```css
active:translate-y-[var(--brutal-pressed-offset,2px)] active:shadow-none
```

即：按压时仅 **Y 轴下移 2px**（`--brutal-pressed-offset` 令牌）+ **阴影直接移除**（shadow-none），无 X 轴位移。此语义自最早提取交互样式的 commit（`f3a314c3`）起未变，全库共享导出 `brutalPress` 及持久按下家族 `brutalPressedState` / `brutalPressedStateOn` / `brutalHighlightPress`（约 30+ 组件引用）。

### 「直接向下」观感的两个成因

1. **无 X 轴位移**：按压类名只有 `translate-y`，从静止位置看就是纯垂直下落 2px。
2. **hover 叠加未重置 X**：鼠标按压必然同时 hover。Tailwind v4 位移由 `--tw-translate-x` / `--tw-translate-y` 两个变量合成，`active:translate-y-...` 只覆盖 Y 轴；hover 的 `-translate-x-0.5`（-2px）在按压态保留 → 按压时按钮实际停在「静止位左偏 2px、下移 2px」处，从 hover 位置（-2,-2）看是**纯垂直下落 4px**，阴影同时消失，观感即「直接向下、阴影凭空没了」。

### 相关令牌与尺度

| 令牌 | 值 | 说明 |
| --- | --- | --- |
| `--brutal-shadow-offset-x` / `-y` | `4px` | 阴影偏移（基础档 `shadow-brutal`；sm=2px、lg=6px、xl=8px 按此派生） |
| `--brutal-pressed-offset` | `2px` | 现行按压偏移（本方案移除） |

## 设计决策

用户已确认选择「**盖住阴影**」式按压：按压时元素斜向滑到阴影原本的位置（X/Y 各等于阴影偏移），同时阴影消失——视觉上按钮「落回右下角盖住自己的影子」。位移直接派生自 `--brutal-shadow-offset-x/y`，**单一事实来源**，主题自定义阴影偏移（如 pastel 的 3px、自定义 6px）时按压自动同步，无需维护第二个令牌。

## 详细设计

### 一、brutalPress 家族新语义（核心）

`packages/ui/src/lib/brutal-interaction-variants.ts` 四个导出全部改为斜向按压（完整类名字面量，满足 @source 契约）：

| 导出 | 新类名串 | 用途 |
| --- | --- | --- |
| `brutalPress` | `active:translate-x-[var(--brutal-shadow-offset-x,4px)] active:translate-y-[var(--brutal-shadow-offset-y,4px)] active:shadow-none` | 瞬态按压（Button 等 30+ 组件自动生效） |
| `brutalPressedState` | `translate-x-[var(--brutal-shadow-offset-x,4px)] translate-y-[var(--brutal-shadow-offset-y,4px)] shadow-none` | 持久按下态（copy-to-clipboard 等） |
| `brutalPressedStateOn` | `data-[state=on]:translate-x-[var(--brutal-shadow-offset-x,4px)] data-[state=on]:translate-y-[var(--brutal-shadow-offset-y,4px)] data-[state=on]:shadow-none` | 持久「开启保持按下」（toggle 等） |
| `brutalHighlightPress` | `data-[highlighted]:active:translate-x-[var(--brutal-shadow-offset-x,4px)] data-[highlighted]:active:translate-y-[var(--brutal-shadow-offset-y,4px)] data-[highlighted]:active:shadow-none` | 高亮项按压（command） |

行为要点：

- **hover 叠加正确**：active/data-* 字节序恒在 hover 之后，`translate-x` 同时被覆盖 → 按压时从 hover(-2,-2) 斜移到 (+4,+4)，恰好落在阴影足迹上。
- **原 `translate-x-0` 重置不再需要**：旧 `brutalPressedStateOn` / `brutalHighlightPress` 用 `translate-x-0` 抵消 hoverLift 的 X 侧滑；新语义的 `translate-x-[阴影偏移]` 本身就是重置（同字节序机制），语义更强。
- **文件头部契约注释同步**：②③ 条补充新位移方向说明。

## 影响与风险

1. **sm 阴影组件按压过冲**：pagination/toggle/MonthPicker 等基态 `shadow-brutal-sm`（2px）组件按压位移为 4px，超出原阴影足迹 2px；阴影同时消失、无可见错位，视觉上只是按压行程更深，可接受。⚠️ 逃生口精确性：`[--brutal-shadow-offset-x:2px]` 局部覆盖会**同时缩放派生阴影**（`--shadow-brutal-sm = offset/2`，styles.css:121），sm 组件下得到「按压 2px 对 1px 阴影」，仍非精确贴合——该逃生口仅适用于 base 阴影组件；sm 组件若需精确贴合只能用 B 类字面量模式（Image/Tour 的 `active:translate-y-[2px]`）。
2. **动效更明显**：hover(-2,-2) → 按压(+4,+4) 为 6px 斜向滑动（transition-all 150ms），正是用户期望的「回到右下角」轨迹；prefers-reduced-motion 无影响（位移为瞬态，无动画）。
3. **门禁校验**：新类名均为完整字面量（check:class-literals 通过面）；无新增 ring/shadow-[rgba] 类（check:deprecated 无影响）；`--brutal-pressed-offset` 从源码面移除后，将 `brutal-pressed-offset` 追加进 `scripts/check-guide-refs.mjs` 的 `REMOVED_SYMBOLS` 黑名单（现不在其中，残留引用不会被拦截）——与文档同步同批提交，使 guides/skills 残留引用变红、验收项有门禁兜底；audit:fallback 白名单键删除后需 `--update-baseline`（冗余白名单在任何模式均 exit 1，必须先删键再更新基线）。
4. **破坏式变更**：`--brutal-pressed-offset` 令牌移除对自定义主题用户是 breaking change（0.x 早期，按仓库约定允许破坏式变更）；主题文档同步移除该令牌行。
