# 首批组件动效改进方案

> 统一 Toast 和 Message 的进出场节奏，让 Counter 连续追随目标值，并增强链接在鼠标与键盘操作时的反馈。

## 改动范围

首批动效使用原生 CSS 和现有 Vue 能力实现。Toast 从当前画面离场，Message 同步完成离场与列表重排，Counter 续接时保持读数完整，链接以可辨认的静止态和稳定的交互反馈呈现。[动效调研](../../reports/research/EffectAtlas动效实现调研.md)

| 改动面 | 具体交付 |
| --- | --- |
| 共享样式 | 由共享令牌编译器生成 npm 样式和 CLI 样式，各分发路径验证本次发行的配套组件与样式。 |
| Toast、Message | Toast 从当前透明度和位置离场并结算 `close`。Message 离场项退出布局流，保留项同时重排。 |
| Counter | 自动模式下仅更新 `to` 时，从当前读数续接，并按起点和目标中更宽的读数预留空间。 |
| Button 的 `link` 变体、BreadcrumbLink | 正文链接默认可辨，悬停和键盘焦点增强下划线。通过现有插槽提供双语文档中的方向箭头示例。 |

现有组件属性、事件、插槽和包入口沿用当前契约。实体按压继续跟随硬阴影令牌，Breadcrumb 的实体标签继续作为整体按压，集合选项行继续使用稳定几何与即时焦点。Image 共享元素、菜单外壳展开和展示型特效归入后续批次。[视觉系统 R4–R7](../../guides/VISUAL_SYSTEM.md#r4-按压反馈-press-feedback)、[分发与公开 API 契约](../../architecture/分发与公开API契约.md)

## 实施顺序

### 一、统一时长令牌与消费方式

在当前 npm 与 CLI 源码安装路径分别记录 Toast 的计算动画时长、`close` 事件时点、Message 的进出场和重排时长，并保留链接在普通、悬停、焦点状态下的对照。Toast 源码中的 `LEAVE_ANIMATION_DELAY` 为 300 ms，`duration-300` 与全局 `animate-out` 参与的是不同的 CSS 声明，基线以实际 `animation-duration` 和事件时点为准。[Toast 关闭逻辑](../../../packages/ui/src/components/toast/Toast.vue#L14)、[Toast 变体](../../../packages/ui/src/components/toast/toast-variants.ts#L8)、[全局动画](../../../packages/ui/src/styles.css#L707)

链接反馈以现有 Button 的 150 ms 为初始值。通知进入 300 ms、离开 250 ms、重排 300 ms 取现有 Message 的节奏作为候选值。对照 Toast 基线比较连续通知、手动关闭和入场中关闭的节奏后定稿。

**分发决策。** 四个语义时长只在共享源定义，由 `pnpm generate:tokens` 生成 npm 全局样式和 CLI `init` 注入的样式。组件通过 CSS 自定义属性读取所在作用域的生效值。通知进入、离开和重排分别引用对应令牌，Counter 使用自身 `duration`。npm 以同一发行版的组件入口与样式入口作为验收单元，CLI 以同一发行版的 `init` 样式与 Registry 组件作为验收单元。两条路径均通过真实渲染验证默认值和使用者覆盖值。[设计令牌](../../../packages/shared/src/design-tokens.ts)、[令牌编译器](../../../packages/shared/src/tokens/token-style-compiler.ts)、[生成与构建机制](../../architecture/生成与构建机制.md)

### 二、对齐 Toast 与 Message 的通知时序

**Toast 离场决策。** 使用 Vue `Transition` 与 `v-show` 管理通知根节点的显示，显式指定 `type="transition"`。根节点在进出场始终声明 `opacity` 和 `transform` 的过渡，打开和关闭分别使用进入和离开时长令牌。入场从右侧透明态过渡到就位态。关闭时直接切换到离场终态，浏览器从当时的透明度和位置开始反向过渡。[Vue 过渡](https://vuejs.org/guide/built-ins/transition.html)

Vue 的 `after-leave` 钩子负责正常结算。CSS 禁用过渡、当前根节点离场过渡取消或减少动态效果生效时，立即落到离场终态并走同一个结算入口。结算关联本次离场，只接受该根节点上属于本次离场的过渡取消，每次关闭只派发一次 `close`。外部移除或卸载会使待执行的结算失效。

自动到期、点击关闭和 Escape 共用离场入口。进入离场即停止业务计时，并让关闭控件停止响应重复输入。`duration` 仍表示停留时间，`duration=0` 保持常驻，悬停暂停、剩余时间恢复、进度条和堆叠行为沿用现有语义。`useToast` 的主动删除和清空仍直接更新列表，组件自身的关闭在视觉结算后通知上层。[Toast](../../../packages/ui/src/components/toast/Toast.vue#L47)、[Toast 状态](../../../packages/ui/src/composables/useToast.ts#L70)

**Message 重排。** 使用 Vue `TransitionGroup` 与稳定消息 ID。离场前记录消息在滚动容器中的布局位置和宽度，离场开始时保留该位置和宽度，并让该项退出布局流。保留项同时通过 `transform` 移向新位置。进出场只过渡 `opacity` 和 `transform`，分别消费对应令牌，重排消费独立令牌。减少动态效果时直接采用最终布局。消息存储继续负责增删与自动关闭，容器仅在消息存储为空、无活跃宿主且所有离场均已结算时进入空闲回收，避免 CSS 时长覆盖截断最后一条消息。[Message 容器](../../../packages/ui/src/components/message/MessageContainer.vue#L57)、[容器回收](../../../packages/ui/src/composables/useMessage.ts#L41)、[Vue 列表过渡](https://vuejs.org/guide/built-ins/transition-group.html)

**通知焦点。** 通知出现时保留页面已有焦点。离场开始时，若焦点在离场项内，依次查找列表中后续通知的可用关闭控件、前序通知的可用关闭控件、该通知出现前记录的页面焦点、页面已有的主内容区域。焦点落点须仍处于当前可交互范围，缺少可用落点时沿用浏览器的 Tab 顺序。焦点处理后，将离场项从命中区域和 Tab 顺序移除。焦点原本在离场项外时留在原处。[WAI 键盘焦点指南](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/#discernibleandpredictablekeyboardfocus)

### 三、让 Counter 从当前读数续接

**Counter 续接与缩放决策。** 每段动画在开始时确定起值和目标，自动续接以最后一次渲染的内部数值为起点，取消旧帧后只运行最新段。段开始时使用现有格式化规则和可见前后缀测量两端，按较宽的一端计算缩放。续接需要缩小时立即应用新比例，放大延至段结束，并按目标读数重算。容器或字体尺寸变化时重新测量，普通动画帧复用本段的缩放比例。[Counter 插值与播放](../../../packages/ui/src/components/counter/Counter.vue#L95)、[Counter 布局测量](../../../packages/ui/src/components/counter/Counter.vue#L139)

| 输入 | 结果 |
| --- | --- |
| 挂载自动播放或显式调用 `play()` | 从当前 `from` 播放至当前 `to`。 |
| `autoStart=true` 且仅 `to` 更新 | 从当前数值续接到最新目标。目标反转时自然改为反方向，已被替换的段不触发 `complete`。 |
| `autoStart=true` 且 `from` 更新 | 以新的 `from` 重新开始。同一批更新中的 `to` 作为目标。 |
| `autoStart=false` 且 `from` 或 `to` 更新 | 沿用手动模式，停止当前段并显示 `from`，由调用方再次触发播放。 |
| 播放中仅更新 `duration` | 按新旧有效时长重算时间基准，保留当前段已完成的比例，剩余播放按新时长计算。 |
| `stop()`、卸载或减少动态效果 | `stop()` 保留当前读数且不触发 `complete`。卸载清理资源。减少动态效果时运行中的最新段立即到达目标并完成一次。 |

### 四、改进链接和方向图标反馈

在 `Button variant="link"` 与 `BreadcrumbLink` 的文字上使用原生 CSS 下划线。Button 的 `link` 变体在静止态提供可见下划线，覆盖 `asChild` 渲染为真实链接的正文用法。BreadcrumbLink 由实体标签和导航结构提供静止态辨识，下划线作为交互增强。悬停或 `:focus-visible` 时过渡 `text-decoration-color`，固定下划线偏移和线宽，由文本排版定位每行下划线。快速移入移出或焦点转移时从当前颜色值过渡。焦点环在获得键盘焦点时立即可见，减少动态效果时下划线立即切换。触屏激活遵循节点原有语义，Breadcrumb 的 `folder` 样式及 Button 的按压、禁用、加载和原语转发沿用现有行为。[Button 变体](../../../packages/ui/src/components/button/button-variants.ts)、[Breadcrumb 变体](../../../packages/ui/src/components/breadcrumb/breadcrumb-variants.ts)、[WCAG 颜色使用](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)

下划线样式落在真实交互节点，`asChild` 仍接收唯一子节点。方向性反馈通过现有插槽给出一个文档示例，使用原有箭头图标，入场和退场仅变换装饰图标层。图标对辅助技术隐藏，文本继续提供可访问名称。实施时同步受影响组件的中英文行为说明和示例。[Button 插槽与属性转发](../../../packages/ui/src/components/button/Button.vue#L216)、[组件文档模板](../../guides/COMPONENT_DOC_TEMPLATE.md)

## 验收标准

| 验收项 | 通过条件 | 验证方法 |
| --- | --- | --- |
| 通知关闭 | Toast 入场首帧关闭可正常结算，入场中途关闭时离场首帧接续当时的透明度和位置。点击、Escape 或自动到期重合时只派发一次 `close`。正常离场时，`close` 跟随覆盖令牌后实际运行的过渡。CSS 禁用过渡或取消过渡时完成结算，运行中开启减少动态效果时立即结算，外部移除及卸载后无迟到事件。 | Vue 单测覆盖定时器、重复输入和卸载。Chromium 在确定的入场进度触发关闭，采样切换前后的 `opacity` 与 `transform`，覆盖退出令牌修改、系统偏好切换及取消过渡。 |
| 通知列表 | Message 删除首项或中间项时，离场项从原位置开始淡出，保留项在离场期间开始移动，离场结束时无二次跳位。连续新增与移除后位置正确，窄屏长文能换行，关闭按钮保持可见。关闭最后一条且离场时长超过空闲回收宽限期时，容器至少存续到离场结束。减少动态效果时直接呈现最终布局。 | 扩展 Message 布局浏览器用例，在离场前、期间和结束后采样边界及过渡状态。通过无活跃宿主的消息验证容器回收，覆盖连续增删及减少动态效果。 |
| 通知焦点 | Toast 和 Message 出现及外部焦点下的自动到期均保留页面焦点。焦点在即将离场的通知内时，按定义的次序移动到可用落点，后续 Tab 或 Shift+Tab 可继续操作。离场项与关闭控件退出命中和 Tab 顺序。 | 浏览器用键盘覆盖关闭按钮和 Toast 的 Escape 路径，并覆盖焦点在项内时的自动到期。断言 `document.activeElement`、Tab 顺序及指针命中，验证多条、最后一条及减少动态效果三种场景。 |
| 数字续接 | `0 → 100` 中途改到 `200` 时从上一读数继续，目标低于当前值时从同一读数反向。窄容器内从多位数改到个位数时，续接首帧与后续读数完整可见，段内缩放稳定，结算后按目标重算。覆盖负值、小数、同批更新 `from/to` 与运行中修改 `duration`，最新段 `complete` 仅一次。 | Counter 单测控制帧时钟，断言读数、时长变更前后进度、手动控制、减少动态效果与卸载清理。Chromium 用窄容器验证可见数字边界在裁剪区域内，并检查段内及结束时的缩放比例。 |
| 链接与箭头 | 同色正文中的真实 `<a>` 在静止及触屏无悬停状态下仍可凭下划线识别。鼠标悬停和键盘焦点增强下划线，反向从当时的颜色继续，减少动态效果时立即切换。Tab 聚焦当帧已有可见焦点环，强制颜色下仍可辨。文本、边框盒和命中区域位置稳定，`asChild` 保留链接节点、可访问名称及 Enter 激活语义。禁用或加载的 Button 按现有语义处理输入，箭头保持在装饰区域且不计入可访问名称。 | Chromium 以同色正文中的真实链接和 Breadcrumb 链接覆盖输入方式、焦点样式、元素边界和可访问名称。Safari 检查中英文长标签、窄容器换行、首次显示与字体加载，确认每行下划线对齐文本。 |
| 主题与几何 | 浅色、深色及自定义主题下下划线和焦点可辨，强制颜色下焦点仍可见。普通 Button 实体盖影按压、Breadcrumb 实体标签、集合行稳定几何仍符合视觉系统。 | 用现有交互和主题用例检查代表组件并人工复核对应文档示例。 |
| 分发与成本 | 各消费路径使用本次发行的配套样式和组件。四个时长令牌的默认值与计算值相符，消费方覆盖后按覆盖值运行。公开入口和依赖声明一致。Button 按需打包通过现有 22 KB 门禁，完整 CSS 与 ESM 体积记录差异。 | 在 U1 安装并导入候选 npm 产物。在 C1 用候选 CLI 执行 `init`，从候选 Registry 安装受影响组件。分别渲染通知与链接，读取计算时长并观察进出场、重排和 `close` 顺序，再运行已有包体校验。 |

浏览器检查以项目现有 Chromium 配置执行断言，Safari 的换行和字体验收单独记录浏览器、系统版本与结果。自动化测试优先读取事件、布局或计算样式，避免用固定等待代替动画完成条件。[浏览器配置](../../../packages/ui/vitest.browser.config.ts)、[测试与打包命令](../../guides/COMMANDS.md)

每阶段运行对应的 UI 单测或浏览器用例。涉及样式、令牌与双轨分发的交付运行 `pnpm check:contracts`、`pnpm check:generated`、`pnpm test:consumers` 和现有包体校验。文档运行 `pnpm check:docs`。按通知、Counter、链接分成可独立审查的变更。全部落地并通过验收后按治理流程归档本方案。[文档治理与归档](../../guides/DOC_GOVERNANCE.md)
