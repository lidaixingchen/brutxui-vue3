## 一、 背景与第一性原理

### 1. 现状痛点与系统性张力

在 BrutxUI 现有代码库中，主题（Theme）与设计令牌（Design Tokens）的流转链路存在三套分裂的实现与维护路径：

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│                          当前主题链路三套分裂现状                           │
├─────────────────────────────────────────────────────────────────────────────┤
│ 1. 唯一权威源: packages/shared/src/design-tokens.ts                         │
│    └─ 派生 styles.css 的 @theme / :root / .dark (经 generate-styles-tokens) │
│                                                                             │
│ 2. CSS 手写预设 (审查报告 §10.5):                                            │
│    └─ styles.css 的 .theme-pastel / .theme-mono / .theme-warm (无生成标记)   │
│                                                                             │
│ 3. JS 运行时两套手抄副本 (审查报告 §10.4 / §13.1):                           │
│    ├─ packages/ui/src/themes/index.ts (default/dark/highContrast/minimal)   │
│    └─ packages/ui/src/lib/theme-variables.ts + theme-editor.ts (约 1600 行) │
└─────────────────────────────────────────────────────────────────────────────┘
```

1. **JS 冗余层零生产消费者，徒增维护负担（审查报告 §10.4 / §13.1）**：
   - `src/themes/index.ts` 维护的 `defaultTheme / darkTheme / highContrastTheme / minimalTheme` 命名与 `useTheme` 运行时（`classic / pastel / mono / warm`）完全脱节，`minimal` 与 `high-contrast` 在 CSS 中根本没有对应的 `.theme-*` 类；
   - `theme-variables.ts` 与 `theme-editor.ts` 包含约 1600 行复杂类型与运行时方法（如 `createThemeEditor`、`themeVariablesToCssVars`、深合并逻辑等），全库仅有其自带的单测引用，主入口未提供生产组件依赖，却在 `package.json` 子路径暴露，形成虚假的公共 API 承诺与原型污染隐患（§13.4）。
2. **CSS 预设处于生成链外，存在漂移风险（审查报告 §10.5）**：
   - [styles.css](../../packages/ui/src/styles.css) 中的 `.theme-pastel / .theme-mono / .theme-warm` 位于生成标记之外，未纳入构建期自动派生，增删令牌时需人工多处同步。
3. **Warm 与历史 Pastel dark 主题白字前景违反 WCAG AA 对比度（审查报告 §14）**：
   - `theme-warm` light 模式下大量使用 `#FFFFFF` 白字叠加在高明度暖色背景上（如按钮 Primary `#E8722A` / `#FFFFFF` 对比度仅 3.1:1，Info `#D4956A` / `#FFFFFF` 仅 2.5:1，Success `#7B8B3A` / `#FFFFFF` 仅 3.8:1），dark 模式下的 Destructive `#E74C3C` / `#FFFFFF`（3.8:1）同样未达 4.5:1。
   - 历史 `theme-pastel` dark 模式同样采用白字叠加在中明度背景上（Primary `#8a739b` / `#ffffff` 对比度 4.20:1，Secondary `#6e8e88` / `#ffffff` 仅 3.45:1，Success `#678465` / `#ffffff` 仅 3.99:1），均低于 WCAG AA 4.5:1 标准。
   - 相比之下，Base 与 Mono 主题的前景均统一采用深色（`#000000` / `#1e1e24`）达成 AA，需对 Warm 与 Pastel dark 进行统一治理。
4. **缺少自动化对比度与 Fallback 门禁（审查报告 §10.7 / §14）**：
   - [theme-fallbacks.ts](../../packages/ui/src/lib/theme-fallbacks.ts) 因 Registry 自包含约束硬编码色值，缺少与 shared `BASE_THEME.light` 的交叉断言；
   - 缺乏对全主题、全模式下的文字与背景对比度自动化回归拦截。

## 二、 目标与重构原则

1. **唯一真相原则（Single Source of Truth）**：
   - `packages/shared/src/design-tokens.ts` 作为全仓唯一令牌事实来源。
   - 彻底删除 JS 层的两套孤立主题系统（`src/themes/`、`src/lib/theme-variables.ts`、`src/lib/theme-editor.ts`），清理入口 re-export 与 dead package 入口，释放 ~1600 行无用代码。
2. **CSS 预设全面生成化（Deterministic Generation）**：
   - 将 `.theme-pastel`、`.theme-mono`、`.theme-warm` 预设数据上收或统一至生成链数据模型，由 `generate-styles-tokens.ts` 自动注入 [styles.css](../../packages/ui/src/styles.css)。
3. **无障碍对比度达标（Accessibility Compliance）**：
   - Warm 主题前景统一修正为深色（`#2D1810` / `#1A1410` 等），Pastel dark 采用明亮底色 + 深色前景（`#16161e`），确保所有主题在所有模式下的文字前景/背景对比度均严格 $\ge 4.5:1$（WCAG AA）。
4. **全链路门禁守护（Guarded by CI）**：
   - 新增全主题 × 全模式对比度不变量自动化测试；
   - 补齐 `theme-fallbacks.ts` 交叉校验测试；
   - 联动已有的 `check-brutalist-tokens` 门禁确保 CLI 与 UI 产物零漂移。

> 生成器仅按 `ThemePresetOverrides` 中显式定义的 key 序列化 `--brutal-*` 属性。`:root` 中生成的 `--brutal-*-subtle` 与 `--shadow-brutal-*` 派生变量直接引用运行时 `var(--brutal-*)`，在应用 `.theme-*` 时由浏览器动态联动，预设块内无需冗余发射派生变量。

### 4. 自动化测试与 CI 门禁建设

#### 4.1 全主题对比度不变量测试 (`packages/ui/src/test/theme-contrast.test.ts`)

编写自动化测试脚本，利用色彩亮度公式（相对亮度 $L = 0.2126 R + 0.7152 G + 0.0722 B$）自动遍历：
- `BASE_THEME` (light / dark)
- 所有预设主题（`pastel`、`mono`、`warm`）的 light / dark 模式
- 针对每一组语义对（`primary / primaryForeground`、`secondary / secondaryForeground`、`accent / accentForeground`、`destructive / destructiveForeground`、`success / successForeground`、`info / infoForeground`、`status* / status*Foreground`、`fg / bg`）
- 严苛断言：$\text{ContrastRatio} \ge 4.5$（大文本/装饰除外，正文全部满足 AA）。

#### 4.2 Fallback 交叉校验测试 (`packages/ui/src/test/theme-fallbacks.test.ts`)

断言 [theme-fallbacks.ts](../../packages/ui/src/lib/theme-fallbacks.ts) 中的 `FALLBACK_PRIMARY_COLOR`、`FALLBACK_SECONDARY_COLOR`、`FALLBACK_FG_COLOR` 等常量与 `BASE_THEME.light` 对应键值完全相等，防止单侧修改导致分叉。
