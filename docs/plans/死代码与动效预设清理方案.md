## 一、 背景与第一性原理

### 1. 现状痛点

在 BrutxUI 早期快速迭代中，引入了部分无生产消费者、仅内部或单测引用的工具函数、全局 CSS 动画预设以及实验性组合式函数：

1. **公共主入口导出面过宽（审查报告 §6.1）**：
   - [src/index.ts](../../packages/ui/src/index.ts) re-export 了大量仅文件内部自调用或专用子路径消费的函数与类型（如 `color.ts` 的底层转换算法、`date.ts` 的 ISO 周数计算、`devtoolsPlugin` 及其关联类型、`mergeLocale` 等）。
   - 形成不必要的公共 API 面承诺，增加了消费者的学习认知负担和打包分析成本。
2. **全局 CSS 动画预设 90%+ 处于死亡状态（审查报告 §6.2）**：
   - [styles.css](../../packages/ui/src/styles.css) 中声明了 14 个 `animate-brutal-*` 类名、14 组 `@keyframes`、6 个延时与重复辅助类（`.animation-delay-*` / `.animation-once` / `.animation-infinite`）以及媒体查询中 14 条 `prefers-reduced-motion` 禁用规则；
   - 经全仓组件扫描，**仅 `Badge.vue` 消费了 `animate-brutal-badge-pulse`**，其余 13 个动画类（如 `shake`、`bounce`、`flip`、`jello` 等）及辅助类在组件库内部零生产引用（组件实际统一使用 Tailwind 内置的 `animate-pulse` / `animate-spin` / `animate-bounce` 等）；
   - 产生无意义的 CSS 产物体积开销。
3. **HardcoreInput 动效双实现（审查报告 §6.2）**：
   - `HardcoreInput.vue` 内部 scoped 自行定义了 `@keyframes input-shake` 与 `:deep(.animate-shake)`，与全局的 `animate-brutal-shake` 重复冗余。
4. **组合式函数 useAnimation 零组件消费（审查报告 §6.2）**：
   - [useAnimation.ts](../../packages/ui/src/composables/useAnimation.ts) 尝试在 JS 层通过 `useReducedMotion` 拦截动画类名，但全库组件均直接通过 CSS 媒体查询或原子类实现无障碍动效降级，`useAnimation` 零组件消费，且其 SSR Hydration 时保守返回空类名的机制容易引发 class 不匹配警告。

## 三、 详细设计与改动清单

### 1. 公共导出面清理

对公共主入口 `packages/ui/src/index.ts` 及聚合桶 `src/lib/index.ts` 进行精确裁剪：

| 分组 | 移除项（值 + 类型） | 定义源文件 | 理由与现状 |
| :--- | :--- | :--- | :--- |
| **color.ts (5)** | `rgbToHsv`、`rgbToHsl`、`hslToRgb`、`hexToHsv`、`hexToRgb` | `src/lib/color.ts` | 仅内部高层颜色解析器自调用，无需对外暴露底层转换函数 |
| **date.ts (1)** | `getISOWeekNumber` | `src/lib/date.ts` | 仅内部 `formatDate` / `parseFormattedDate` 算法消费 |
| **devtools (3+6)** | **函数/常量 (3)**：`devtoolsPlugin`、`setupDevtools`、`useDevtools`<br>**类型 (6)**：`DevtoolsPluginOptions`、`BrutxUIDevtoolsContext`、`EventLogEntry`、`PerformanceEntry`、`DevtoolsComponentMeta`、`PerformanceReport` | `src/lib/devtools-plugin.ts` | 内部开发调试插件，不占主入口公共命名空间 |
| **locales (1)** | `mergeLocale` (主入口 re-export) | `src/locales/index.ts` | 统一规范：语言包工具全部走 `brutx-ui-vue/locales` 子路径，消除主入口重复导出 |
| **themes (已落地)** | `themes`、`defaultTheme`、`darkTheme`、`highContrastTheme`、`minimalTheme`、`getPresetThemeNames`、`getPresetTheme`、`createCustomTheme` | `src/themes/index.ts` | *已在《主题系统三套合一方案》中连同目录完成清理* |

> [!NOTE]
> `color.test.ts`、`date.test.ts`、`devtools-plugin.test.ts` 均通过相对路径（如 `../color`）直接引入底层方法进行单测，裁剪公共入口不会破坏底层算法的测试覆盖。

---

### 2. 全局动效预设与 Keyframes 裁剪

在 [packages/ui/src/styles.css](../../packages/ui/src/styles.css) 中清理冗余 CSS 规则：

#### 2.1 删除的 13 个死动效类、Keyframes 与 6 个辅助类
- **移除 13 个动画类**：`.animate-brutal-shake`、`.animate-brutal-bounce`、`.animate-brutal-pulse`、`.animate-brutal-flip`、`.animate-brutal-slide-up`、`.animate-brutal-slide-down`、`.animate-brutal-slide-left`、`.animate-brutal-slide-right`、`.animate-brutal-pop`、`.animate-brutal-rotate`、`.animate-brutal-swing`、`.animate-brutal-jello`、`.animate-brutal-heartbeat`。
- **移除对应 13 组 `@keyframes`**：`brutal-shake`、`brutal-bounce`、`brutal-pulse`、`brutal-flip`、`brutal-slide-up`、`brutal-slide-down`、`brutal-slide-left`、`brutal-slide-right`、`brutal-pop`、`brutal-rotate`、`brutal-swing`、`brutal-jello`、`brutal-heartbeat`。
- **移除 6 个延时与重复辅助类**：`.animation-delay-100`、`.animation-delay-200`、`.animation-delay-300`、`.animation-delay-500`、`.animation-once`、`.animation-infinite`。
- **移除 `@media (prefers-reduced-motion)` 列表中的对应 13 条选择器**。

#### 2.2 保留项
- **保留** `.animate-brutal-badge-pulse` 与 `@keyframes brutal-badge-pulse`（`Badge.vue` 呼吸微标组件强依赖）。
- `HardcoreInput.vue` 保持其 scoped 私有 `input-shake` / `bounce-short` / `fade-in` 实现，消除双轨混淆。
