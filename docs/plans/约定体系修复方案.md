# 约定体系修复方案

> 依据：《[约定与代码裁决审查报告](../reports/约定与代码裁决审查报告.md)》归纳的 7 条系统性弱点；本方案按 7 弱点逐条给出具体改动，并含跨条依赖、执行顺序与优先级
> 范围：仅修复约定体系自身（文档措辞 + 令牌补全 + 自动化兜底）；C1-C8 组件代码修复在裁决报告，不在本方案，本方案只纳入"让规则成立所需的配套最小代码改动"

## 概述

本方案对约定体系（docs/guides 文档 + 支撑令牌 + 校验脚本）的 7 条系统性弱点做综合修复，遵循四条主线：

1. **约定措辞修订**——把 5 条被裁决实证的合法例外写进绝对禁令（WW1），并按"单一权威、其余只引用"重构 CVA.md 与多 guide 重复规则（WW4）；
2. **机制说明文档**——新建 `tailwind-v4-mechanisms.md` 作为 Tailwind v4 四机制（`--tw-outline-style` 元素级变量 / twMerge 同组静默移除 / @utility 变体 / @source 字面量）的唯一权威出处，规则文本只引用不抄写（WW2）；
3. **令牌补全**——补齐缺失的 `--brutal-status-*` 家族、`--shadow-brutal-destructive`、`border-brutal-dashed`，让"规则只剩禁令没有正资产"变成"有给有禁"（WW1/WW5）；
4. **自动化兜底**——以 check-class-literals / check-deprecated-utilities / check-doc-template / check-guide-conventions / check-guide-refs / commitlint 六道门禁把每条规则变成可 grep 落地、可防回潮的硬约束（WW6/WW4/WW7）。

执行分 6 阶段：事实核验 → 机制文档与引用面 → 约定措辞 → 令牌与迁移 → 门禁与 CI → 收尾回归。

## 指导原则

1. **先修会让按图施工者系统性回退的部分**：CVA.md 过期蓝图（ring 焦点/硬编码前景/缺 rounded-brutal，与 R3/R6/R7 直接矛盾）是净质量最大拖累，优先级最高。
2. **单一权威源**：机制解释以 tailwind-v4-mechanisms.md 为唯一出处；视觉规则以 VISUAL_SYSTEM R1-R7 为唯一权威；过渡以 COMPONENT_GUIDE r13 为唯一权威；其余 guide 只引用不抄写。
3. **每条规则可 grep 落地**：规则措辞必须能被命令断言（例外关键词、措辞回归、门禁脚本），避免"规则在、代码违、无处查"。
4. **机制说明先行**：一切规则措辞修订都建立在已核验的机制事实上（twMerge 复现、产物 grep、字节序实证），先证后写。
5. **令牌先于规则**：规则里引用的令牌/工具类必须先落地，否则规则不可执行、门禁无收敛目标。
6. **门禁基线兜底而非阻断存量**：防回潮门禁用基线快照放行既有债（对应裁决 C1-C8），只拦新增；债清零后再收基线。
7. **规则向现实靠拢而非放松标准**：r04/r13 的弱化是"知行合一"的精确化，例外条款必须写死边界，防止被滥用。
8. **同一文件多段改动串行合入**：被多条弱点共改的文件按文件顺序一次性合入，避免并发编辑冲突。

## WW2：Tailwind v4 四机制单一权威说明（tailwind-v4-mechanisms.md）

### 修复改动

**新建 docs/guides/tailwind-v4-mechanisms.md（全文，机制唯一权威）**

> 版本基线：Tailwind CSS ^4.3（packages/ui/package.json）、tailwind-merge ^3.6.0、cn() = twMerge(clsx(...))。凡规则文本引用本文件的机制，解释一律以本文件为准，其它 guide 只引用、不重复抄写。

**§1 `--tw-outline-style` 是元素级变量（@property inherits:false）**

```css
@property --tw-outline-style { syntax: "*"; inherits: false; initial-value: solid; }
```

inherits:false 两个后果：① 变量不跨元素继承，只作用于设置它的元素；② 未显式设置的元素读取得到 initial-value: solid。outline 工具类拆写（产物实证）：`outline-none` 写 `--tw-outline-style:none + outline-style:var(--tw-outline-style)`（重置该变量）；`outline-<n>` 只写 `outline-style:var(--tw-outline-style) + outline-width:<n>`（不重置）；颜色类只写 outline-color。陷阱：同一元素 outline-none 与 outline-<n> 并存时，outline-<n> 读到被置 none 的变量 → 焦点环静默不渲染；`focus-visible:outline-2` 不把 style 恢复为 solid。twMerge 不帮忙（不同类组，两保留）。不跨元素：内层 outline-none 不泄漏到容器，容器 focus-within:outline-2 与内层 focus:outline-none 互不干扰。推论规则：承载焦点 outline 的元素不得带任何 outline-none；合法例外仅一种（容器 focus-within 方案的内层 input/textarea）；不可聚焦元素上的惰性 outline-none 属死类按 C1 裁决删除。

**§2 twMerge 同组静默移除**

transition 族（transition、transition-none、transition-all、transition-colors、transition-opacity、transition-shadow、transition-transform、transition-[...]）同属一组，后写者胜、先写者被静默移除。实证：`node --input-type=module -e "import { twMerge } from 'tailwind-merge'; console.log(twMerge('transition-all duration-150','transition-[transform,box-shadow]'))"` → `duration-150 transition-[transform,box-shadow]`。推论规则：同一交互元素只声明一份 transition；组件 base 声明 transition-all 又被 WithTransition 变体经 cn() 拼接时，源码里的 transition-all 是死类；需要更多属性过渡用完整属性列表任意值覆盖而非 transition-all。

**§3 @utility vs 普通 @layer utilities 的变体支持**

只有被工具引擎注册的类才支持变体，注册途径仅 @theme 令牌派生与 @utility 指令。普通 @layer utilities 手写类不进工具引擎，带变体写法（hover:border-brutal、data-[highlighted]:border-brutal）被静默丢弃（dist 实证 0 命中，全库 6+ 处引用）。规则：需要变体支持的自定义工具类必须用 @utility 或 @theme 派生；禁止写带变体的手写 @layer utilities 类。现状与迁移方向：styles.css:50-55 的 @utility shadow-brutal* 已合规；styles.css:327-334 的 .border-3（与 Tailwind 生成同值冗余，C4 待删）与 .border-brutal 为手写类，推荐将 .border-brutal 改为 @utility（使 6+ 处 hover:border-brutal 复活）。

**§4 @source 静态扫描字面量要求**

styles.css:5-6 声明 @source "../**/*.vue" 与 "../**/*.ts"，Tailwind 按源码字面量逐个匹配，无法从 ${expr} 动态拼接推断。规则：每个类名必须是完整字面量；允许「完整字面量常量 + ${} 组合」但每个片段本身须为完整字面量；禁止字面量缺一截的拼接（如 `h-[var(--sep-thickness,${DEFAULT_THICKNESS})]`，C6 separator 案例）。验证：`grep -rnE '\$\{' packages/ui/src` 逐一核验 + 构建后 grep 产物抽查。
