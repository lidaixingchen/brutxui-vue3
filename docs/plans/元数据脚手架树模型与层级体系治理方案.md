## 一、方案背景与治理目标

在 BrutxUI Vue 3 的持续演进中，工程基础设施与类型/样式体系暴露出三个深层次的架构断裂点：

1. **元数据与脚手架双轨脱节**：`pnpm generate:component` 仅生成组件文件与 UI 导出，未同步更新 `packages/shared/src/components.ts`（全库组件清单单一源头），导致新组件无法被 CLI `add` 与 VitePress 文档侧边栏感知。
2. **树节点类型多头定义**：`TreeView` 与 `TreeSelect` 分别独立定义了高度重叠的 `TreeNode<T>` 接口，在全库导出时被迫使用 `TreeSelectTreeNode` 别名，造成领域模型割裂与数据跨组件传递障碍。
3. **Z-Index 层级尺度多头信源与去重失效**：声明式浮层（`z-50`）、命令式弹窗（`1000 + 10` 步进）与全局高层浮层（`9998 ~ 10010`）缺乏统一阶梯；同时 `tailwind-merge` 默认不识别非数字的自定义 `z-*` 类，导致外部传入的覆盖类无法正常去重。

### 治理目标

- **元数据闭环自动化**：脚手架生成组件时原子化写入 `packages/shared/src/components.ts`，自动维护字母序与默认合法元数据，保证单一源头不被破坏。
- **树模型统一**：收拢构建单一 `TreeNode<T>` 领域模型，彻底废弃 `TreeSelectTreeNode` 别名，实现树形数据的无缝互通与组件级重导出。
- **Z-Index 阶梯化、令牌化与去重闭环**：建立确定性的 5 级 Z-Index 阶梯与复合浮层子层级，将层级收敛至 `design-tokens.ts`，全量派生 Tailwind `@theme`、`tailwind-merge` 类组配置、CLI 模板与 TS 运行时常量，消除硬编码魔法数字与类名冲突。

## 二、详细设计与实施方案

### 1. 脚手架与组件元数据单一源头自动同步 (Metadata Sync Engine)

#### 1.1 架构设计

在 `packages/ui/scripts/scaffold/` 模块中引入 `MetadataManager`，负责对 `packages/shared/src/components.ts` 进行幂等、类型安全的结构化注入。

```
packages/ui/scripts/scaffold/
├── scaffold-engine.ts       # 脚手架编排主引擎（仅在 type === 'component' 时触发元数据同步）
├── barrel-manager.ts        # UI index.ts 导出注入器
├── metadata-manager.ts      # [NEW] shared/src/components.ts 元数据注入器
└── metadata-manager.test.ts # [NEW] 元数据管理器单元测试（覆盖首位/中间/尾部插入与 dry-run）
```

#### 1.2 注入规则与 AST 解析算法

当运行 `pnpm generate:component <Name>` 时，`MetadataManager` 按以下规范生成条目：

```ts
    '<kebab-name>': {
        titleZh: '<PascalName> 组件',
        category: 'utility',
        dependencies: ['reka-ui', '@lucide/vue'],
        description: '<PascalName> component description.',
    },
```

- **AST 定位与行切片插入（Deterministic Line-Slice Insertion）**：
  1. 通过 `ts.createSourceFile` 解析 `packages/shared/src/components.ts`，定位到 `COMPONENTS` 变量声明的 `ObjectLiteralExpression` 节点。
  2. 遍历其 `properties`（`PropertyAssignment`），提取每个键的字符串字面量（如 `'accordion'`, `'button'`）。
  3. 检索首个 ASCII 字母序大于 `<kebab-name>` 的已有属性节点，获取其 `getFullStart()` 位置作为插入锚点；若不存在则插入至最后一个属性节点之后。
  4. 使用行切片（Line-slice）无损拼接新生成的代码块，严格保持 4 空格缩进、单引号与末尾逗号，不触发 AST 全量重印，完整保留既有注释与空行。
- **VFS 适配**：依赖 `brutx-shared-vue/fs` 的 `FileSystemAdapter` 接口，支持纯内存测试与 `--dry-run` 模式。
- **幂等防护**：若已存在同名组件键，则安全跳过并发出提示，严禁覆盖既有元数据。

### 2. TreeNode 跨组件领域模型统一 (Unified Tree Node Domain Model)

#### 2.1 统一领域接口定义

在 `packages/ui/src/types/tree.ts` 中建立全库统一的树节点接口，作为唯一事实来源：

```ts
/**
 * BrutxUI 统一树节点数据模型
 */
export interface TreeNode<T = unknown> {
    /** 节点唯一标识 */
    id: string;
    /** 节点显示文本 */
    label: string;
    /** 节点图标（Lucide 图标名或自定义图标类名） */
    icon?: string;
    /** 子节点列表 */
    children?: TreeNode<T>[];
    /** 自定义业务数据载荷 */
    data?: T;
    /** 是否禁用交互 */
    disabled?: boolean;
    /** 是否叶子节点（异步懒加载场景下为 true 则不渲染展开图标） */
    isLeaf?: boolean;
    /** 懒加载子节点是否已加载完毕 */
    loaded?: boolean;
    /** 懒加载是否处于请求中 */
    loading?: boolean;
    /** 过滤搜索时是否隐藏 */
    hidden?: boolean;
}

export type SelectionMode = 'single' | 'checkbox';
```

#### 2.2 组件消费与导出契约

1. **`TreeView`**：
   - 基础类型从 `@/types/tree` 导入；`components/tree-view/types.ts` 重新导出 `export type { TreeNode, SelectionMode } from '@/types/tree'`，并保留组件专属 Props/Emits 类型。
2. **`TreeSelect`**：
   - `components/tree-select/tree-select-types.ts` 移除冗余的 `TreeNode` 定义，改为 `export type { TreeNode } from '@/types/tree'`。
3. **`packages/ui/src/index.ts`**：
   - 统一顶层导出：`export type { TreeNode, SelectionMode } from './types/tree'`
   - 彻底废弃并移除 `export type { TreeNode as TreeSelectTreeNode }` 别名（破坏式变更）。
4. **文档与 Demo 迁移**：
   - 更新 `apps/docs/components/tree-select.md` 与 `TreeSelectDemo.vue`，统一使用 `TreeNode`。

### 3. Z-Index 全局层级阶梯与设计令牌体系化 (Z-Index Scale Architecture)

#### 3.1 五级全局层级尺度标准与复合子层级

建立全库统一的 Z-Index 标尺，所有层级划分具有明确的物理边界、堆叠逻辑与复合浮层子层级：

| 层级 | 区间与基准 | 令牌名称 | 对应数值 | 适用组件与场景 |
| :--- | :--- | :--- | :--- | :--- |
| **Layer 1: Inline / Sticky** | `z-10 ~ z-40` | `sticky`<br>`header` | `10`<br>`40` | 表格冻结列 (`z-sticky`)、粘性表头 (`z-sticky`)、页面固定导航 (`z-header`)、BeforeAfter 滑块 |
| **Layer 2: Popper / Dropdown** | `z-100 ~ z-200` | `popover`<br>`dropdown`<br>`tooltip` | `100`<br>`100`<br>`200` | Popover、DropdownMenu、Select 下拉列表、Cascader 浮层、Tooltip 提示框 |
| **Layer 3: Overlay / Dialog** | `z-1000 ~ z-2000` | `dialog` | `1000` | 声明式与命令式 Dialog、AlertDialog、Sheet、MessageBox（命令式弹层以 1000 为基准、步长 10 自增） |
| **Layer 4: System / Guide / Preview** | `z-9000 ~ z-9200` | `tour-canvas`<br>`tour-popover`<br>`preview-overlay`<br>`preview-control`<br>`loading` | `9000`<br>`9001`<br>`9100`<br>`9101`<br>`9200` | 全屏 Loading 遮罩 (`z-loading`)、Tour 导览画布 (`9000`) 与卡片 (`9001`)、ImagePreview 大图预览背景 (`9100`) 与控制条 (`9101`) |
| **Layer 5: Top Notification** | `z-10000+` | `toast`<br>`message` | `10010`<br>`10010` | 全局 Toast 容器、Message 浮动通知，置于视口最高层 |

#### 3.2 单一事实来源 (SSOT) 全链路同构派生设计

全库 Z-Index 令牌在 `packages/shared/src/design-tokens.ts` 中定义，并通过自动化编译器同构派生到 UI、CLI 与运行时：

```
                    packages/shared/src/design-tokens.ts
                     (Z_INDEX_TOKENS / BRUTAL_Z_INDEX_NAMES)
                                       │
        ┌──────────────────────────────┼──────────────────────────────┐
        ▼                              ▼                              ▼
【样式与主题编译】              【类名去重与工具函数】           【CLI 模板与同构样式】
packages/ui/scripts/compiler/  packages/ui/src/lib/utils.ts   packages/cli/src/lib/constants.ts
token-style-compiler.ts        ├── 注入 BRUTAL_Z_INDEX_NAMES   ├── UTILS_TEMPLATE (同步注入 z-index 类组)
        │                      └── extendTailwindMerge 配置   packages/cli/src/styles/brutalist.css
        ▼                           classGroups.z 冲突去重    └── 注入 @theme / :root z-index 变量
packages/ui/src/styles.css                     │                              │
├── @theme (--z-index-*)                       ▼                              ▼
└── :root / .dark              packages/ui/src/lib/z-index.ts  CLI 用户项目 (pnpm brutx init / add)
                               └── TS 运行时常量 (供命令式浮层/Tour/Preview 消费)
```

#### 3.3 `tailwind-merge` 自定义 Z-Index 冲突去重机制

##### 机制原理
在 Tailwind v4 中，`--z-index-*` 派生出的类名为 `z-dialog`、`z-popover` 等。但 `tailwind-merge` 默认仅将数字、`auto` 或任意值判定为 `z` 冲突组。若不显式扩展 `classGroups.z`，调用方传入覆盖类时（如 `cn('z-dialog', 'z-50')`）两者将被同时保留，导致层级覆盖失效。

##### 实现规范
1. 在 `packages/shared/src/design-tokens.ts` 导出 Z-Index 名称数组：
   ```ts
   export const BRUTAL_Z_INDEX_NAMES = Object.freeze([
       'sticky',
       'header',
       'popover',
       'dropdown',
       'tooltip',
       'dialog',
       'tour-canvas',
       'tour-popover',
       'preview-overlay',
       'preview-control',
       'loading',
       'toast',
       'message',
   ] as const);
   ```
2. 在 `packages/ui/src/lib/utils.ts` 与 `packages/cli/src/lib/constants.ts` 中注册 `classGroups.z`：
   ```ts
   /* @brutx:z-index-names:start */
   const BRUTAL_Z_INDEX_NAMES = ['sticky', 'header', 'popover', 'dropdown', 'tooltip', 'dialog', 'tour-canvas', 'tour-popover', 'preview-overlay', 'preview-control', 'loading', 'toast', 'message'];
   /* @brutx:z-index-names:end */

   const customTwMerge = extendTailwindMerge({
       extend: {
           theme: {
               color: [...BRUTAL_COLOR_NAMES],
           },
           classGroups: {
               z: [{ z: [...BRUTAL_Z_INDEX_NAMES] }],
           },
       },
   });
   ```

## 四、验证与验收标准

### 1. 自动化测试与 CI 门禁
- **令牌派生一致性（Zero Drift）**：
  ```bash
  pnpm --filter brutx-ui-vue prebuild:tokens -- --check
  ```
- **类名合并冲突去重验证**：
  在 `packages/ui/src/lib/utils.test.ts` 中验证 `cn('z-dialog', 'z-50') === 'z-50'` 与 `cn('z-popover', 'z-dialog') === 'z-dialog'`。
- **脚手架元数据注入验证**：
  ```bash
  pnpm --filter brutx-ui-vue test scripts/scaffold/metadata-manager.test.ts
  ```
- **Registry 元数据校验**：
  ```bash
  pnpm --filter brutx-registry-vue validate
  ```

### 2. 静态检查与文档链接
- **类型检查**：`pnpm --filter brutx-ui-vue typecheck` 零错误；`TreeView` 数据直接传入 `TreeSelect` 享受完全类型推导。
- **文档有效性**：运行 `node scripts/docs/check-doc-links.mjs check` 确保 0 死链。

### 3. 视觉与层级交互验证
- 混合打开声明式 Dialog 与命令式 Dialog / MessageBox 时，层级按调用栈确定性递增，无穿透遮挡。
- Loading 遮罩 (`z-loading` / 9200) 位于 Dialog 之上，Toast / Message (`10010`) 位于最顶层。
