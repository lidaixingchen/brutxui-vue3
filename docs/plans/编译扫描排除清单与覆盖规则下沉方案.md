## 一、 背景与第一性原理

### 1. 现状痛点分析

在现行代码库中，组件依赖扫描与注册表编译涉及以下关键事实与契约：
- `LIB_EXCLUDE`：排除不应纳入独立注册表/分发包的工具文件（如 `utils.ts`，消费者在 `init` 时生成本地版本）；
- `MANIFEST_OVERRIDES`：补充纯 AST 静态分析无法通过 `import` 关系自动发现的约定式运行时依赖（如 `loading` 指令随 `Loading.vue` 分发）。

然而，这一组跨包通用的元数据与处理逻辑曾被定义在 `packages/ui/scripts/manifest-shared.ts` 中：

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│                       当前 Monorepo 依赖 Seam 破坏现状                       │
├─────────────────────────────────────────────────────────────────────────────┤
│ packages/shared (原 Seam 承担者)                                            │
│   └─ scan.ts (只导出了 scanComponentFiles 等 AST 工具，缺少核心排除与覆盖规则)│
│                                                                             │
│ packages/ui                                                                 │
│   └─ scripts/manifest-shared.ts (私有脚本目录存放了核心共享元数据)           │
│         ▲                     ▲                                             │
│         │ (合法包内引用)       │ (非法跨包跨层相对引用: ../../../ui/scripts) │
│   packages/ui/scripts         packages/registry                             │
│   (prebuild-scan.ts)          ├─ scripts/build-registry.ts                  │
│                               ├─ src/compiler/registry-compiler.ts          │
│                               └─ src/compiler/cache-manager.ts (魔法值残留)  │
└─────────────────────────────────────────────────────────────────────────────┘
```

该结构破坏了 Monorepo 的依赖分层与单一信源原则：
1. **Seam 破坏与隐式耦合**：`packages/registry` 是独立编译包，却通过 `import { LIB_EXCLUDE } from '../../../ui/scripts/manifest-shared.js'` 穿透引用了 `packages/ui` 未打包的私有脚本目录。此举打破了 `packages/shared` 作为唯一共享契约层的边界，在无源码环境或独立分发时会引发 `ERR_MODULE_NOT_FOUND`；
2. **多处魔法值与逻辑漂移风险**：`packages/registry/src/compiler/cache-manager.ts` 和 `dependency-resolver.ts` 内部存在多处手写的默认参数 `libExclude: Set<string> = new Set(['utils.ts'])`，未与单一信源绑定；
3. **调用方样板与易错性**：调用方在调用 `scanComponentFiles(options)` 得到 AST 结果后，必须手动补充调用 `applyManifestOverrides(manifest)`，一旦遗漏将导致清单数据静默残缺。

## 二、 架构重构设计

### 1. 核心下沉：`packages/shared` 作为单一信源

在 `packages/shared/src/scan-manifest.ts` 中确立所有扫描排除项与约定覆盖清单的唯一真实来源，并通过 `brutx-shared-vue/scan` 与根入口统一导出。

```typescript
// packages/shared/src/scan-manifest.ts
import type { ComponentFileManifest } from './registry-manifest.types.js';

/**
 * 默认不参与 registry 发布/哈希的 lib 目录文件清单（只读集合）。
 */
export const DEFAULT_LIB_EXCLUDE: ReadonlySet<string> = new Set(['utils.ts']);

/**
 * 约定式依赖覆盖清单：AST 扫描无法静态分析出的隐式依赖。
 * 类型收窄为实际实现的 directives 字段，若未来扩展 files/composables/lib 须同步更新实现，避免静默失效。
 */
export const DEFAULT_MANIFEST_OVERRIDES: Readonly<Record<string, Partial<Pick<ComponentFileManifest, 'directives'>>>> = {
    loading: {
        directives: ['loading.ts'],
    },
};

/**
 * 将 MANIFEST_OVERRIDES 合并进组件扫描结果（就地修改传入的 manifest）。
 */
export function applyManifestOverrides(
    manifest: Record<string, ComponentFileManifest>,
    overrides: Record<string, Partial<Pick<ComponentFileManifest, 'directives'>>> = DEFAULT_MANIFEST_OVERRIDES
): void {
    for (const [name, override] of Object.entries(overrides)) {
        if (!manifest[name]) continue;
        if (override.directives) {
            const existing = new Set(manifest[name].directives ?? []);
            for (const d of override.directives) {
                existing.add(d);
            }
            manifest[name].directives = Array.from(existing).sort();
        }
    }
}
```

### 2. 扫描器深模块内聚：`scanComponentFiles` 内置覆盖

将依赖覆盖能力内聚进 `scanComponentFiles`，消除外部调用方遗漏覆盖步骤的隐患：

```typescript
// packages/shared/src/scan-component-files.ts
import { DEFAULT_LIB_EXCLUDE, DEFAULT_MANIFEST_OVERRIDES, applyManifestOverrides } from './scan-manifest.js';

export interface ScanOptions {
    componentsDir: string;
    composablesDir: string;
    libDir: string;
    directivesDir: string;
    /** 排除的 lib 文件集合，未指定时默认使用 DEFAULT_LIB_EXCLUDE */
    libExclude?: ReadonlySet<string>;
    /**
     * 依赖覆盖清单。
     * - undefined（默认）：自动应用 DEFAULT_MANIFEST_OVERRIDES
     * - Record<...>: 应用自定义覆盖清单
     * - false: 禁用覆盖，仅返回纯 AST 扫描结果
     */
    manifestOverrides?: Record<string, Partial<Pick<ComponentFileManifest, 'directives'>>> | false;
}

export function scanComponentFiles(options: ScanOptions): Record<string, ComponentFileManifest> {
    // ... 执行 AST 扫描组装 manifest ...

    // 内聚默认覆盖行为
    if (options.manifestOverrides !== false) {
        applyManifestOverrides(manifest, options.manifestOverrides ?? DEFAULT_MANIFEST_OVERRIDES);
    }

    return manifest;
}
```

### 3. Registry 编译器层消除硬编码与全链路类型升级

1. **类型契约统一**：`CompilerOptions.libExclude`、`RegistryCompiler`、`DependencyResolver` 与 `CacheManager` 的 `libExclude` 类型全部统一为 `ReadonlySet<string>`，默认值统一指向 `DEFAULT_LIB_EXCLUDE`；
2. **消灭非法相对引用**：全量移除 `packages/registry` 对 `../../ui/scripts/manifest-shared.js` 的相对导入，全部改由 `brutx-shared-vue` / `brutx-shared-vue/scan` 导入；
3. **精简调用方样板**：`packages/registry/scripts/build-registry.ts` 的 `runPrebuildScan` 直接调用 `scanComponentFiles(options)` 即可，删除外部显式的 `applyManifestOverrides(manifest)` 调用；
4. **彻底清理废弃文件**：彻底删除 `packages/ui/scripts/manifest-shared.ts`，`packages/ui/scripts/prebuild-scan.ts` 同步移除显式覆盖调用。
