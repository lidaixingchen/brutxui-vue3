# 生成与构建机制

本文档阐明 BrutxUI 的自动化代码生成体系、设计令牌编译映射、Turbo 构建流水线与 Git 暂存区快照一致性校验机制。

---

## 一、 职责与边界：输入与生成映射

为了防止多包维护时的代码漂移并保障唯一信源，工程内部分关键产物由脚本自动投影生成。**自动生成的文件严禁手动直接编辑**。

| 唯一数据源（手写输入） | 负责编译/生成工具 | 目标生成产物（自动生成，勿手动修改） |
| --- | --- | --- |
| [`packages/shared/src/design-tokens.ts`](../../packages/shared/src/design-tokens.ts) | `pnpm generate:tokens`（底层由 `packages/ui` 与 `packages/cli` 生成器驱动） | `packages/ui/src/styles.css`（`:root` / `.dark` / `@theme` 变量块）、`packages/ui/src/preflight.css`（字体栈）、`packages/ui/src/lib/utils.ts`（`BRUTAL_COLOR_NAMES` 列表） |
| [`packages/shared/src/design-tokens.ts`](../../packages/shared/src/design-tokens.ts) | `pnpm generate:tokens`（CLI 令牌编译器） | `packages/cli/src/styles/brutalist.css`（令牌与预设标记块）、`packages/cli/src/lib/constants.ts`（`UTILS_TEMPLATE` 模板块） |
| [`packages/ui/api-contract.ts`](../../packages/ui/api-contract.ts) | `pnpm --filter brutx-ui-vue generate`（统一代码生成入口，执行契约投影） | `packages/ui/registry-manifest.json`、`packages/ui/exports-manifest.json` |
| [`packages/ui/api-contract.ts`](../../packages/ui/api-contract.ts) | `pnpm --filter brutx-ui-vue generate`（exports 生成管线） | `packages/ui/package.json` 中的 `exports` 字段 |
| [`packages/ui/api-contract.ts`](../../packages/ui/api-contract.ts) | `pnpm --filter brutx-ui-vue generate`（组件索引生成管线） | `packages/ui/src/components/*/index.ts`（各组件导出入口）及 `packages/ui/src/index.ts`（根入口） |

## 二、 令牌编译与设计系统分工

### 1. 单一事实来源
所有设计令牌（边框粗细、硬阴影偏移、基准色、圆角标尺、Z-Index 层级）统一定义在 `packages/shared/src/design-tokens.ts` 中。

### 2. 多端编译器协作
- **UI 组件库端**：通过正则与 AST 注入器，将令牌编译为 Tailwind CSS v4 标准的 `@theme` 指令与 `:root` / `.dark` 变量，直接驱动组件渲染。
- **CLI 脚手架端**：将相同的令牌注入为独立的 `brutalist.css` 模板，在用户运行 `brutx-vue init` 时动态注入到用户项目的全局样式表中。

## 三、 Turbo 编排与缓存机制

### 1. 任务依赖图谱

在 [`turbo.json`](../../turbo.json) 中，构建与生成任务编排如下：

```text
       ┌──────────────┐
       │   generate   │ (cache: false, 始终全量对比手写输入与生成物)
       └──────┬───────┘
              │
              ▼
     ┌─────────────────┐
     │ build:artifact  │ (缓存 dist 产物，输入变更时自动失效)
     └─────────────────┘
```

- **`generate` 任务**：设置为 `"cache": false`。确保任何令牌或契约改动都能实时生成最新文件并保留手写区域。
- **`build:artifact` 任务**：依赖前置的 `generate` 任务。当源码未变动时复用 Turbo 本地/云端构建缓存。
- **`brutx-registry-vue#build:artifact`**：同样保持 `"cache": false`，并依赖 `brutx-ui-vue#generate`，确保读取最新 UI 源码。

## 四、 暂存区快照检查（Staged Snapshot）

为了杜绝“本地生成了但未提交、导致 CI 产物不一致”的常见隐患，工程设计了快照一致性防御机制：

### 1. `check:staged-snapshot` 机制
- 在提交前或 pre-commit 钩子中，运行 `node scripts/generation/check-staged-snapshot.mjs`。
- 脚本直接从 Git 暂存区（Index）物化一个隔离的虚拟环境，在虚拟环境中运行生成器，并比对暂存区的生成物是否与最新输入完全一致。
- 若开发者仅修改了 `design-tokens.ts` 或 `api-contract.ts`，但忘记暂存自动生成的 CSS 或 index 文件，检查会立即熔断拦截。

### 2. 自愈与提交引导
当快照检查失败时：
1. 运行 `pnpm generate:tokens`；
2. 运行 `git diff` 审视被自动更新的文件；
3. 将受影响的文件同批执行 `git add` 并重新提交。

## 五、 源码入口与操作清单

### 1. 关键源码入口
- UI 令牌生成器：[`packages/ui/scripts/generate-styles-tokens.ts`](../../packages/ui/scripts/generate-styles-tokens.ts)（统一入口为 [`packages/ui/scripts/generate.ts`](../../packages/ui/scripts/generate.ts)）
- UI 导出生成器：[`packages/ui/scripts/generate-exports.ts`](../../packages/ui/scripts/generate-exports.ts)
- CLI 令牌同步器：[`packages/cli/scripts/generate-tokens.ts`](../../packages/cli/scripts/generate-tokens.ts)
- 快照一致性检测器：[`scripts/generation/check-staged-snapshot.mjs`](../../scripts/generation/check-staged-snapshot.mjs)
- 生成防回归测试：[`scripts/contracts/gate-equivalence.test.mjs`](../../scripts/contracts/gate-equivalence.test.mjs)

### 2. 高频操作命令

| 操作 | 命令 | 说明 |
| --- | --- | --- |
| 同步所有子包设计令牌 | `pnpm generate:tokens` | 同时驱动 UI 与 CLI 的令牌生成任务 |
| 仅生成 UI 导出与清单 | `pnpm --filter brutx-ui-vue generate` | 刷新 exports 映射与组件 index |
| 只读校验生成物一致性 | `pnpm check:generated` | 检查是否有生成物落后于手写源文件 |
| 暂存区快照一致性自检 | `pnpm check:staged-snapshot` | 模拟 Git 暂存区物化生成校验 |
