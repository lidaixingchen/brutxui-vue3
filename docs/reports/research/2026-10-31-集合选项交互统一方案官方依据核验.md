# 集合选项交互统一方案官方依据核验

核验日期：2026-10-31  
核验对象：[集合选项柠檬黄交互统一改造方案](../../archive/2026/ui/集合选项柠檬黄交互统一改造方案.md)

## 结论

方案把行尺寸、颜色和状态标记做成一致的视觉语言，方向可行。稳定布局、区分焦点与选择、使用成对语义令牌，适合本项目。Classic 使用柠檬黄属于品牌决策，其纯黑文字对比度成立。

定稿前应解决现有行为与统一状态描述之间的冲突，协调行内描边与项目焦点规范，并收窄输入模式适配范围。焦点、当前项、控件选中态和已提交业务值应按控件分别映射。

本报告把 **WCAG 2.2 成功准则**视为规范要求，把 **ARIA APG**视为 W3C 的作者实践建议；Reka UI 文档与源码只说明该库的实现契约。APG 的行为建议不是 WCAG 成功准则本身。

## 已核实依据

### WCAG 规范要求

- **键盘焦点必须可见。** WCAG 2.2 AA 的 2.4.7 要求键盘可操作界面存在键盘焦点指示器可见的操作模式，但本条不规定其形状或颜色。[WCAG 2.2 SC 2.4.7](https://www.w3.org/TR/WCAG22/#focus-visible)
- **重要状态信息需有足够对比。** AA 的 1.4.11 对用于识别控件及其状态（包括焦点、选中）的视觉信息规定相对相邻颜色至少 3:1；用户代理提供且作者未改动的外观属于例外。[WCAG 2.2 SC 1.4.11](https://www.w3.org/TR/WCAG22/#non-text-contrast)
- **文字对比度按实际前景/背景组合评估。** AA 的 1.4.3 通常要求普通大小文字至少 4.5:1，大号文字至少 3:1。[WCAG 2.2 SC 1.4.3](https://www.w3.org/TR/WCAG22/#contrast-minimum)
- **2.4.13 是 AAA 的额外焦点外观准则。** 除对比变化至少 3:1 外，还要求指示器面积至少等于未聚焦控件 2 CSS px 粗的周长面积。这里测的是聚焦/未聚焦同一像素的变化，不等同于 1.4.11 的相邻颜色对比。[WCAG 2.2 SC 2.4.13](https://www.w3.org/TR/WCAG22/#focus-appearance)
- **强制颜色模式采用用户调色板。** CSS Color Adjustment 规定 `forced-colors` 模式会把 `forced-color-adjust: auto` 元素的颜色属性映射到用户系统调色板。作者应让焦点边界及选择标记在系统颜色下仍可辨认，不能依赖柠檬黄必须保留。[CSS Color Adjustment §3](https://www.w3.org/TR/css-color-adjust-1/#forced-colors-mode)

### APG 作者实践建议

- **Listbox 与 TreeView 将焦点和选中分开处理。** 两种模式都明确说明 DOM 焦点在功能上不同于选中态；单选模式可以选择让选中跟随焦点，也可以选择不跟随，APG 提醒后者可能更适合某些操作情境。[Listbox Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/)、[Tree View Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/)
- **Combobox 不等于普通 listbox。** 可编辑 combobox 有手动选择、自动选择和行内自动补全等不同模型；其弹出列表项可随焦点成为当前建议值。APG 的 select-only 示例中，方向键只移动视觉焦点，Enter、Space 或 Tab 才设置输入值。因而应分别描述“当前建议项/`aria-selected`”与“已提交值”，不能把一个规则机械应用到全部 Combobox。[Combobox Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)、[Select-Only Combobox Example](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/examples/combobox-select-only/)
- **菜单禁用项可以获得焦点，但不能激活。** 这是 APG Menu and Menubar Pattern 的明确建议；它不同于 listbox、tree 中由各自选项导航模型处理的禁用节点。[Menu and Menubar Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/menubar/)
- **组合控件有两种焦点管理策略。** APG 描述 roving `tabindex` 和 `aria-activedescendant`，它们是管理组合控件焦点的替代策略，并非要求组件自行同时实现两套。Combobox 的 listbox/tree/grid 弹层模式通常让 DOM 焦点留在输入框，用 `aria-activedescendant` 表示活动项；活动项仍须有可见焦点提示并滚入视口。[Developing a Keyboard Interface](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/)、[Combobox Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)
- **APG 不规定品牌色。** 它要求焦点、当前项和选中态有可识别的语义表现；柠檬黄、黑色、整行底色、行内描边及固定勾选槽均属于设计与实现选择。统一样式应复用视觉规则，同时保留不同控件的状态含义。

### Reka UI 官方资料

已用 Context7 检索 Reka UI（官方仓库文档，`v2` 分支），并核对官方文档及源码：

- Reka 的 Select 文档将方向键导航与 Enter/Space 选择分开描述；Listbox 文档也把高亮导航与 Enter 选择分别列出。[Select 文档](https://github.com/unovue/reka-ui/blob/v2/docs/content/docs/components/select.md)、[Listbox 文档](https://github.com/unovue/reka-ui/blob/v2/docs/content/docs/components/listbox.md)
- DropdownMenu 文档说明使用 roving `tabindex` 管理菜单焦点；源码的方向键导航选择器排除 `[data-disabled]`，因此当前 Reka v2 行为与 APG 对菜单禁用项的建议不同。它是明确的版本行为，不能据此把“菜单禁用项不可聚焦”写成通用最佳实践。[DropdownMenu 文档](https://github.com/unovue/reka-ui/blob/v2/docs/content/docs/components/dropdown-menu.md)、[MenuContentImpl.vue](https://github.com/unovue/reka-ui/blob/v2/packages/core/src/Menu/MenuContentImpl.vue)
- Combobox 输入组件由原语把高亮项 ID 写入 `aria-activedescendant`；Listbox 原语已管理高亮、方向键导航和禁用项筛选。[ComboboxInput.vue](https://github.com/unovue/reka-ui/blob/v2/packages/core/src/Combobox/ComboboxInput.vue)、[ListboxRoot.vue](https://github.com/unovue/reka-ui/blob/v2/packages/core/src/Listbox/ListboxRoot.vue)

## 优先级审查发现

1. **P1｜第 51、60、174 行：TreeView 的现有行为与统一值提交规则冲突。** 折叠分支按 ArrowRight、展开分支按 ArrowLeft 时，[TreeViewNode.vue](../../../packages/ui/src/components/tree-view/TreeViewNode.vue) 的处理器会同时发出展开/收起与 `select`；[TreeView.vue](../../../packages/ui/src/components/tree-view/TreeView.vue) 的 `selectNode` 会触发 `update:modelValue`。保留现有行为与要求这些按键不改变值，无法同时成立。建议本次视觉改造保留当前提交时点，在组件状态映射表中明确；键盘选择策略的调整应单独界定行为范围。APG 允许单选树选择跟随焦点，不能仅凭最佳实践推导出统一提交策略。
2. **P2｜第 60、65–68、134、136 行：持久标记的状态来源需要按组件定义。** [Transfer.vue](../../../packages/ui/src/components/transfer/Transfer.vue) 的 `modelValue` 表示目标面板成员，Checkbox 表示待转移勾选，两者独立；[Cascader.vue](../../../packages/ui/src/components/cascader/Cascader.vue) 的导航路径、已选路径和父节点聚合三态也分别存在。另据当前 [TreeSelectNode.vue](../../../packages/ui/src/components/tree-select/TreeSelectNode.vue)，TreeSelect 提供选中 ID 与勾选标记，未提供方案所称半选模型。应将标记来源分别写明，避免统一适配时混淆业务归属、临时勾选和路径状态。
3. **P2｜第 90 行：行内描边需要与现行视觉规范同步。** [视觉系统 R7](../../guides/VISUAL_SYSTEM.md#r7-焦点指示体系-focus-ring) 规定复用带外扩偏移的 `FOCUS_RING_CLASSES`，并依靠 `outline-hidden` 维持强制颜色模式的焦点指示。行内描边能减少滚动边界裁切，但方案需要定义对应的集合行焦点样式、强制颜色行为及规范更新，才能形成一致的工程契约。项目当前目标为 AA；无需把 AAA 的 2.4.13 额外作为本次放行门槛。
4. **设计建议｜第 85–89、119、121 行：共享样式与输入模式保持窄接口。** 本地 Select 和 DropdownMenu 选项拥有真实 DOM 焦点；Command 通过 `ListboxFilter` 把 DOM 焦点留在输入框，以 `aria-activedescendant` 表示活动项。[CommandInput.vue](../../../packages/ui/src/components/command/CommandInput.vue) 是后者的接入点。建议共享模块接收组件已归一化的呈现状态；输入模式跟踪优先限定在 Command/Combobox 的虚拟焦点路径，按需要扩展。方案已有“仅控制表现”的正确边界，实施时应继续保留原语的导航、滚动和提交职责。
5. **验收补充｜第 70、108、176、186–189 行：补齐实际状态与消费端覆盖。** 菜单禁用项跳过导航符合当前 Reka 行为，APG 则建议菜单禁用项可聚焦而不可激活；应明确这是保留原语契约。TreeSelect 的 Home/End 当前直接聚焦首末节点，首末节点禁用时无法满足方案的跳过承诺。新增令牌应加入编辑器和两份对比度测试的显式色对清单，并通过现有 [CLI 消费端工具](../../../packages/cli/scripts/test-consumers.mjs) 验证 `init`、`add`、`update` 与构建；注册表校验本身不能证明安装产物完整。

## 配色与主题判断

按 WCAG 2.x 相对亮度公式，`#FFE600` 的相对亮度约为 `0.778536`，与纯黑的文字对比约为 **16.57:1**，满足普通文字 4.5:1 的 AA 门槛。[WCAG 2.2 对比度公式与阈值](https://www.w3.org/TR/WCAG22/#contrast-minimum) 该结论适用于不透明的纯黑前景与此黄色背景；自定义主题、辅助文字、透明度和焦点边界仍按实际组合验收。

独立的 `itemHighlight` 色对使集合高亮拥有清晰语义，可避免影响通用 `accent` 的其他用途。新字段会增加自定义主题迁移工作，方案已识别此成本；实施说明应给出覆盖新色对的配置示例。Classic、Pastel、Mono、Warm 各自保持主题身份的映射方式合理。

## 实施前应保留的边界

- 复用行布局、颜色对和状态槽位可以统一；焦点、活动项、ARIA 选中态、已提交值、动作执行结果仍由控件语义决定。
- 共享模块只产出视觉状态类；不得成为第二套方向键导航、焦点管理或值提交机制。
- 强制颜色模式保留焦点描边与非颜色的持久选择标记，允许浏览器和系统色替代 `#FFE600`。
- 官方 Reka 文档按 `v2` 分支核验；本地 UI 包解析到 `reka-ui@2.9.9`，基础选项的焦点和禁用导航行为已对照本地原语源码核对。
