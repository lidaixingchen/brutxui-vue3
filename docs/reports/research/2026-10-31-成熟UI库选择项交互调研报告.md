# 成熟 UI 库选择项交互调研报告

调研日期：2026-10-31。

调研范围：Ant Design、Element Plus、Naive UI、MUI、Fluent UI、Carbon、Radix Themes、shadcn/ui 的默认选择器与相关列表选项。依据官方设计规范、组件源码及主题令牌，比较鼠标悬浮、键盘当前项、已选中、字重和几何变化。样本用于覆盖不同设计体系，不代表市场份额或产品排名。

## 一、结论

**优先统一选项行的几何稳定性与状态表达，再确定配色强度。** 所查默认行样式均未使用交互态的整行平移、缩放或独立行投影来表达悬浮与当前项；反馈主要由背景、前景、选择标记和焦点轮廓承担。弹层投影、弹层开合动画和图标自身动画属于不同层级，不计为选项行位移。逐库证据见第三节。

配色有两类明确实践：Ant Design、Element Plus、Naive UI、MUI、Fluent UI、Carbon 的所查默认样式主要采用低强度背景；Radix Themes 的默认 `solid` 内容变体采用实心强调色；shadcn/ui 默认 Neutral 主题的 `accent` 则是中性浅底。因此，**实心黄色高亮具有可参考的产品先例，浅色高亮更接近所查企业型组件库的默认强度**，不存在由这些样本推出的唯一行业配色。

字重必须区分状态：Ant Design 和 Element Plus 会强化**已选中项**的字重，所查悬浮规则不改变字重。BrutxUI 目前最直接的问题是 Select 选项悬浮时整行位移，Command 选项高亮时还改变字重；这些都应在统一规则中处理。

**对 BrutxUI 的设计建议：采用整行背景高亮与固定字重，保留清楚的选择标记；键盘可见焦点使用独立轮廓。** 在已有视觉方向中，A 的整行结构最有参考依据；可以补充浅黄色强度，比较它与现有实心黄色的可读性。B 的左色条不是所查组件的共同默认做法；C 的稳定轮廓更适合作为键盘焦点表达的参考。

以上 BrutxUI 建议属于根据来源作出的设计判断，尚未通过用户实验验证。

## 二、对比矩阵

| 产品与组件 | 悬浮、键盘当前项 | 已选中项 | 字重与几何的关键区别 |
| --- | --- | --- | --- |
| Ant Design Select | 当前项使用轻灰底色，鼠标与键盘通过 active 状态表达 | 浅蓝底色、较高字重；默认多选显示勾号 | 悬浮不改变字重；选中可变为 600；所查行状态没有位移或行阴影 |
| Element Plus Select | `is-hovering` 使用浅灰底色，鼠标与键盘共用状态 | 主色文字、加粗；默认多选显示勾号 | 加粗属于选中态；所查悬浮规则保持行尺寸与位置稳定 |
| Naive UI Select | pending 状态以浅底伪元素表达，鼠标与键盘共用状态 | 主色文字、独立勾号；与 pending 底色组合 | 所查行状态保持字重与位置稳定；勾号动画独立于整行 |
| MUI MenuItem / Autocomplete | hover 与可见焦点分别使用 action 颜色令牌 | 主色透明背景，可与 hover / focus 组合；默认没有内置勾号 | 所查行状态不改变字重、边框宽度或整行变换 |
| Fluent UI React v9 Option | 悬浮用中性底色；键盘可见焦点用独立轮廓 | 单选勾号，多选复选指示器 | 焦点轮廓绝对定位，不挤占行空间；所查行状态不改变字重 |
| Carbon Dropdown / ComboBox | 悬浮用 layer-hover，键盘当前项另有焦点轮廓 | layer-selected 背景与勾号；多选使用复选框 | 固定行高，分隔边框预先存在；所查行状态保持位置与字重稳定 |
| Radix Themes Select / DropdownMenu | 默认 solid 变体以实心主题强调色和配套前景高亮 | Select 和可勾选菜单项使用独立指示器 | 所查行状态无平移、缩放、行投影或高亮加粗 |
| shadcn/ui base-nova | Select、Combobox 使用 accent / accent-foreground；默认 Neutral 主题是中性底色 | 独立 ItemIndicator 与勾号 | 所查行状态无平移、缩放、行投影或高亮加粗；实际颜色受主题控制 |

矩阵是下列具体源码的摘要，不应外推为这些产品所有主题、组件变体和消费者定制后的共同表现。

## 三、逐库证据

### 1. Ant Design

`option-active` 控制当前项背景，默认 `optionActiveBg` 为浅灰叠色。`option-selected` 独立设置选中背景、前景和 `optionSelectedFontWeight`；默认选中字重为 600。选中项同时为当前项时另有组合背景。源码将背景色过渡与状态色放在稳定的行框上。[选项样式](https://github.com/ant-design/ant-design/blob/45821ad453667bce7d3c15cd54603edea8300a0d/components/select/style/dropdown.ts)、[默认令牌](https://github.com/ant-design/ant-design/blob/45821ad453667bce7d3c15cd54603edea8300a0d/components/select/style/token.ts)

底层 OptionList 维护 active 当前项，键盘与指针都可更新它。默认选择图标的展示与多选模式关联，不能据此假定所有库的单选都会带勾号。[当前项逻辑](https://github.com/react-component/select/blob/fcbd87ee9ef419eb677cc351744181d027a50110/src/OptionList.tsx)、[图标默认值](https://github.com/ant-design/ant-design/blob/45821ad453667bce7d3c15cd54603edea8300a0d/components/select/useIcons.tsx)、[官方文档](https://ant.design/components/select/)

### 2. Element Plus

`el-select-dropdown__item.is-hovering` 使用 `hover-background`；默认映射至 `fill-color-light`。`is-selected` 单独使用主色文字及加粗。多选勾号也由独立状态控制；悬浮并不触发选中字重。[选项样式](https://github.com/element-plus/element-plus/blob/a8d102a91b96f52c433d0d3ef7c91c565a9aa317/packages/theme-chalk/src/option.scss)、[默认令牌](https://github.com/element-plus/element-plus/blob/a8d102a91b96f52c433d0d3ef7c91c565a9aa317/packages/theme-chalk/src/common/var.scss)

选项组件和 Select 的键盘逻辑共同维护 hovering 状态。该结论限于所查 `el-select`，不直接覆盖 `el-select-v2`。[选项组件](https://github.com/element-plus/element-plus/blob/a8d102a91b96f52c433d0d3ef7c91c565a9aa317/packages/components/select/src/option.vue)、[键盘逻辑](https://github.com/element-plus/element-plus/blob/a8d102a91b96f52c433d0d3ef7c91c565a9aa317/packages/components/select/src/useSelect.ts)、[官方文档](https://element-plus.org/en-US/component/select.html)

### 3. Naive UI

指针与键盘导航更新 pending 当前项；`optionColorPending` 通过伪元素绘制底色。selected 独立决定主色文字与勾号，selected 和 pending 同时成立时使用组合背景令牌。所查默认行规则不改变字重或整行位置。[选项组件](https://github.com/tusen-ai/naive-ui/blob/8b249214f17328a47eeb57dd5c7b80a47c94d116/src/_internal/select-menu/src/SelectOption.tsx)、[菜单逻辑](https://github.com/tusen-ai/naive-ui/blob/8b249214f17328a47eeb57dd5c7b80a47c94d116/src/_internal/select-menu/src/SelectMenu.tsx)、[样式](https://github.com/tusen-ai/naive-ui/blob/8b249214f17328a47eeb57dd5c7b80a47c94d116/src/_internal/select-menu/src/styles/index.cssr.ts)

默认浅色 pending 底色来自 `hoverColor`，选中文字来自 `primaryColor`；Select 的 `showCheckmark` 默认为 true。勾号可以有自己的进入动画，不等同于整行缩放。[浅色主题](https://github.com/tusen-ai/naive-ui/blob/8b249214f17328a47eeb57dd5c7b80a47c94d116/src/_internal/select-menu/styles/light.ts)、[Select 默认属性](https://github.com/tusen-ai/naive-ui/blob/8b249214f17328a47eeb57dd5c7b80a47c94d116/src/select/src/Select.tsx)

### 4. MUI Material UI

核对版本为 v7.3.10。MenuItem 与 Autocomplete 将 hover、可见焦点、selected 交给不同状态选择器和 action 令牌；已选项的主色背景能够与 hover / focus 的强度组合。所查行状态没有改变 `fontWeight`、整行变换、投影或边框宽度。[MenuItem 样式](https://github.com/mui/material-ui/blob/v7.3.10/packages/mui-material/src/MenuItem/MenuItem.js#L88-L123)、[Autocomplete 样式](https://github.com/mui/material-ui/blob/v7.3.10/packages/mui-material/src/Autocomplete/Autocomplete.js#L323-L386)

默认选中背景不等同于内置复选框。Autocomplete 的复选框示例通过 `renderOption` 添加选择标记。MenuItem 继承的 ButtonBase 还可能有点击 ripple，其效果与 hover 位移无关。[Autocomplete 文档](https://mui.com/material-ui/react-autocomplete/)、[Select 文档](https://mui.com/material-ui/react-select/)、[ButtonBase](https://github.com/mui/material-ui/blob/v7.3.10/packages/mui-material/src/ButtonBase/ButtonBase.js#L33-L88)

### 5. Fluent UI

核对的是 React v9 Dropdown / Combobox 所用的 Option。hover 使用 `colorNeutralBackground1Hover` 等中性令牌；键盘可见焦点通过绝对定位的伪元素绘制轮廓，因此不会挤压文字。选中标记独立于当前行背景：单选显示勾号，多选显示方框及品牌色填充。[Option 样式](https://github.com/microsoft/fluentui/blob/1d2e3b10bdfc230051dbcc35d0c56d2ba78001cc/packages/react-components/react-combobox/library/src/components/Option/useOptionStyles.styles.ts#L32-L112)

选中状态和指示器有各自的属性、slot 与样式。所查 Option 行规则没有交互态的整行变换、行投影或字重切换。[Option 状态](https://github.com/microsoft/fluentui/blob/1d2e3b10bdfc230051dbcc35d0c56d2ba78001cc/packages/react-components/react-combobox/library/src/components/Option/useOption.tsx#L47-L117)

### 6. Carbon

官方规范分别定义 hover、active、selected：菜单行的 hover 背景为 `layer-hover`，selected 为 `layer-selected` 并伴随勾号。源码还给键盘当前项配置焦点轮廓，选中项悬浮使用组合状态。[官方状态规范](https://www.carbondesignsystem.com/building-blocks/core/components/dropdown/specifications)、[高亮和选中源码](https://github.com/carbon-design-system/carbon/blob/v11.119.0/packages/styles/scss/components/list-box/_list-box.scss#L829-L895)

v11.119.0 的共享 list-box 固定行高，基础字重为 normal，行分隔边框预先存在，交互时主要改变颜色。ComboBox 引入同一套共享样式。图标的垂直居中变换作用于图标；菜单投影作用于容器。[行样式](https://github.com/carbon-design-system/carbon/blob/v11.119.0/packages/styles/scss/components/list-box/_list-box.scss#L618-L753)、[焦点轮廓](https://github.com/carbon-design-system/carbon/blob/v11.119.0/packages/styles/scss/utilities/_focus-outline.scss#L15-L36)、[ComboBox 共享导入](https://github.com/carbon-design-system/carbon/blob/v11.119.0/packages/styles/scss/components/combo-box/_combo-box.scss#L8-L14)

### 7. Radix Themes

比较对象是带默认视觉的 Radix Themes。Select 内容的默认变体为 `solid`，高亮行使用 `accent-9` 和配套的 `accent-contrast`；高对比变体另有配对色。Select 的 ItemIndicator 单独呈现选择状态。[Select 官方文档](https://www.radix-ui.com/themes/docs/components/select)、[Select 样式](https://github.com/radix-ui/themes/blob/1faff10ac26ae17f09944d418c6949b93fc6b566/packages/radix-ui-themes/src/components/select.css)、[组件实现](https://github.com/radix-ui/themes/blob/1faff10ac26ae17f09944d418c6949b93fc6b566/packages/radix-ui-themes/src/components/select.tsx)

DropdownMenu 共享菜单基础样式，默认 solid 高亮也使用实心强调色。普通操作项与可勾选菜单项保持各自语义，不能把每个菜单动作都当成选中值。[基础菜单样式](https://github.com/radix-ui/themes/blob/1faff10ac26ae17f09944d418c6949b93fc6b566/packages/radix-ui-themes/src/components/_internal/base-menu.css)、[DropdownMenu 官方文档](https://www.radix-ui.com/themes/docs/components/dropdown-menu)

Radix Primitives 本身提供无样式基础能力；以上视觉结论来自 Themes 的皮肤实现，不由 Primitives 的交互文档推导。

### 8. shadcn/ui

2026 年 7 月的官方公告将新项目默认组件基础切换为 Base UI，同时继续支持 Radix。此次主比较范围为 `base-nova`；旧 Radix `new-york-v4` 示例作为另一个明确标注的参考，不能混合描述成同一个默认版本。[官方默认切换公告](https://ui.shadcn.com/docs/changelog/2026-07-base-ui-default)、[默认主题及配置](https://ui.shadcn.com/docs/theming)

当前 Base Select 和 Combobox 通过 accent 背景与配套前景表达当前项，用独立 ItemIndicator 显示选择。Nova 样式中的高亮规则没有加入整行变换、行投影或高亮加粗。官方 Neutral 默认主题将 accent 定义为中性色，具体项目仍可覆盖令牌。[Base Select](https://github.com/shadcn-ui/ui/blob/24a16429815cc4d691f38b49d0f4ffc11a9daef4/apps/v4/registry/bases/base/ui/select.tsx)、[Base Combobox](https://github.com/shadcn-ui/ui/blob/24a16429815cc4d691f38b49d0f4ffc11a9daef4/apps/v4/registry/bases/base/ui/combobox.tsx)、[Nova 样式](https://github.com/shadcn-ui/ui/blob/24a16429815cc4d691f38b49d0f4ffc11a9daef4/apps/v4/registry/styles/style-nova.css)

旧 Radix 示例中的 Combobox 组合 CommandItem；其 `data-selected` 对应当前高亮项，实际值的勾选由示例另外维护。状态名不能直接等同于业务选中语义。[旧 Command](https://github.com/shadcn-ui/ui/blob/24a16429815cc4d691f38b49d0f4ffc11a9daef4/apps/v4/registry/new-york-v4/ui/command.tsx)、[旧 Combobox 示例](https://github.com/shadcn-ui/ui/blob/24a16429815cc4d691f38b49d0f4ffc11a9daef4/apps/v4/registry/new-york-v4/examples/combobox-demo.tsx)

## 四、对 BrutxUI 的统一建议

以下为设计建议，不是上述产品对 BrutxUI 的约束。

| 状态或层级 | 建议规则 |
| --- | --- |
| 普通行 | 行高、缩进、字重和标记槽位固定，长文本沿用一致截断规则 |
| 鼠标悬浮 / 键盘当前项 | 使用成对背景与前景令牌；整行位置、字重与投影保持稳定 |
| 单选已选中 | 固定槽位显示勾选，与当前项高亮独立表达 |
| 多选已选中 | 持续显示复选指示器，保留未选和半选状态的区分 |
| 键盘可见焦点 | 使用独立焦点轮廓；通过 outline、绝对定位或预留空间保持行几何稳定 |
| 禁用 | 弱化显示，并由所属原语跳过选择与当前项导航 |
| 树形和级联 | 沿用相同的行反馈，另外保留缩进、展开与路径状态 |
| 危险操作 | 保留 destructive 语义及配套对比度，不归入普通业务选中态 |
| 弹层外壳 | 承担粗边框与硬阴影，承载现有 Neo-Brutalism 风格 |

焦点与选择是不同状态，具体角色、ARIA 属性与键盘操作仍由所属原语决定；不能为了统一视觉而强行替换树、菜单和列表框的交互模型。[WAI 列表框说明](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/#note)

颜色强度的后续评审可集中在两种整行表达：现有实心黄色，以及由主题令牌派生的柔和黄色。这样可以比较品牌辨识度和长列表的视觉负担，避免同时改变色彩、位移、字重与边框导致判断混杂。

## 五、证据范围与待验证项

- 这是官方文档与默认源码的比较，没有逐库装包进行浏览器像素、性能或辅助技术验收；源码未声明某类效果，不等于对所有主题与定制代码作出保证。
- Ant Design、Element Plus、Naive UI 主要核对默认浅色令牌；shadcn/ui 另核对了官方 Neutral 主题的亮暗配对。其余库以指定源码和规范中的默认状态规则为准。
- MUI 与 Carbon 使用文中指定发布标签；其余源码固定在链接中的分支提交快照。各快照不构成同一套可运行安装环境，也不用于宣称它们是各产品的最新发布版。
- Naive UI 官网组件页本次未成功加载，相关默认行为由官方源码与仓库文档结构核对。
- BrutxUI 的柔和黄色、键盘轮廓、选中与高亮叠加状态，仍需在亮暗主题、紧凑密度、长文本、嵌套滚动及强制颜色模式下验收。
