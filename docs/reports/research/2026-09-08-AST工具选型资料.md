# AST 工具选型资料

调研日期：2026-09-08。范围：官方工具能力与架构边界；项目现状由综合报告另行核实。

## 结论

**工程判断：根据具体任务复用成熟解析器通常合理；自行维护全项目持久 AST 并不是普遍最佳实践。** 官方工具分别提供文件语法树、语义查询、增量编译和框架文件解析能力，不能仅因为需要分析代码，就认定必须再建设一套统一持久树。该结论是基于下述能力边界的选型建议，并非官方发布的通用规范。

## 一手事实

| 工具 | 官方事实 | 对选型的含义 |
| --- | --- | --- |
| TypeScript Compiler API | `SourceFile` 包含源码和 AST；`Program` 表示整个应用；纯语法遍历可以只用 `createSourceFile`。`TypeChecker` 提供符号和类型查询。官方也提供增量 builder/watch API。 | 提取 import、export 等语法事实可局部解析；解析标识符指向、推导类型时再建立语义上下文。无需所有任务都启动完整类型检查。 |
| Vue SFC 编译器 | `parse` 提取 SFC descriptor，`compileScript` 处理脚本及 `<script setup>`，`compileTemplate` 处理模板，`compileStyle` 处理样式。 | `.vue` 是混合文件，适合先按官方 SFC 结构拆分，再处理各语言；不要直接当作完整 TypeScript 文件解析。 |
| Tree-sitter | 官方定义输出为 CST（具体语法树），支持源文件编辑后的增量更新，并能在语法错误存在时提供结果。 | 适合快速结构检索和交互工具；其解析结果本身不能等同于 TypeScript 类型检查结果。 |

来源：[TypeScript Compiler API](https://github.com/microsoft/TypeScript/wiki/Using-the-Compiler-API)、[Vue compiler-sfc 官方说明](https://github.com/vuejs/core/blob/main/packages/compiler-sfc/README.md)、[Tree-sitter 官方仓库](https://github.com/tree-sitter/tree-sitter)。

## 语法、语义与索引的边界

Vue 官方明确说明：`defineProps` 的类型到运行时转换仍基于 AST，因此不支持某些需要实际类型分析的复杂类型，例如以条件类型表示整个 props 对象。**这直接说明，能够解析 AST 并不意味着能够完成所有类型语义分析。** [Vue script setup 文档](https://vuejs.org/api/sfc-script-setup.html)

Tree-sitter 对多语言文档提供范围解析，但明确把语言之间的交互处理交给应用层。编辑后也要求更新树与缓存节点的位置信息。**工程推论：调用图、跨文件引用图和影响分析图是解析结果之上的派生模型；准确性还依赖符号解析、语言集成、规则覆盖和更新机制，不能从“使用 AST/CST”直接推导出完整性。** [Tree-sitter Advanced Parsing](https://tree-sitter.github.io/tree-sitter/using-parsers/3-advanced-parsing.html)

Vue 官方建议通过 `vue/compiler-sfc` 导入，以保持编译器与 Vue 运行时版本同步；CLI 类型检查可使用 `vue-tsc`，涵盖 SFC。**工程建议：Vue 模板和组件 props 的语义验证优先复用官方语言工具链。** [Vue Tooling](https://vuejs.org/guide/scaling-up/tooling)

## 持久化与增量更新建议

以下为基于上述资料的工程判断，不是已在本仓库测量过的性能结论：

- 一次性扫描：按文件解析，提取所需事实，任务结束后释放树。
- 持续语义分析：复用编译器的项目上下文与增量能力，避免自行重复实现模块解析和失效传播。
- 面向快速查询的长期索引：优先保存实际查询需要的符号、路径、范围、依赖边等派生数据；是否保留完整树由测量决定。
- 引入缓存前应测量冷启动、热更新、峰值内存和结果准确性；缓存键需考虑源码内容、解析器版本及影响结果的配置。
- 全项目持久 AST 只有在反复查询原始节点的收益得到验证、并有明确缓存失效和版本管理方案时，才值得进一步设计。

版本注意：当前 TypeScript Compiler API Wiki 明示其内容适用于 TypeScript 6.0 及以前，TypeScript 7.1 将采用不同 API。实施前须对照仓库实际版本；这也支持将编译器适配控制在明确边界内。 [TypeScript Compiler API](https://github.com/microsoft/TypeScript/wiki/Using-the-Compiler-API)
