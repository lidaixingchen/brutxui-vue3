## 背景与优化范式

已实施的"阴影过渡与焦点体系统一方案"（[../plans/阴影过渡与焦点体系统一方案.md](../plans/阴影过渡与焦点体系统一方案.md)）揭示了 8 个可复用的优化范式，本报告按这些范式发散扫描全库，定位同类问题：

1. **手写类 vs Tailwind 生成类双定义**——`@layer utilities` 手写类与 `@theme` 令牌派生类并存（shadow-brutal 即死于此）
2. **焦点/激活体系并行分裂**——同一语义多种实现（ring/outline/背景高亮/位移）
3. **主题化路径绕过 token**——硬编码值替代 `--brutal-*` 派生类
4. **Tailwind v4 变量机制竞态**——`--tw-*` 变量多源写入，胜出者由编译顺序决定
5. **@source 扫描约定违反**——动态拼接类名导致产物静默缺类
6. **死代码/死导出**——定义并导出但零消费者
7. **并行体系残留**——同一语义两套实现
8. **过渡声明与实际属性错配**——`transition-[transform,box-shadow]` 吞掉真实颜色过渡

## 一、手写类 vs Tailwind 生成类双定义

### `border-3` 三定义竞态（实为同值冗余，非 shadow-brutal 同源风险）

dist 产物（`packages/ui/dist/styles.css`）中存在 **3 条 `.border-3` 规则**（另有 1 条 `.border-brutal` 配套规则）：

| 规则 | 来源 | 特点 |
| --- | --- | --- |
| `.border-3{border-style:var(--tw-border-style);border-width:var(--border-width-3)}` | Tailwind 生成（`@theme` 的 `--border-width-3` 派生） | 声明 border-style |
| `.border-3{border-width:var(--border-width-3)}` | [styles.css](../../packages/ui/src/styles.css) `@layer utilities` 手写 | 仅声明 border-width，未声明 border-style |
| `.border-brutal{border-style:solid;border-color:var(--brutal-border-color,#000)}` | 手写 | 组件配套提供 solid + token 边框色 |
| `.border-3{border-width:4px}` | `prefers-contrast: high` 全局覆盖（未入层，位于产物末尾） | 高对比度增强 |

**澄清（经产物字节序与属性级联核验）**：两条 `.border-3` 规则**同时作用于同一元素、按属性级联**，而非"后者整体覆盖前者"。手写版只声明 `border-width`（与 Tailwind 版**同值** `var(--border-width-3)`），`border-style` 仍由 Tailwind 版规则的 `border-style:var(--tw-border-style)` 提供，而 preflight 将 `--tw-border-style` 默认置为 `solid`。因此：

- **单独挂 `border-3`（不配 `border-brutal`）时边框正常显示**——全库裸用 `border-3` 的组件（MenuItem、SubMenu、textarea、hardcore-input、spinner、accordion、DataTableColumnFilter、date-picker）实测均为实线边框
- prefers-contrast 的 4px 覆盖未入层且位于产物末尾，**恒胜，高对比度增强生效**
- 手写版对视觉**零贡献、100% 冗余**——真正的性质是"同值双定义"，与 shadow-brutal 之死（手写版为**不同值**、破坏主题）**不同源**，无实际风险

**修复方向**：删手写版，保留 Tailwind 生成版（自带 `border-style`，更完整）。由于两条规则 `border-width` 同值、`border-style` 本由 Tailwind 版提供，删除为**纯冗余清理、无任何行为变更**（裸 `border-3` 删除前后均为实线）。定级为 **P2 冗余清理**，非 P1 架构债。

## 四、Tailwind v4 transform 变量竞态（`--tw-translate-y` 多源写入）

产物 CSS 字节序（同特异度后者胜）：`hover:*` < `focus:*` < `active:*` < `data-[highlighted]:*` < `data-[state=on]:*` 等，即 **`data-*` 变体恒后于 hover/focus/active**。

### 4.1 command item 按压反馈失效（真实缺陷，已字节序实证）

[command-variants.ts:24-25](../../packages/ui/src/components/command/command-variants.ts#L24-L25)：`brutalHighlightLiftWithBorder`（`data-[highlighted]:-translate-y-0.5` + `data-[highlighted]:shadow-brutal-lg`）与 `brutalPress`（`active:translate-y-[var(--brutal-pressed-offset,2px)]` + `active:shadow-none`）同元素并存。reka Listbox 的 `data-highlighted` 在鼠标按下前必已置位，高亮项按压时两态必同时成立；产物字节序实测 `active:translate-y-...`@80230 < `data-[highlighted]:-translate-y-0.5`@84674、`active:shadow-none`@80763 < `data-[highlighted]:shadow-brutal-lg`@85714，同特异度 (0,2,0) 下 `data-[highlighted]` 恒胜 → **所有鼠标按压场景下按压位移与去影反馈完全不出现**（非偶发）。含 `transition-all` 也救不回——状态切换期间计算值不变。违反 brutalPress"active 整体接管"约定；对照 cascader/select 的 `active:translate-x-0` 显式重置模式，此处未处理。

### 4.2 toggle ON 态持久位移压过 hover/active（需人工确认意图）

[toggle-variants.ts:19,24](../../packages/ui/src/components/toggle/toggle-variants.ts#L19-L24)：`data-[state=on]`（持久 +2px）、`hover`（-2px）、`active`（+2px）三源写入同一变量，`data-[state=on]` 恒胜（产物 @90865）→ **ON 态下 hover 浮起完全不生效**。核验修正：`data-[state=on]:shadow-none`（@91495）同样压过 `hover:shadow-brutal`（@77938），**ON 态 hover 阴影也不会"正常放大"**——实际 ON 态 hover/按压的位移与阴影反馈整体归零（bg/text 亦被 data-on 覆盖），非原述"阴影上浮语义与位置脱节"。与 switch/checkbox 同族组件（checked 位移在独立 thumb）行为不一致。

### 4.3 已核查安全（对照基准）

carousel 居中 calc 保留、cascader/select 的 active 显式重置、Image/Tour/number-input 的 hover/active 成对（active 后置接管成功）、form-toggle-base 的 disabled 特异度压制、date-picker hover 只写 x / active 只写 y（不同变量）、Rate 展平按压、SelectContent 动画走关键帧非变量——均符合 brutalPress 约定。

## 十四、主题前景色对比度（新发现，open-code-review 审查 2026-08-13）

**warm 主题前景色对比度不足 WCAG AA**（值同步自 [styles.css:270-296](../../packages/ui/src/styles.css#L270-L296) 的既有主题设计、并随 §10.1/10.2 同步至 [brutalist.css:213-214](../../packages/cli/src/styles/brutalist.css#L213-L214)，**非本次修复引入**）：

| 场景 | 前景 / 背景 | 对比度 | 阈值 |
| --- | --- | --- | --- |
| warm light `text-brutal-primary-foreground`（按钮文字） | `#FFFFFF` / `#E8722A` | ~3.1:1 | AA 4.5:1 |
| warm light `text-brutal-info-foreground`（Alert info 等） | `#FFFFFF` / `#D4956A` | ~2.5:1 | AA 4.5:1 |

| warm dark `text-brutal-destructive-foreground` | `#FFFFFF` / `#E74C3C` | ~3.8:1 | AA 4.5:1 |

对比其他色板：light 主题 base/pastel/mono 前景均用深色（`#000000`/`#1e1e24`）达 AA，唯 warm 用 `#FFFFFF` 白字失配。
